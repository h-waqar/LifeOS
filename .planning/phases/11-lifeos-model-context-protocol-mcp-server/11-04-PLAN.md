## 1. Objective

Provide end-to-end integration tests using real stdio subprocess communication (`bin/lifeos.js mcp`), protocol compliance testing, adversarial security defenses, cross-user boundary isolation, secret scrubbing, and full repository regression:
1. **Real Subprocess Stdio MCP Invocation (MCP-01):**
   - Implement `scripts/tests/phase-11/plan-04/mcp-test-client.ts` to spawn `bin/lifeos.js mcp` in a child process and speak standard JSON-RPC 2.0 over stdin/stdout.
   - Verify protocol initialization: `initialize` request -> `initialized` notification.
   - Verify server information (`name: "lifeos"`, `version: "0.1.0"`) and advertised capabilities (resources, tools, prompts).
2. **End-to-End Protocol Flow:**
   - Execute `resources/list` -> assert all `lifeos://context/*` resources are listed.
   - Execute `resources/read` for `lifeos://context/overview` -> assert valid JSON context structure.
   - Execute `tools/list` -> assert all 10 domain tools are listed.
   - Execute `tools/call` for `lifeos_create_task` -> verify task creation in database.
   - Execute `tools/call` for `lifeos_update_task` -> verify task update in database.
   - Execute `tools/call` for `lifeos_delete_task` -> verify task deletion.
   - Execute `prompts/list` and `prompts/get` for `lifeos_morning_planning`.
3. **Stream Discipline & Clean Protocol Framing (MCP-01):**
   - Verify that stdout NEVER contains debug banners, log messages, or warnings.
   - Verify that stderr receives all lifecycle logs (`[lifeos-mcp] Authenticated session...`) without corrupting stdout JSON-RPC framing.
4. **Adversarial Security & Zero-Trust Boundary (MCP-04, MCP-05):**
   - **Unauthenticated invocation:** Spawning `lifeos mcp` without token or credentials file fails closed with exit code 3 (`AUTH_ERROR`).
   - **Tampered / Expired Token:** Spawning `lifeos mcp` with invalid or expired session token fails closed with exit code 3.
   - **Caller Identity Spoofing Resistance:** Attempting to inject `userId`, `user_id`, or `user-id` in any tool call or resource URI fails closed with security rejection.
   - **Cross-User Ownership Isolation:** Verify that User A's MCP session cannot access, update, or delete User B's tasks, projects, goals, notes, or habits.
   - **Comprehensive Secret Scrubbing:** Verify that session tokens, database passwords, encryption keys, and cookies never leak into resource contents, tool results, error payloads, or logs.
   - **Financial Mutation Shield:** Verify that no tool calls exist that allow modifying financial balances, accounts, or transactions.
5. **Zero Database Migrations Verification:**
   - Assert migrations directory strictly contains `0000–0026`.
   - Assert 0 new database migrations were introduced.
6. **Full Project Regression Gate:**
   - `pnpm exec tsc --noEmit` completes with 0 errors.
   - `pnpm test` passes across all test suites with 0 failures.
   - `pnpm build` succeeds with exit code 0.

## 4. Implementation Steps

1. **Stdio MCP Test Client Harness (`scripts/tests/phase-11/plan-04/mcp-test-client.ts`):**
   - Implement `McpTestClient` class spawning `bin/lifeos.js mcp` with isolated environment:
     ```ts
     export class McpTestClient {
       async start(options?: { token?: string; env?: Record<string, string> }): Promise<void>;
       async request<T>(method: string, params?: unknown): Promise<T>;
       async notify(method: string, params?: unknown): Promise<void>;
       async stop(): Promise<{ exitCode: number | null; stderr: string }>;
     }
     ```
   - Handle line-delimited JSON-RPC 2.0 messages over stdout/stdin.
   - Capture stderr in memory for diagnostic assertions.

2. **Protocol & Lifecycle Integration Suite (`scripts/tests/phase-11/plan-04/mcp-integration.test.ts`):**
   - Test full client connection and `initialize` handshake.
   - Test `resources/list` returns all context resources.
   - Test `resources/read` for `lifeos://context/overview`.
   - Test `tools/list` returns all 10 domain tools.
   - Test `tools/call` for `lifeos_create_task` and `lifeos_search`.
   - Test `prompts/list` and `prompts/get`.
   - Test clean shutdown on client disconnect.
   - Test that stdout is 100% valid JSON-RPC with zero debug output.

3. **Adversarial Security & Isolation Suite (`scripts/tests/phase-11/plan-04/mcp-adversarial.test.ts`):**
   - **Missing Token:** Start `lifeos mcp` without credentials -> expect exit code 3.
   - **Expired Token:** Start with expired token -> expect exit code 3.
   - **Tampered Token:** Start with malformed token -> expect exit code 3.
   - **Caller Identity Spoofing:** Call `lifeos_create_task` with `{ title: "X", userId: "other-user" }` -> expect error.
   - **Cross-User Data Isolation:** Create task for User B. Attempt to read or mutate it using User A's MCP session -> expect `NOT_FOUND` / 404 error without data leakage.
   - **Secret Scrubbing:** Cause errors with sensitive values -> expect `***REDACTED***` in error message.
   - **Zero Migration Assertion:** Read migration directory and journal -> verify range is 0000–0026 and count is 0 new.

4. **Full Regression Gate:**
   - Execute `pnpm exec tsc --noEmit`.
   - Execute `pnpm test`.
   - Execute `pnpm build`.

## 6. Acceptance Criteria

1. Subprocess invocation of `bin/lifeos.js mcp` completes JSON-RPC 2.0 handshake and negotiates capabilities without protocol framing errors.
2. Real agent client harness can list resources, read context graphs, list tools, and invoke domain operations.
3. Unauthenticated connections fail closed with exit code 3.
4. Identity spoofing attempts (`userId` parameters) fail closed immediately.
5. Cross-user isolation guarantees that no user can access another user's records through MCP resources or tools.
6. Stdout stream contains exclusively valid JSON-RPC protocol frames; zero diagnostic logs or banners pollute stdout.
7. Secrets, tokens, and passwords are scrubbed from all resource responses, tool results, and error messages.
8. Zero new database migrations are introduced.
9. Full project regression suite (`tsc`, `pnpm test`, `next build`) passes with zero failures.
