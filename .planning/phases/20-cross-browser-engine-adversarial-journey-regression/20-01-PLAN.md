# Plan 20-01: Cross-Browser Engine Compatibility & Rendering/Interaction Hardening

## Executive Summary
Verifies and hardens LifeOS across desktop rendering engines: Chromium (Blink), Mozilla Firefox (Gecko), Apple Safari (WebKit), and Microsoft Edge:
1. Hardens CSS styling for non-Chromium engines in `src/app/globals.css`:
   - Adds Firefox standard scrollbar rules (`scrollbar-width: thin`, `scrollbar-color`) and WebKit/Blink scrollbar pseudo-elements (`::-webkit-scrollbar`) ensuring consistent theme-aware scrollbars and eliminating layout-breaking default gray scrollbar gutters.
   - Enforces fallback rules for CSS `backdrop-filter` in environments where backdrop filtering is unsupported or disabled in privacy/low-power modes, ensuring transparent UI cards/modals maintain legible contrast.
2. Hardens storage resiliency in `src/components/theme-provider.tsx`:
   - Wraps `localStorage.getItem` and `localStorage.setItem` in fail-safe try/catch accessors to prevent fatal uncaught `SecurityError` or `QuotaExceededError` crashes in Apple Safari Private Browsing mode and Firefox Strict Tracking Protection.
3. Validates Web Speech API graceful degradation across engines in `src/hooks/use-speech-recognition.ts` and `src/components/voice/voice-dictation-button.tsx`:
   - Verifies that Gecko/Firefox (where Web Speech is disabled by default) and Safari/WebKit (where speech recognition prefix and continuous modes vary) gracefully degrade to disabled states with accessible `role="status"` announcements rather than throwing unhandled exceptions.
4. Distinguishes automated headless browser execution, simulated browser environments (Gecko/WebKit user-agent profiles and feature matrices), and manual/unsupported platforms with full transparency.

## Objectives
1. **Cross-Engine CSS & Scrollbar Normalization (`src/app/globals.css`) (QA-05)**:
   - Provide standard `scrollbar-width` and `scrollbar-color` rules for Gecko/Firefox.
   - Retain WebKit scrollbar pseudo-element styles for Safari and Chromium.
   - Provide backdrop-filter feature fallback for cards and modals.
2. **Storage Resiliency in Private Browsing / ITP (`src/components/theme-provider.tsx`) (QA-05)**:
   - Prevent runtime crashes in Safari Private Mode by isolating all `localStorage` access into guarded utilities with in-memory fallback.
3. **Engine-Specific Feature Detection & Degradation (`src/hooks/use-speech-recognition.ts`) (QA-05)**:
   - Validate Web Speech feature detection under Blink, Gecko, and WebKit simulated environments.
   - Confirm seamless fallback without UI lockup or unhandled promise rejections.
4. **Automated Cross-Browser Test Suite (`scripts/tests/phase-20/plan-01/cross-browser-engine.test.tsx`) (QA-05)**:
   - Automated tests validating Blink, Gecko, and WebKit rendering declarations, CSS rules, storage safety in private browsing, and speech recognition degradation.

## Acceptance Criteria
- Firefox (Gecko), Safari (WebKit), and Edge/Chrome (Blink) exhibit zero fatal uncaught runtime exceptions during app mount, theme toggling, or voice control inspection.
- CSS scrollbars and backdrop filters maintain visual stability and contrast across all engines.
- Safari Private Browsing simulated storage restrictions do not prevent theme initialization or page rendering.
- All tests in `scripts/tests/phase-20/plan-01/cross-browser-engine.test.tsx` pass cleanly.

## Risks & Edge Cases
- *Edge case*: Browser with disabled local storage throws on read and write — mitigated by memory fallback in `theme-provider.tsx`.
- *Edge case*: Web Speech API constructor exists but `start()` immediately aborts with `not-allowed` — handled gracefully by state machine error handlers.
- *Risk*: Breaking existing responsive layout — mitigated by CSS additive rules only.
