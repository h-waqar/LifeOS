# Plan 05-01: Content Idea Capture, Multi-Platform Draft Editor, and Workflow Status Transitions

## 1. Plan Overview & Executive Context

- **Phase:** 5 — Content & Social Media
- **Plan Identification:** 05-01
- **Domain:** Content Idea Capture, Multi-Platform Draft Engine, Platform-Specific Constraints & Lifecycle Workflow Transitions
- **Prerequisites:** Phase 1 Foundation, Phase 2 Core Productivity, Phase 3 Knowledge, Learning & Relationships, and Phase 4 Personal Finance verified on `main` (commit `3b807126bc2aac333065ac00e33691ad0ec2763c`). PostgreSQL with Drizzle ORM, Better Auth session authentication, server-side resource ownership authorization via authenticated `user_id`, composite tenant isolation, and audit logging are operational.
- **Goal:** Deliver the core creative and editorial engine of LifeOS Content & Social Media: capture content ideas with topics, target audience, prospective channels, and tags; author platform-specific variants (Twitter/X thread, LinkedIn post, Blog article) for a single idea; enforce platform constraints (tweet 280-character limits, thread ordering, LinkedIn 3,000-character limits, Blog markdown & slug validation); manage the content lifecycle state machine (Idea → Draft → In Review → Scheduled → Published → Archived); provide an intuitive `/content` UI with idea capture modal, multi-platform editor, and status controls; and integrate content items into PostgreSQL full-text search and the command palette.
- **Requirements Satisfied:**
  - `CONT-01`: User can capture content ideas with tags, target audience, and prospective distribution channels.
  - `CONT-02`: User can author content drafts with platform-specific variants (Twitter/X thread, LinkedIn post, Blog article).
  - `CONT-04`: Content can transition through workflow statuses: Idea → Draft → In Review → Scheduled → Published → Archived.
- **Key Architectural Constraints:**
  1. **Vertical-Slice Rule**: Introduce only schemas and migrations required for content items and platform variants (`content_items`, `content_variants`). Publication execution records (`content_publications`) and manual performance metrics (`content_metrics`) belong strictly to Plan 05-02.
  2. **No Direct External Auto-Publishing in Phase 5**: Automated publishing to external social media APIs (Twitter, LinkedIn OAuth direct posting) is classified as `PUB-01` (v2) and deferred to Phase 8 per PRD Section 18-19 and Roadmap out-of-scope boundaries. Phase 5 focuses strictly on internal ideation, drafting, editorial scheduling, and manual metrics tracking.
  3. **Composite Multi-Tenant Isolation**: Every content entity row is partitioned by `user_id`. Unique constraints `(userId, id)` and composite foreign keys `(userId, contentItemId) REFERENCES content_items(userId, id)` guarantee zero data leakage across users at the database level.
  4. **Strict State Machine Transitions**: Workflow transitions are governed by an explicit transition matrix (`src/server/content/workflow.ts`). Cannot transition to `scheduled` without a target date and at least one platform variant. Transition to `published` stamps `publishedAt`. Soft archival preserves all linkages.
  5. **Clean Repository & Test Organization**: All tests reside strictly in `scripts/tests/phase-05/plan-01/`. Zero test files inside `src/`.

## 3. Database Architecture & Vertical-Slice Schema Evolution

All database changes for Plan 05-01 begin at migration `0019_content_items_and_variants.sql` in `src/server/db/migrations/`.

### 3.1 New Schema File: `src/server/db/schema/content.ts`

```typescript
import {
  pgTable,
  text,
  timestamp,
  boolean,
  integer,
  jsonb,
  unique,
  check,
  foreignKey,
  index,
} from "drizzle-orm/pg-core";
import { sql } from "drizzle-orm";
import { user } from "./auth";
import { projects } from "./projects";
import { goals } from "./goals";
import { notes } from "./notes";

/**
 * Content Items Table
 * Master entity for content ideas, drafts, and scheduled/published pieces.
 */
export const contentItems = pgTable(
  "content_items",
  {
    id: text("id")
      .primaryKey()
      .$defaultFn(() => crypto.randomUUID()),
    userId: text("user_id")
      .notNull()
      .references(() => user.id, { onDelete: "cascade" }),
    title: text("title").notNull(),
    contentType: text("content_type", {
      enum: [
        "post",
        "thread",
        "article",
        "short_video",
        "carousel",
        "newsletter",
        "other",
      ],
    })
      .notNull()
      .default("post"),
    status: text("status", {
      enum: [
        "idea",
        "draft",
        "in_review",
        "scheduled",
        "published",
        "archived",
      ],
    })
      .notNull()
      .default("idea"),
    topic: text("topic"),
    targetAudience: text("target_audience"),
    primaryPlatform: text("primary_platform"),
    targetChannels: jsonb("target_channels")
      .$type<string[]>()
      .notNull()
      .default(sql`'[]'::jsonb`),
    tags: jsonb("tags")
      .$type<string[]>()
      .notNull()
      .default(sql`'[]'::jsonb`),
    summary: text("summary"),
    mediaUrls: jsonb("media_urls")
      .$type<string[]>()
      .notNull()
      .default(sql`'[]'::jsonb`),
    scheduledAt: timestamp("scheduled_at", { withTimezone: true }),
    publishedAt: timestamp("published_at", { withTimezone: true }),
    projectId: text("project_id"),
    goalId: text("goal_id"),
    noteId: text("note_id"),
    isArchived: boolean("is_archived").notNull().default(false),
    createdAt: timestamp("created_at", { withTimezone: true })
      .notNull()
      .defaultNow(),
    updatedAt: timestamp("updated_at", { withTimezone: true })
      .notNull()
      .defaultNow(),
  },
  (table) => [
    unique("content_items_user_id_id_unique").on(table.userId, table.id),
    check(
      "content_items_title_non_empty",
      sql`length(trim(${table.title})) > 0`
    ),
    check(
      "content_items_title_max_length",
      sql`length(${table.title}) <= 255`
    ),
    check(
      "content_items_type_check",
      sql`${table.contentType} IN ('post', 'thread', 'article', 'short_video', 'carousel', 'newsletter', 'other')`
    ),
    check(
      "content_items_status_check",
      sql`${table.status} IN ('idea', 'draft', 'in_review', 'scheduled', 'published', 'archived')`
    ),
    foreignKey({
      name: "content_items_user_project_fk",
      columns: [table.userId, table.projectId],
      foreignColumns: [projects.userId, projects.id],
    }).onDelete("set null"),
    foreignKey({
      name: "content_items_user_goal_fk",
      columns: [table.userId, table.goalId],
      foreignColumns: [goals.userId, goals.id],
    }).onDelete("set null"),
    foreignKey({
      name: "content_items_user_note_fk",
      columns: [table.userId, table.noteId],
      foreignColumns: [notes.userId, notes.id],
    }).onDelete("set null"),
    index("content_items_user_id_idx").on(table.userId),
    index("content_items_user_status_idx").on(table.userId, table.status),
    index("content_items_user_type_idx").on(table.userId, table.contentType),
    index("content_items_user_scheduled_idx").on(
      table.userId,
      table.scheduledAt
    ),
    index("content_items_user_is_archived_idx").on(
      table.userId,
      table.isArchived
    ),
    index("content_items_user_project_idx").on(table.userId, table.projectId),
    index("content_items_user_goal_idx").on(table.userId, table.goalId),
  ]
);

/**
 * Content Variants Table
 * Platform-specific adaptations of a master content item (e.g. Twitter thread, LinkedIn post, Blog markdown).
 */
export const contentVariants = pgTable(
  "content_variants",
  {
    id: text("id")
      .primaryKey()
      .$defaultFn(() => crypto.randomUUID()),
    userId: text("user_id")
      .notNull()
      .references(() => user.id, { onDelete: "cascade" }),
    contentItemId: text("content_item_id").notNull(),
    platform: text("platform", {
      enum: [
        "twitter",
        "linkedin",
        "blog",
        "instagram",
        "youtube",
        "newsletter",
        "other",
      ],
    }).notNull(),
    title: text("title"),
    body: text("body").notNull().default(""),
    threadItems: jsonb("thread_items")
      .$type<string[]>()
      .notNull()
      .default(sql`'[]'::jsonb`),
    charCount: integer("char_count").notNull().default(0),
    status: text("status", {
      enum: ["draft", "ready", "published"],
    })
      .notNull()
      .default("draft"),
    customSettings: jsonb("custom_settings")
      .$type<{
        slug?: string;
        canonicalUrl?: string;
        metaDescription?: string;
        hashtags?: string[];
        threadNumbering?: boolean;
      }>()
      .notNull()
      .default(sql`'{}'::jsonb`),
    createdAt: timestamp("created_at", { withTimezone: true })
      .notNull()
      .defaultNow(),
    updatedAt: timestamp("updated_at", { withTimezone: true })
      .notNull()
      .defaultNow(),
  },
  (table) => [
    unique("content_variants_user_id_id_unique").on(table.userId, table.id),
    unique("content_variants_user_item_platform_unique").on(
      table.userId,
      table.contentItemId,
      table.platform
    ),
    foreignKey({
      name: "content_variants_user_item_fk",
      columns: [table.userId, table.contentItemId],
      foreignColumns: [contentItems.userId, contentItems.id],
    }).onDelete("cascade"),
    check(
      "content_variants_platform_check",
      sql`${table.platform} IN ('twitter', 'linkedin', 'blog', 'instagram', 'youtube', 'newsletter', 'other')`
    ),
    check(
      "content_variants_status_check",
      sql`${table.status} IN ('draft', 'ready', 'published')`
    ),
    check("content_variants_char_count_non_negative", sql`${table.charCount} >= 0`),
    index("content_variants_user_id_idx").on(table.userId),
    index("content_variants_user_item_idx").on(
      table.userId,
      table.contentItemId
    ),
    index("content_variants_user_platform_idx").on(
      table.userId,
      table.platform
    ),
  ]
);

export const contentItem = contentItems;
export const contentVariant = contentVariants;

export type ContentItem = typeof contentItems.$inferSelect;
export type NewContentItem = typeof contentItems.$inferInsert;
export type ContentVariant = typeof contentVariants.$inferSelect;
export type NewContentVariant = typeof contentVariants.$inferInsert;
```

### 4.2 Platform Validation Rules: `src/server/content/platform-validator.ts`
Pure TypeScript validator module checking platform limits and invariants:
- **Twitter/X**:
  - Max 280 characters per tweet (accounting for standard URL weight: 23 chars per URL).
  - If `contentType === "thread"` or `threadItems` has length > 1:
    - Every tweet in the thread must not exceed 280 chars.
    - Automated thread numbering helper (e.g. `1/5 ...`, `2/5 ...`).
    - Helper `splitIntoTweets(text: string, numbering: boolean): string[]`.
- **LinkedIn**:
  - Max 3,000 characters.
  - Hashtag extraction and formatting recommendations.
- **Blog / Article**:
  - Markdown syntax validation.
  - Auto-generated URL slug (kebab-case alphanumeric regex).
  - Word count and estimated reading time calculation (`Math.ceil(wordCount / 200)` minutes).

### 4.3 Workflow State Machine: `src/server/content/workflow.ts`
- Explicit status transition matrix:
  ```typescript
  const ALLOWED_TRANSITIONS: Record<ContentStatus, ContentStatus[]> = {
    idea: ["draft", "archived"],
    draft: ["in_review", "idea", "scheduled", "archived"],
    in_review: ["draft", "scheduled", "published", "archived"],
    scheduled: ["in_review", "draft", "published", "archived"],
    published: ["archived", "in_review"], // In review allowed for post-publication revisions
    archived: ["idea", "draft", "in_review", "scheduled", "published"], // Restore
  };
  ```
- Validation guards:
  - Cannot transition to `scheduled` without a valid `scheduledAt` timestamp in the future (or current day) AND at least one platform variant.
  - Transition to `published` automatically sets `publishedAt` to now if not provided.
  - Emits immutable audit log entry via `auditLog` for status changes.

### 4.4 Content Service: `src/server/content/service.ts`
- `listContentItems(userId, filters)`: Filterable, paginated query returning items with linked variant summaries and entity names.
- `getContentItemById(userId, contentItemId)`: Retrieves single content item with all associated variants, linked project name, goal title, and note title.
- `createContentItem(userId, input)`: Inserts content item and automatically creates initial platform variants if `targetChannels` specified.
- `updateContentItem(userId, contentItemId, input)`: Updates metadata and validates ownership.
- `deleteContentItem(userId, contentItemId, hardDelete)`: Soft archives by default (`isArchived = true`, `status = 'archived'`); hard delete cascade with `?hard=true`.
- `upsertContentVariant(userId, contentItemId, input)`: Creates or updates a platform variant; recalculates `charCount` and validates platform rules.
- `deleteContentVariant(userId, contentItemId, variantId)`: Removes specific platform variant.
- `transitionContentStatus(userId, contentItemId, targetStatus, metadata)`: Executes workflow state transition within transaction, updating timestamps and recording audit event.

## 5. API Routes

All endpoints enforce `requireAuthenticatedUser(req)`, strict user-scoped database isolation, Zod validation, and standard error handling (`400`, `401`, `403`, `404`, `500`).

- `GET /api/content`: List content items with filter parameters (`status`, `platform`, `topic`, `tag`, `search`, pagination).
- `POST /api/content`: Create content item and optional initial variants.
- `GET /api/content/[id]`: Get full content item with all platform variants and cross-entity metadata.
- `PATCH /api/content/[id]`: Update content item properties.
- `DELETE /api/content/[id]`: Soft archive or hard delete (`?hard=true`).
- `POST /api/content/[id]/variants`: Upsert platform variant (Twitter, LinkedIn, Blog, etc.).
- `DELETE /api/content/[id]/variants/[variantId]`: Delete specific variant.
- `POST /api/content/[id]/status`: Trigger workflow status transition with guard validation.

## 7. Security Model & Multi-Tenant Authorization

1. **Authentication Gate**: All API routes and server actions call `requireAuthenticatedUser(req)`. Unauthenticated requests immediately reject with `401 Unauthorized`.
2. **Resource Ownership Guard**: All queries strictly include `where(eq(table.userId, user.id))`. Client-supplied `userId` parameters are completely ignored.
3. **Composite Database Constraints**:
   - `content_items` has `UNIQUE (user_id, id)`.
   - `content_variants` has `UNIQUE (user_id, id)` and composite foreign key `(user_id, content_item_id) REFERENCES content_items(user_id, id) ON DELETE CASCADE`.
   Cross-tenant variant attachment is physically impossible in PostgreSQL.
4. **Audit Logging**: Any status transition or deletion creates an immutable audit record in `audit_log` with `category = 'mutation'`, `action = 'content.status_transition'` or `action = 'content.delete'`, recording `contentItemId`, previous status, and new status.
