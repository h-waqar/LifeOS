# Plan 10-02: Headless CLI Commands for Entity CRUD, Context Inspection & Daily Planning

**Phase:** Phase 10: Shared Application Services & Headless CLI  
**Plan:** 10-02  
**Status:** Pending  
**Dependencies:** Plan 10-01 (CLI runner foundation, auth, formatters, lifecycle)  
**Requirements Covered:** CLI-03, CLI-04, CLI-05  

---

## 1. Objective

Implement headless CLI subcommands for context/status inspection, domain entity CRUD, and daily planning workflows by strictly delegating to existing canonical server domain services and domain Zod validation schemas:
1. **Context & Status Inspection (CLI-03):** Implement `lifeos status` and `lifeos context` in `src/cli/commands/context.ts`:
   - Aggregate current goals (`status: in_progress`), active projects (`status: active`), top daily tasks (sorted by canonical priority score), upcoming calendar time blocks, and unread notifications count/list.
   - Strictly reuse canonical application services: `getDashboardOverview` (`@/server/dashboard/service`), `listNotifications` / `getUnreadCount` (`@/server/notifications/service`), and `listTimeBlocks` (`@/server/calendar/service`).
2. **Entity CRUD Operations (CLI-04):** Implement validated CRUD/list/filter subcommands for tasks, projects, goals, notes, and habits:
   - `lifeos tasks [list|get|create|update|delete]` (`src/cli/commands/tasks.ts`):
     - `list`: Filter by `--status`, `--project-id`, `--priority`, `--energy`, `--scheduled-date`, `--overdue`.
     - `get <id>`: Inspect detailed task with dependencies and priority score.
     - `create`: Validate payload with canonical `createTaskSchema`, delegate to `createTask(userId, data)`.
     - `update <id>`: Validate payload with canonical `updateTaskSchema`, delegate to `updateTask(userId, id, data)`.
     - `delete <id>`: Delegate to `deleteTask(userId, id)`.
   - `lifeos projects [list|get|create|update|delete]` (`src/cli/commands/projects.ts`):
     - `list`: Filter by `--status`, `--area`.
     - `get <id>`: Inspect detailed project with milestones.
     - `create`: Validate payload with canonical `createProjectSchema`, delegate to `createProject(userId, data)`.
     - `update <id>`: Validate payload with canonical `updateProjectSchema`, delegate to `updateProject(userId, id, data)`.
     - `delete <id>`: Delegate to `deleteProject(userId, id)`.
   - `lifeos goals [list|get|create|update|delete]` (`src/cli/commands/goals.ts`):
     - `list`: Filter by `--status`, `--horizon`, `--area`.
     - `get <id>`: Inspect detailed goal with progress and metric details.
     - `create`: Validate payload with canonical `createGoalSchema`, delegate to `createGoal(userId, data)`.
     - `update <id>`: Validate payload with canonical `updateGoalSchema`, delegate to `updateGoal(userId, id, data)`.
     - `delete <id>`: Delegate to `deleteGoal(userId, id)`.
   - `lifeos notes [list|get|create|update|delete]` (`src/cli/commands/notes.ts`):
     - `list`: Filter by `--type`, `--area`, `--tag`.
     - `get <id>`: Inspect detailed note with backlinks and content.
     - `create`: Validate payload with canonical `createNoteSchema`, delegate to `createNote(userId, data)`.
     - `update <id>`: Validate payload with canonical `updateNoteSchema`, delegate to `updateNote(userId, id, data)`.
     - `delete <id>`: Delegate to `deleteNote(userId, id)`.
   - `lifeos habits [list|get|create|update|delete|log]` (`src/cli/commands/habits.ts`):
     - `list`: Filter by `--area`, `--frequency`, `--status`.
     - `get <id>`: Inspect detailed habit with streak stats and history.
     - `create`: Validate payload with canonical `createHabitSchema`, delegate to `createHabit(userId, data)`.
     - `update <id>`: Validate payload with canonical `updateHabitSchema`, delegate to `updateHabit(userId, id, data)`.
     - `delete <id>`: Delegate to `deleteHabit(userId, id)`.
     - `log <id>`: Log habit completion for date/value via `logHabitEntry` / `toggleHabitEntry`.
3. **Daily Planning Workflows (CLI-05):** Implement `lifeos plan morning` and `lifeos plan evening` in `src/cli/commands/plan.ts`:
   - `lifeos plan morning`:
     - Inspect today's plan, overdue tasks, priority suggestions, and habit intentions.
     - Complete/save plan via canonical `saveMorningPlan(userId, input)` with `saveMorningPlanSchema`.
   - `lifeos plan evening`:
     - Inspect completed tasks, completed habits, and incomplete tasks for review.
     - Submit review via canonical `completeEveningReview(userId, input)` with `completeEveningReviewSchema`.
     - Execute task rollover via canonical `executeRollover(userId, input)` with `executeRolloverSchema`.
4. **Architectural Guardrails:**
   - No direct SQL queries in any CLI command handlers.
   - User identity `userId` is obtained strictly from the validated session context; passing `user_id` or `--userId` as a CLI flag is prohibited and rejected.
   - All inputs are validated against canonical domain Zod schemas before reaching domain services.
   - Any validation errors return structured error messages and exit code 2.

## 4. Implementation Steps

1. **Context & Status Commands (`src/cli/commands/context.ts`):**
   - Implement `handleStatus(context, flags)` and `handleContext(context, flags)`:
     - Invoke `getDashboardOverview(userId, today)`.
     - Invoke `listNotifications(userId, { read: false, limit: 10 })` and `getUnreadCount(userId)`.
     - Invoke `listTimeBlocks(userId, { startDate: todayStart, endDate: todayEnd })`.
     - Aggregate into unified context structure:
       ```ts
       {
         date: string,
         user: { name: string },
         metrics: DashboardMetricsDTO,
         goals: GoalDTO[],
         projects: ProjectDTO[],
         tasks: { priority: TaskDTO[], overdue: TaskDTO[] },
         schedule: TimeBlockDTO[],
         notifications: { unreadCount: number, items: NotificationDTO[] },
         habits: { items: HabitDTO[], completionRate: number }
       }
       ```
     - For `--json`: Return strictly-typed aggregated object.
     - For default: Render structured sections: "Current Goals", "Active Projects", "Top Tasks Today", "Upcoming Schedule", "Unread Notifications", "Habits Today".

2. **Task Commands (`src/cli/commands/tasks.ts`):**
   - `tasks list`: Parse flags (`--status`, `--project`, `--priority`, `--energy`, `--scheduled-date`, `--overdue`), invoke `listTasks(userId, filter)`.
   - `tasks get <id>`: Invoke `getTask(userId, id)`.
   - `tasks create`: Parse and validate flags against `createTaskSchema`, invoke `createTask(userId, data)`.
   - `tasks update <id>`: Parse and validate flags against `updateTaskSchema`, invoke `updateTask(userId, id, data)`.
   - `tasks delete <id>`: Invoke `deleteTask(userId, id)`.

3. **Project Commands (`src/cli/commands/projects.ts`):**
   - `projects list`: Parse flags (`--status`, `--area`), invoke `listProjects(userId, filter)`.
   - `projects get <id>`: Invoke `getProject(userId, id)`.
   - `projects create`: Parse and validate flags against `createProjectSchema`, invoke `createProject(userId, data)`.
   - `projects update <id>`: Parse and validate flags against `updateProjectSchema`, invoke `updateProject(userId, id, data)`.
   - `projects delete <id>`: Invoke `deleteProject(userId, id)`.

4. **Goal Commands (`src/cli/commands/goals.ts`):**
   - `goals list`: Parse flags (`--status`, `--horizon`, `--area`), invoke `listGoals(userId, filter)`.
   - `goals get <id>`: Invoke `getGoal(userId, id)`.
   - `goals create`: Parse and validate flags against `createGoalSchema`, invoke `createGoal(userId, data)`.
   - `goals update <id>`: Parse and validate flags against `updateGoalSchema`, invoke `updateGoal(userId, id, data)`.
   - `goals delete <id>`: Invoke `deleteGoal(userId, id)`.

5. **Note Commands (`src/cli/commands/notes.ts`):**
   - `notes list`: Parse flags (`--type`, `--area`, `--tag`), invoke `listNotes(userId, filter)`.
   - `notes get <id>`: Invoke `getNoteById(userId, id)`.
   - `notes create`: Parse and validate flags against `createNoteSchema`, invoke `createNote(userId, data)`.
   - `notes update <id>`: Parse and validate flags against `updateNoteSchema`, invoke `updateNote(userId, id, data)`.
   - `notes delete <id>`: Invoke `deleteNote(userId, id)`.

6. **Habit Commands (`src/cli/commands/habits.ts`):**
   - `habits list`: Parse flags (`--area`, `--frequency`, `--status`), invoke `listHabits(userId, filter)`.
   - `habits get <id>`: Invoke `getHabit(userId, id)`.
   - `habits create`: Parse and validate flags against `createHabitSchema`, invoke `createHabit(userId, data)`.
   - `habits update <id>`: Parse and validate flags against `updateHabitSchema`, invoke `updateHabit(userId, id, data)`.
   - `habits delete <id>`: Invoke `deleteHabit(userId, id)`.
   - `habits log <id>`: Parse `--date`, `--completed`, `--notes`, invoke `logHabitEntry` or `toggleHabitEntry`.

7. **Daily Planning Commands (`src/cli/commands/plan.ts`):**
   - `plan morning`:
     - Default without flags: Display today's plan status, overdue tasks, priority task candidates, and habit intentions via `getDailyPlan(userId, date)`.
     - With completion flags (`--priority-tasks <id,...>`, `--habit-intentions <id,...>`, `--notes <string>`, `--complete`): Validate against `saveMorningPlanSchema` and invoke `saveMorningPlan(userId, input)`.
   - `plan evening`:
     - Default without flags: Display daily plan review status, completed tasks count, completed habits count, and pending tasks requiring rollover via `getDailyPlan(userId, date)`.
     - With review flags (`--rating <1-10>`, `--reflections <string>`, `--challenges <string>`, `--rollover <json|string>`): Validate against `completeEveningReviewSchema` and invoke `completeEveningReview(userId, input)`. If rollover actions provided, validate with `executeRolloverSchema` and execute `executeRollover(userId, rolloverInput)`.

8. **Router Registration (`src/cli/index.ts`):**
   - Connect all command modules to `src/cli/index.ts`.
   - Ensure help documentation (`--help`) is available for every command and subcommand.

9. **Automated Verification (`scripts/tests/phase-10/plan-02/cli-commands.test.ts`):**

   - Test task CRUD and filter operations, verifying Zod validation error on empty title or invalid priority.

   - Test that invalid flags or schema failures return exit code 2 (`ERROR_VALIDATION`).

## 6. Acceptance Criteria

1. `lifeos status` and `lifeos context` return unified life context (active goals, projects, top tasks, upcoming blocks, unread notifications) by delegating strictly to canonical services.
2. `lifeos tasks`, `lifeos projects`, `lifeos goals`, `lifeos notes`, and `lifeos habits` provide complete CRUD and list/filter capabilities.
3. Every mutating and reading command validates inputs through existing domain Zod schemas; malformed input is rejected with exit code 2 and structured validation error details.
4. `lifeos plan morning` and `lifeos plan evening` allow inspecting and completing daily planning and review workflows without browser interaction.
5. All commands support `--json` with deterministic JSON outputs and clean default tabular formatting.
6. Zero raw SQL queries are introduced in CLI command files.
