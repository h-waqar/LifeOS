## 1. Objective

Provide end-to-end integration tests, subprocess-level execution tests (`child_process.spawnSync` against `bin/lifeos.js`), adversarial security verification, and complete regression test coverage:
1. **Real Subprocess CLI Invocation:** Test execution of the real executable entry point `bin/lifeos.js` from child process, confirming:
   - Command line parsing and option resolution.
   - Clean exit codes (`0`, `1`, `2`, `3`, `4`).
   - Clean stdout/stderr stream separation (no diagnostic warnings or banners corrupting stdout).
   - Fast cold start and clean process termination (no hanging handles, pool cleanly closed).
2. **Deterministic `--json` Output Verification (CLI-02):**
   - Ensure every command (`status`, `context`, `tasks`, `projects`, `goals`, `notes`, `habits`, `plan`) produces valid, deterministic JSON parseable by standard tooling (`jq`, `JSON.parse`).
   - Validate that on command failure, `--json` produces structured machine-readable error JSON:
     `{ "success": false, "error": { "code": string, "message": string, "status": number } }`.
3. **Tabular Output & Stream Discipline:**
   - Verify default human-readable output presents stable column alignment, clean headers, and friendly empty-state messaging.
   - Verify stderr receives error messages and diagnostic information while stdout remains reserved for command results.
4. **Adversarial & Security Boundary Verification:**
   - **Unauthenticated invocation:** Commands fail closed with exit code 3 when no token or credentials exist.
   - **Invalid or expired token:** Commands fail closed with exit code 3 when a forged, expired, or invalid token is supplied.
   - **Ownership enforcement:** A valid user's CLI cannot view, query, or mutate another user's records.
   - **Caller spoofing resistance:** Ensure callers cannot supply `--userId` or inject `userId` in flags/payloads to bypass the authenticated user session.
   - **Secret scrubbing:** Verify that tokens, session secrets, passwords, and encryption keys never appear in normal output, JSON output, error traces, or stderr.
   - **Validation invariants:** Malformed inputs fail with exit code 2 and structured validation issues; no partial or corrupt state is persisted.
5. **Full Project Regression Verification:**
   - Verify `pnpm exec tsc --noEmit` completes with 0 errors.
   - Verify full unit & integration test suite (`pnpm test`) passes with 0 regressions.
   - Verify production build (`pnpm build`) succeeds with exit code 0.

## 4. Implementation Steps

1. **Subprocess Test Harness (`scripts/tests/phase-10/plan-03/cli-integration.test.ts`):**
   - Implement `runLifeOS(args, envOptions)` helper wrapping `child_process.spawnSync` pointing to `bin/lifeos.js`:
     ```ts
     function runLifeOS(args: string[], options?: { env?: Record<string, string> }): {
       status: number | null;
       stdout: string;
       stderr: string;
       json: <T = unknown>() => T;
     }
     ```
   - Test `lifeos --version` returns version and exit code 0.
   - Test `lifeos --help` returns usage and exit code 0.
   - Test unauthenticated `lifeos status` returns exit code 3 with authentication error on stderr.
   - Test `lifeos status --json` with missing token returns exit code 3 with structured JSON error on stdout.

2. **End-to-End Command Invocations:**
   - Test `lifeos login` with valid credentials stores token and returns exit code 0.
   - Test `lifeos whoami` returns authenticated user identity.
   - Test `lifeos status` and `lifeos context` return complete aggregated state.
   - Test `lifeos tasks create --title "CLI Task" --priority high` creates task and outputs formatted result.
   - Test `lifeos tasks list --status inbox --json` returns valid JSON array containing created task.
   - Test `lifeos tasks update <id> --status completed` completes task.
   - Test `lifeos tasks delete <id>` deletes task.
   - Repeat CRUD verification across `projects`, `goals`, `notes`, `habits`.
   - Test `lifeos plan morning` and `lifeos plan evening` workflows end-to-end.

3. **Deterministic Formatting & Stream Separation:**
   - Verify JSON output:
     - Run `lifeos tasks list --json` and verify `JSON.parse(result.stdout)` succeeds without syntax error.
     - Verify object keys are sorted deterministically.
     - Verify stderr is empty when stdout contains JSON.
   - Verify tabular output:
     - Run `lifeos tasks list` (default non-JSON) and verify table headers and column alignment.
     - Verify empty results display clean `(no records found)` instead of broken table frames.

4. **Adversarial & Security Verification (`scripts/tests/phase-10/plan-03/cli-adversarial.test.ts`):**
   - **Token Tampering:** Supply mutated token `LIFEOS_TOKEN=tampered_token_xyz` -> expect exit code 3.
   - **Expired Session:** Insert expired session record into `session` table -> expect exit code 3.
   - **Cross-User Ownership Isolation:**
     - Create entity belonging to User B.
     - Execute `lifeos tasks get <user_b_task_id>` with User A's token.
     - Verify command fails with exit code 4 (`NotFoundError`) or exit code 1 / 3, without exposing User B's task details.
   - **Caller Identity Spoofing:**
     - Pass `--userId <other_user_id>` to `lifeos tasks create` or `lifeos tasks list`.
     - Verify CLI strictly rejects `--userId` as an unknown/disallowed option or ignores it in favor of session `userId`.
   - **Zod Validation Bypass Prevention:**
     - Pass invalid payload (`--title ""` or `--priority invalid_priority` or `--estimated-duration -100`).
     - Verify command fails with exit code 2 and structured validation error.
   - **Secret Scrubbing:**
     - Trigger errors containing sensitive strings (e.g. invalid tokens, passwords).
     - Verify output does NOT leak plain tokens, passwords, or encryption keys.

5. **Full Repository Regression Suite:**
   - Execute `pnpm exec tsc --noEmit` -> ensure 0 TypeScript errors.
   - Execute `pnpm test` -> ensure all existing 105+ test files pass with 0 regressions.
   - Execute `pnpm build` -> ensure Next.js production build completes with exit code 0.

## 6. Acceptance Criteria

1. Subprocess invocation of `bin/lifeos.js` succeeds in standard Node.js environment without warnings or hanging processes.
2. Unauthenticated calls fail closed with exit code 3.
3. Passing `--json` emits strictly valid, deterministic JSON on stdout; diagnostics, warnings, and error messages are isolated to stderr.
4. Output formatting never leaks sensitive credentials, session tokens, or encryption keys.
5. Cross-user data access is strictly blocked; caller identity is anchored to the authenticated session.
6. Input validation rejections return exit code 2 and structured validation issue descriptions.
7. Full project regression suite (`tsc`, `pnpm test`, `next build`) passes with zero failures.
