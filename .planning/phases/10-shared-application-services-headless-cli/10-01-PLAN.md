# Plan 10-01: Shared Domain Service Contracts & Standalone CLI Runner Foundation

**Phase:** Phase 10: Shared Application Services & Headless CLI  
**Plan:** 10-01  
**Status:** Pending  
**Dependencies:** Milestone 1.0 Baseline (`src/server/auth/`, `src/server/db/`, `src/lib/env.ts`)  
**Requirements Covered:** CLI-01, CLI-02  

---

## 1. Objective

Establish the pure TypeScript standalone CLI executable and runner foundation for LifeOS without launching the browser:
1. **Canonical Executable Entry Point:** Create `bin/lifeos.js` (Node wrapper with signal handling, `NODE_NO_WARNINGS=1`, executable permissions) and `bin/lifeos.ts` (TypeScript executable entry point), registered in `package.json` under `"bin"` and `"scripts"`.
2. **Deterministic Argument & Flag Parsing:** Implement a robust command router in `src/cli/index.ts` supporting hierarchical subcommands (`lifeos [group] [action] [args]`) and global flags (`--json`, `--help`, `--version`, `--token`, `--config`).
3. **Environment & Credential Resolution (CLI-01):** Implement `src/cli/config.ts` supporting persistent credentials at `~/.config/lifeos/credentials.json` (or `~/.lifeos/credentials.json`) with strict file mode `0o600`, overridden by `LIFEOS_TOKEN` environment variable or `--token` CLI flag.
4. **Authentication & Session Management (CLI-01):** Implement `src/cli/auth.ts` integrating with Better Auth (`session` and `user` tables via `@/server/auth` and `@/server/db`). Implement authentication verification and CLI subcommands:
   - `lifeos login`: Authenticate with email/password via `auth.api.signInEmail` and securely persist the session token.
   - `lifeos logout`: Revoke active session via `auth.api.revokeSession` and delete stored credentials.
   - `lifeos whoami`: Display authenticated user details (ID, email, name, session expiration).
5. **Deterministic Output Formatters (CLI-02):** Implement `src/cli/formatters.ts`:
   - `--json`: Machine-readable, strictly-typed, deterministic JSON serialization with sorted keys and stable indentation; zero console logs or banners on stdout.
   - Default: Stable tabular and human-readable formatted output with consistent headers, column ordering, and graceful empty-state handling.
   - Stdout/stderr separation: Clean data to stdout; errors, warnings, and progress strictly to stderr.
6. **Error Handling & Stable Exit Codes:** Implement `src/cli/errors.ts` mapping errors to stable POSIX exit codes:
   - `0`: Success
   - `1`: General / domain execution error
   - `2`: Command usage or Zod input validation failure
   - `3`: Authentication / session failure (missing, expired, or invalid token)
   - `4`: Resource not found error
   - Redaction: Automatic secret scrubbing so tokens, passwords, and secrets never appear in error messages, stack traces, or logs.
7. **Process Lifecycle & Database Teardown:** Implement `src/cli/lifecycle.ts` ensuring `await closeDatabase()` is always executed in a top-level `finally` block and on `SIGINT` / `SIGTERM` signals.

## 4. Implementation Steps

1. **CLI Core Types & Exit Codes (`src/cli/types.ts` & `src/cli/errors.ts`):**
   - Define command interfaces: `CommandContext`, `CommandResult<T>`, `GlobalOptions`.
   - Define exit code constants: `SUCCESS = 0`, `ERROR_GENERAL = 1`, `ERROR_VALIDATION = 2`, `ERROR_AUTH = 3`, `ERROR_NOT_FOUND = 4`.
   - Implement `formatCliError(error, isJson)` with secret scrubbing (masking tokens, passwords, secrets).

2. **Configuration & Credential Storage (`src/cli/config.ts`):**
   - Resolve config directory: `~/.config/lifeos` (fallback: `~/.lifeos`).
   - Implement `loadCredentials()`: Read `credentials.json` with permission check (`0o600` on POSIX).
   - Implement `saveCredentials(token, user)`: Write atomic file with `mode: 0o600`.
   - Implement `clearCredentials()`: Remove `credentials.json`.
   - Implement `resolveToken(options)`: Check `options.token` -> `process.env.LIFEOS_TOKEN` -> stored credentials.

3. **Authentication Boundary (`src/cli/auth.ts` & `src/cli/commands/auth.ts`):**
   - Implement `resolveAuthenticatedUser(token)`:
     - Query Better Auth session: `SELECT s.*, u.* FROM session s JOIN "user" u ON s.user_id = u.id WHERE s.token = :token AND s.expires_at > NOW()`.
     - Reject with `ERROR_AUTH` (exit code 3) if missing, invalid, or expired.
   - Implement `handleLogin(options)`: Call `auth.api.signInEmail({ body: { email, password } })`, save session token to credentials.
   - Implement `handleLogout(options)`: Call `auth.api.revokeSession`, clear local credentials.
   - Implement `handleWhoami(options)`: Output user ID, email, name, session expiration.

4. **Output Formatters (`src/cli/formatters.ts`):**
   - Implement `formatJson(data)`: Deterministic JSON serialization with recursively sorted object keys and 2-space indentation. Ensure errors serialize to `{ "success": false, "error": { "code": string, "message": string, "details"?: unknown } }`.
   - Implement `formatTable(columns, rows, options)`: Stable tabular display with column alignment, headers, and clean message on empty rows (`(no records found)`).
   - Enforce stdout/stderr discipline: Formatters write results to `process.stdout`; warnings and diagnostics write to `process.stderr`.

5. **Process Lifecycle & Teardown (`src/cli/lifecycle.ts`):**
   - Wrap command execution in `try / finally` calling `await closeDatabase()`.
   - Register process signal handlers (`SIGINT`, `SIGTERM`, `beforeExit`) to trigger graceful database pool shutdown.

6. **CLI Runner & Entry Point (`src/cli/index.ts`, `bin/lifeos.ts`, `bin/lifeos.js`):**
   - Implement `main(argv)` parsing arguments, routing to subcommands, handling `--json`, `--help`, `--version`, and catching errors to set `process.exitCode`.
   - Create `bin/lifeos.ts` delegating to `main()`.
   - Create `bin/lifeos.js` Node runner script (`chmod +x bin/lifeos.js`).
   - Update `package.json` with `"bin"` mapping.

7. **Automated Verification (`scripts/tests/phase-10/plan-01/cli-runner.test.ts`):**
   - Test config loading from env, flags, and credentials file.
   - Test credential permissions (`0o600`).
   - Test auth session verification, rejection on invalid/expired token.
   - Test login/logout/whoami commands.
   - Test deterministic `--json` formatting (key sorting, no random order).
   - Test tabular formatting and empty result sets.
   - Test exit codes: 0, 1, 2, 3, 4.
   - Test secret scrubbing (tokens never printed in output or errors).
   - Test lifecycle teardown (`closeDatabase` called).

## 6. Acceptance Criteria

1. `lifeos --version` and `lifeos --help` execute and return cleanly without database connection.
2. Invoking any protected CLI command without a token returns exit code 3 (`ERROR_AUTH`) and a structured error message.
3. Invoking protected commands with a valid token resolves the authenticated user session without browser involvement.
4. Passing `--json` produces deterministic JSON with sorted keys and zero extraneous output on stdout.
5. Default non-JSON output displays clean tabular views with stable column ordering and empty-state messaging.
6. Database connections are closed cleanly on process completion or interruption (`SIGINT`/`SIGTERM`), preventing hung CLI processes.
7. Secrets (passwords, tokens, encryption keys) are scrubbed from all error messages and output.
