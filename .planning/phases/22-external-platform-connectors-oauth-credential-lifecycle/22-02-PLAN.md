<threat_model>
### ASVS Level 1 Threat Analysis & Security Controls

| Threat ID | Category / CWE | Threat Description & Attack Surface | ASVS L1 Mitigation & Architectural Invariant |
|---|---|---|---|
| **T-22-06** | CWE-20 / CWE-918 (Input Injection & SSRF) | Parameter injection or SSRF redirection via malformed or malicious webhook endpoints and platform parameters. | Strictly typed `SocialPlatformAdapter` contract isolating provider communication. Twitter and LinkedIn endpoints hardcoded to official APIs (`api.twitter.com/2/`, `api.linkedin.com/v2/`). Blog webhook URLs validated via Zod schema disallowing non-HTTP(S) schemas and internal loopback addresses in production. (D-05, D-06) |
| **T-22-07** | CWE-208 (Timing Side-Channel on HMAC) | Attacker performs byte-by-byte timing discrepancy attacks to forge webhook signatures (`X-LifeOS-Signature-256`). | Strict timing-safe verification via `crypto.timingSafeEqual` with byte-length equality pre-check; fails closed immediately without variable latency. (D-05) |
| **T-22-08** | CWE-200 (Sensitive Credential Leakage in DTOs) | Web browser clients receiving encrypted or plaintext tokens in API responses, exposing credentials to client-side scripts and XSS. | Strict transformation to `SocialConnectionDTO` on all GET responses; explicitly scrubs `encryptedAccessToken`, `encryptedRefreshToken`, and shared secrets. Only non-sensitive metadata (handle, display name, status, expiration date) is exposed. (D-03) |
| **T-22-09** | CWE-284 (Improper Access Control / Cross-Tenant) | Unauthorized or cross-tenant actor disconnects or reconfigures another user's external social connectors. | `requireAuthenticatedUser` guard enforced at the entry of every route handler; all database operations strictly filter by `userId === session.user.id`. (D-01) |
| **T-22-10** | CWE-400 (Uncontrolled Resource Consumption) | External API rate limits (HTTP 429) cause cascading hangs in downstream worker queues. | Adapter normalizes 429 responses into `PlatformRateLimitError` extracting `x-rate-limit-remaining`, `x-rate-limit-reset`, or `Retry-After`, providing structured retry hints to callers. (D-06) |
</threat_model>

         export interface SocialPlatformAdapter {

           getAuthorizationUrl(params: { userId: string; redirectUri: string; state: string; codeChallenge?: string }): string;
           exchangeCode(params: { code: string; redirectUri: string; codeVerifier?: string }): Promise<OAuthTokens>;

         - `getAuthorizationUrl`: Constructs `https://twitter.com/i/oauth2/authorize` with query params:
           `response_type=code`, `client_id`, `redirect_uri`, `scope=tweet.read tweet.write users.read offline.access`, `state`, `code_challenge`, `code_challenge_method=S256`.

         - `parseRateLimits`: Extracts `x-rate-limit-limit`, `x-rate-limit-remaining`, and `x-rate-limit-reset`.
         - Error normalization: Catches HTTP non-2xx responses and throws `PlatformAuthenticationError` on 401/403, `PlatformRateLimitError` on 429, `PlatformNetworkError` on 5xx, or `PlatformPayloadError` on 400.

  <action>
    Implement Decisions D-03 and D-05 for outbound blog webhook signing and verification:
    1. Create `src/server/integrations/social/adapters/blog-adapter.ts`:
       - Implement `BlogAdapter` conforming to `SocialPlatformAdapter`:
         - `platform = "blog"`
         - `computeSignature(rawBody: string, secret: string): string`:
           - Computes HMAC-SHA256 hex digest:
             `const hash = crypto.createHmac("sha256", secret).update(rawBody, "utf8").digest("hex");`
           - Returns `sha256=${hash}` format.
         - `verifySignature(rawBody: string, signatureHeader: string, secret: string): boolean`:
           - Validates `signatureHeader` starts with `sha256=`.
           - Extracts provided hex digest; computes expected hex digest via `computeSignature`.
           - Converts both to `Buffer.from(..., "hex")`.
           - If buffer lengths differ, returns `false` immediately to prevent exception.
           - Returns `crypto.timingSafeEqual(providedBuf, expectedBuf)` (strictly prevents timing side-channel attacks).
         - `verifyWebhook(params: { webhookUrl: string; secret: string }): Promise<BlogVerificationResult>`:
           - Constructs ping payload:
             ```json
             {
               "event": "lifeos.ping",
               "timestamp": new Date().toISOString(),
               "version": "1.0"
             }
             ```
           - Serializes body to UTF-8 JSON string.
           - Computes signature header `X-LifeOS-Signature-256`.
           - Sends POST request with `fetch` using `signal: AbortSignal.timeout(5000)`:
             - Headers: `Content-Type: application/json`, `User-Agent: LifeOS-Webhook/1.0`, `X-LifeOS-Signature-256: <sig>`.
           - Measures start and end time to calculate `latencyMs`.
           - Returns `{ success: response.ok, status: response.status, latencyMs, message: response.ok ? "Ping verified" : \`HTTP \${response.status}\` }`.
           - Catches network errors/timeouts and returns `{ success: false, status: 0, latencyMs, message: error.message }`.
         - Stub OAuth methods (`getAuthorizationUrl`, `exchangeCode`, `refreshToken`) to throw `PlatformPayloadError("Blog connector does not use OAuth; use webhook configuration")`.
    2. Write unit test suite in `scripts/tests/phase-22/plan-02/blog-webhook.test.ts`:
       - Tests HMAC-SHA256 signature computation over arbitrary payloads.
       - Tests `verifySignature`:
         - Valid signature returns true.
         - Single-bit or single-character tampered signature returns false.
         - Malformed header (missing `sha256=` prefix) returns false.
         - Length mismatch returns false without throwing.
       - Tests `verifyWebhook` against an ephemeral Node `http.createServer`:
         - Test server verifies received `X-LifeOS-Signature-256` matches calculated HMAC.
         - Returns 200 OK -> `verifyWebhook` reports success with roundtrip latency.
         - Test server returns 500 Internal Server Error -> reports `success: false, status: 500`.
         - Test server drops connection / times out -> reports `success: false`.
  </action>
