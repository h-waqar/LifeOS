<threat_model>
### ASVS Level 1 Threat Analysis & Security Controls

| Threat ID | Category / CWE | Threat Description & Attack Surface | ASVS L1 Mitigation & Architectural Invariant |
|---|---|---|---|
| **T-22-01** | CWE-20 (Improper Input Validation) | Insertion of arbitrary provider strings bypassing adapter validation and breaking state transitions. | Strict PostgreSQL `CHECK` constraint on `integration_connections.provider` in migration 0028 (`CHECK ("provider" IN ('google_calendar', 'github', 'backup', 'twitter', 'linkedin', 'blog'))`), matching TypeScript schema enum; verified with linear Drizzle Kit snapshot continuity (`0028_snapshot.json` linked to `0027_snapshot.json`). (D-02) |
| **T-22-02** | CWE-384 / CWE-352 (Session Fixation & CSRF) | Attacker initiates OAuth flow and tricks victim into completing callback, or swaps PKCE verifier, attaching attacker's account to victim's LifeOS. | Ephemeral encrypted session cookies (`oauth_state_${provider}`) containing `userId`, `stateNonce`, and PKCE `codeVerifier`, encrypted with AES-256-GCM authenticated ciphertext and 10-minute TTL (D-01). Callback strictly enforces `cookie.userId === session.user.id` and validates `cookie.stateNonce === query.state`. Cookie deleted immediately after single use. |
| **T-22-03** | CWE-312 / CWE-532 (Cleartext Secret Storage & Log Leakage) | Plaintext OAuth access tokens, refresh tokens, and blog secrets exposed in database dumps, logs, or error stack traces. | AES-256-GCM encryption at rest via `encryptSecret` (`src/lib/crypto.ts`) with NIST 96-bit random IV and 128-bit authentication tag (D-03). Zero plaintext tokens in logs, database audit payloads, or API response DTOs. |
| **T-22-04** | CWE-362 (Race Condition / Concurrency) | Simultaneous requests trigger parallel token refresh requests to Twitter/LinkedIn. Twitter rotates refresh tokens upon use; parallel requests using the same old refresh token cause one or both to be invalidated, leaving the user permanently disconnected. | Concurrency-safe proactive token refresh (<5m threshold) guarded by PostgreSQL row-level pessimistic locking (`SELECT ... FOR UPDATE` on `integration_connections`) within an atomic transaction. Re-evaluates expiration timestamp inside the lock; if already refreshed, returns the fresh token immediately without an external HTTP call (D-04). |
| **T-22-05** | CWE-670 (Fail-Open on Auth Failure) | Expired or revoked credentials continue to be attempted repeatedly, leading to rate limit bans or silent failures. | Unrecoverable failures (HTTP 401, `invalid_grant`, revoked token) immediately transition connection status to `'expired'`, purge cached access/refresh tokens to `null`, record sanitized error metadata, and emit transactional audit logs (D-04). |
</threat_model>

    Implement Decisions D-03, D-04, and D-06 for proactive token lifecycle management, concurrency safety, and typed error handling:
    1. Create `src/server/integrations/social/errors.ts`:
       - `PlatformError` base class extending `Error` with `platform`, `statusCode`, and `retryable` properties.
       - `PlatformAuthenticationError` (statusCode: 401, retryable: false).
       - `PlatformRateLimitError` (statusCode: 429, retryable: true, includes `RateLimitInfo`).
       - `PlatformNetworkError` (statusCode: 502, retryable: true).
       - `PlatformPayloadError` (statusCode: 400, retryable: false).
    2. Create `src/server/integrations/social/token-manager.ts`:
       - Implement `SocialTokenManager` class:
         - `getValidAccessToken(params: { userId: string; provider: SocialPlatform; refreshFn: (refreshToken: string) => Promise<OAuthTokens> }): Promise<string>`:
           - Wraps operation in `db.transaction(async (tx) => ...)`.
           - Queries `integrationConnections` where `userId = params.userId` and `provider = params.provider` using `.for("update")` pessimistic row-level lock.
           - If connection missing or status not `'connected'`, throws `PlatformAuthenticationError`.
           - If `encryptedAccessToken` is null, throws `PlatformAuthenticationError`.
           - Computes remaining lifetime: `timeRemaining = (conn.tokenExpiresAt?.getTime() ?? 0) - Date.now()`.
           - If `timeRemaining > 5 * 60 * 1000` (5-minute threshold):
             - Decrypts and returns `decryptSecret(conn.encryptedAccessToken)`.
           - If `timeRemaining <= 5 * 60 * 1000`:
             - Requires `conn.encryptedRefreshToken`; if missing, transitions status to `'expired'`, nulls tokens, logs audit event, and throws `PlatformAuthenticationError`.
             - Decrypts refresh token: `rawRefreshToken = decryptSecret(conn.encryptedRefreshToken)`.
             - Executes `params.refreshFn(rawRefreshToken)`.
             - On refresh success:
               - Encrypts new access token: `encryptSecret(newTokens.access_token)`.
               - If `newTokens.refresh_token` provided (token rotation, e.g. Twitter), encrypts new refresh token: `encryptSecret(newTokens.refresh_token)`. Otherwise preserves existing encrypted refresh token.
               - Updates database row with new encrypted token(s), `tokenExpiresAt = new Date(Date.now() + newTokens.expires_in * 1000)`, and `updatedAt: new Date()`.
               - Emits audit log via `createAuditLog` with `category: "security"`, `action: "social_token_refreshed"`, `status: "success"`, passing `tx`.
               - Returns `newTokens.access_token`.
             - On unrecoverable error (`PlatformAuthenticationError`):
               - Transitions status to `'expired'`.
               - Wipes `encryptedAccessToken = null` and `encryptedRefreshToken = null`.
               - Updates `metadata.lastError` with sanitized error message (zero plaintext tokens).
               - Emits audit log with `action: "social_token_expired"`, `status: "failure"`, passing `tx`.
               - Throws `PlatformAuthenticationError`.
         - `saveConnection(params: { userId: string; provider: SocialPlatform; tokens?: OAuthTokens; sharedSecret?: string; externalAccountId?: string; metadata?: Record<string, unknown> }): Promise<string>`:
           - Encrypts tokens / sharedSecret using `encryptSecret`.
           - Upserts `integrationConnections` using `onConflictDoUpdate` or select-and-update on `(userId, provider)`.
           - Emits `social_connection_created` or `social_connection_updated` audit log.
         - `disconnect(userId: string, provider: SocialPlatform): Promise<void>`:
           - Sets status to `'disconnected'`, clears `encryptedAccessToken = null`, `encryptedRefreshToken = null`.
           - Emits `social_connection_disconnected` audit log.
         - `getConnectionDTO(userId: string, provider: SocialPlatform): Promise<SocialConnectionDTO | null>`:
           - Retrieves connection, maps to sanitized `SocialConnectionDTO` scrubbing all encrypted tokens and secrets.
