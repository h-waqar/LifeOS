# Plan 19-02: Native Screen-Reader Accessibility, Auditory Traversal & Semantic ARIA Hardening

## Executive Summary
Enforces comprehensive assistive technology compatibility and eliminates auditory traps across LifeOS for native screen readers (NVDA, JAWS on Windows; VoiceOver on macOS and iOS; TalkBack on Android):
1. Delivers an accessible Skip to Main Content mechanism (`#main-content`) allowing non-visual and keyboard users to bypass repetitive navigation landmarks.
2. Hardens semantic document structure with correct ARIA landmark roles (`banner`, `navigation`, `main`, `complementary`), heading hierarchy, and accessible names for all interactive elements.
3. Implements strict focus management and trapping inside modal dialogs (`QuickCaptureModal`, `AssistantDrawer`), ensuring Tab cycling stays contained, Escape key cleanly dismisses the dialog, and focus is restored to the triggering element upon close.
4. Provides polite and assertive ARIA live regions (`aria-live="polite"` / `role="status"`, `role="alert"`) for asynchronous events: task capture confirmations, sync status, dictation state transitions, and form validation errors.

## Objectives
1. **Accessible Landmarks & Skip Link (`src/components/app-shell.tsx`)**:
   - Provide `<a href="#main-content" className="sr-only focus:not-sr-only ...">Skip to main content</a>` as the first focusable element.
   - Tag primary landmark regions with semantic `<main id="main-content">`, `<nav aria-label="Main Navigation">`, `<aside aria-label="Sidebar">`, `<header role="banner">`.
2. **Modal Dialog Focus Trapping & Zero Auditory Traps (`src/components/quick-capture-modal.tsx`)**:
   - Ensure `QuickCaptureModal` has `role="dialog"`, `aria-modal="true"`, `aria-labelledby="quick-capture-title"`.
   - Implement focus trap: when modal opens, focus moves automatically to the input; Tab/Shift+Tab cycles only between focusable elements within the modal without escaping to underlying background elements.
   - Escape key dismisses modal and restores focus to the previously active element (`triggerRef`).
3. **Screen Reader Voice & Status Feedback (`src/components/voice/voice-dictation-button.tsx`)**:
   - Provide real-time accessible state: `aria-pressed="true|false"`, `aria-label="Start voice dictation" | "Stop voice dictation"`.
   - Announce recording start, speech transcribing, and error states via an accessible live status announcement container.
4. **Accessible Form Controls & Name Computation**:
   - All icon buttons, toggle buttons, and form inputs must have unique, descriptive accessible names (`aria-label`, `<label>`, or `title`).
   - Zero unlabeled buttons or ambiguous interactive elements.
