## 1. Executive Summary & Context

Plan 02-05 implements the **Daily Planning Morning Routine and Evening Review** execution workflow for LifeOS. This system bridges strategic goals, active projects, canonical tasks, habits, and calendar time blocks into an intentional daily cadence:

1. **Morning Routine (PLAN-01):** A guided workflow where the user reviews overdue/unfinished work, commits to 3–5 top priority tasks for the day, reviews habit intentions, allocates time blocks on the calendar, and enters morning focus notes.
2. **Evening Review (PLAN-02):** A guided closing ritual where the user reviews completed and incomplete work, logs habit completions and streaks, writes daily reflections (wins and challenges), and computes a deterministic daily productivity score.
3. **Zero-Duplication Rollover (PLAN-03):** An idempotent, non-destructive carry-over mechanism for incomplete daily tasks. Uncompleted tasks can be carried over to tomorrow, rescheduled to a future date, or returned to the backlog with a single click—guaranteeing 100% stable task identity, zero duplicate task records, and zero duplicate time-block records.
4. **History & Trend Analysis (PLAN-04):** Tracking daily plan and evening review completion across 7-day (weekly) and 30-day (monthly) horizons, visualizing productivity score trends, habit consistency, and task completion velocity.

## 3. Database Architecture & Vertical-Slice Evolution

In accordance with the **Vertical-Slice Database Evolution Rule**, Plan 02-05 introduces only the relational infrastructure strictly required for daily planning:

### 3.1 `daily_plans` Table
```sql
CREATE TABLE daily_plans (
  id TEXT PRIMARY KEY,
  user_id TEXT NOT NULL REFERENCES "user"(id) ON DELETE CASCADE,
  date TEXT NOT NULL, -- ISO calendar date YYYY-MM-DD
  status TEXT NOT NULL DEFAULT 'in_progress', -- 'in_progress' | 'completed'
  priority_task_ids JSONB NOT NULL DEFAULT '[]'::jsonb,
  habit_intention_ids JSONB NOT NULL DEFAULT '[]'::jsonb,
  morning_notes TEXT,
  completed_at TIMESTAMP WITH TIME ZONE,
  created_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT NOW(),
  CONSTRAINT daily_plans_user_id_id_unique UNIQUE (user_id, id),
  CONSTRAINT daily_plans_user_date_unique UNIQUE (user_id, date),
  CONSTRAINT daily_plans_date_format CHECK (date ~ '^\d{4}-\d{2}-\d{2}$'),
  CONSTRAINT daily_plans_status_check CHECK (status IN ('in_progress', 'completed')),
  CONSTRAINT daily_plans_completed_at_invariant CHECK (status != 'completed' OR completed_at IS NOT NULL)
);
```

### 3.2 `evening_reviews` Table
```sql
CREATE TABLE evening_reviews (
  id TEXT PRIMARY KEY,
  user_id TEXT NOT NULL REFERENCES "user"(id) ON DELETE CASCADE,
  daily_plan_id TEXT,
  date TEXT NOT NULL, -- ISO calendar date YYYY-MM-DD
  productivity_score INTEGER NOT NULL DEFAULT 0, -- 0 to 100
  positive_reflections TEXT,
  challenges_reflections TEXT,
  notes TEXT,
  completed_task_ids JSONB NOT NULL DEFAULT '[]'::jsonb,
  incomplete_task_ids JSONB NOT NULL DEFAULT '[]'::jsonb,
  rolled_over_task_ids JSONB NOT NULL DEFAULT '[]'::jsonb,
  completed_habit_ids JSONB NOT NULL DEFAULT '[]'::jsonb,
  completed_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT NOW(),
  created_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT NOW(),
  CONSTRAINT evening_reviews_user_id_id_unique UNIQUE (user_id, id),
  CONSTRAINT evening_reviews_user_date_unique UNIQUE (user_id, date),
  CONSTRAINT evening_reviews_user_daily_plan_fk FOREIGN KEY (user_id, daily_plan_id)
    REFERENCES daily_plans(user_id, id) ON DELETE SET NULL,
  CONSTRAINT evening_reviews_date_format CHECK (date ~ '^\d{4}-\d{2}-\d{2}$'),
  CONSTRAINT evening_reviews_score_bounds CHECK (productivity_score >= 0 AND productivity_score <= 100)
);
```

### 3.3 Indexes & Composite Isolation
- `daily_plans(user_id, date)` unique index guarantees exactly one plan per calendar day per user.
- `evening_reviews(user_id, date)` unique index guarantees exactly one evening review per calendar day per user.
- Composite foreign key `evening_reviews(user_id, daily_plan_id) REFERENCES daily_plans(user_id, id)` eliminates cross-tenant foreign key leakage.

## 4. Zero-Duplication Rollover Specification

The rollover operation is the most critical architectural contract of Plan 02-05:

1. **Identity Preservation:**
   - Tasks are mutable execution entities. A task created in Phase 2 Plan 02-01 possesses a stable `id`.
   - When rolled over, the task's `scheduledDate` column is updated directly:
     - `carry_over`: `scheduledDate = tomorrowDate`
     - `reschedule`: `scheduledDate = chosenDate`
     - `backlog`: `scheduledDate = NULL`
   - Under no circumstances is a new task record inserted into `tasks`.
2. **Zero Duplicate Time Blocks:**
   - Rollover does not create automatic duplicate time blocks on the calendar. Incomplete time blocks from today remain intact as historical records of scheduled effort.
3. **Idempotency & Safe Retries:**
   - Repeated calls to `executeRollover` with the same parameters result in identical database state without throwing errors.
   - `rolledOverTaskIds` in `evening_reviews` is maintained as a deduplicated set.
4. **Tenant-Guarded Transactions:**
   - All mutations execute inside a database transaction (`db.transaction`).
   - Every updated task is verified with `and(eq(tasks.userId, safeUserId), eq(tasks.id, taskId))`. If a task does not belong to the user, the entire transaction aborts.

## 5. Pure Productivity Scoring Engine

Located in `src/server/daily-plan/productivity-score.ts`:
- Pure function with zero database or framework dependencies:
```ts
export function calculateProductivityScore(input: {
  plannedTasksCount: number;
  completedTasksCount: number;
  plannedHabitsCount: number;
  completedHabitsCount: number;
  plannedTimeBlocksCount: number;
  completedTimeBlocksCount: number;
  selfRating?: number | null; // 1-10
}): {
  score: number; // 0-100
  taskRate: number; // 0-100
  habitRate: number; // 0-100
  timeBlockRate: number; // 0-100
  breakdown: string;
}
```
- **Weights:**
  - Tasks: 50%
  - Habits: 30%
  - Time blocks: 20%
  - Dynamic re-weighting when specific categories are empty (e.g. no time blocks planned).
  - Self-rating blend option (when provided, 20% weight to self-rating, 80% to objective metrics).
