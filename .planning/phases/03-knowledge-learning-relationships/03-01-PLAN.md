# Plan 03-01: Markdown Note Editor with Wikilinks, Tags, and Backlink Graph Inspection

## 1. Plan Overview & Executive Context

- **Phase:** 3 — Knowledge, Learning & Relationships
- **Plan Identification:** 03-01
- **Domain:** Markdown Notes, Knowledge Graph Links, and Tag Taxonomy
- **Prerequisites:** Phase 2 Core Productivity completed and verified on `main` (commit `c7258b4`). PostgreSQL database with Drizzle ORM, Better Auth session authentication, server-side resource ownership authorization via authenticated `user_id`, composite tenant isolation, and audit logging are fully verified and operational.
- **Goal:** Deliver the foundation of the LifeOS personal knowledge system: rich Markdown note creation and editing, automatic parsing and resolution of bidirectional wikilinks (`[[Note Title]]`), tags, note types, and life areas organization, direct entity links to core productivity entities (Projects, Goals, Tasks), and reverse backlink graph inspection.
- **Requirements Satisfied:** `NOTE-01`, `NOTE-02`, `NOTE-03`, `NOTE-04` (Partial: Projects, Goals, and Tasks implemented; People and Learning Items deferred per vertical-slice rule).
- **Key Architectural Constraints:**
  1. **Vertical-Slice Rule**: Only introduce tables and schema necessary for notes and knowledge links (`notes`, `note_links`). People CRM (`people`, `interactions`), full-text search indexes across all entities, and learning items (`learning_items`) belong to subsequent plans in Phase 3 (03-02, 03-03, 03-04).
  2. **Composite Tenant Isolation**: Every note and note-link row is strictly partitioned by `user_id`. Direct foreign keys between notes and existing domain tables (`projects`, `goals`, `tasks`) enforce composite ownership `(user_id, project_id) REFERENCES projects(user_id, id)`.
  3. **Wikilink Parsing & Backlink Indexing**: Wikilinks written in markdown text (syntax: `[[Target Note Title]]` or `[[Target Note Title|Display Text]]`) are parsed transactionally on save. `note_links` records are maintained in the database so backlinks can be indexed, resolved, and queried in $O(1)$ time without expensive full-text table scans.

## 3. Database Architecture & Vertical-Slice Schema Evolution

### 3.1 New Table: `notes` (`src/server/db/schema/notes.ts`)
```typescript
export const notes = pgTable(
  "notes",
  {
    id: text("id")
      .primaryKey()
      .$defaultFn(() => crypto.randomUUID()),
    userId: text("user_id")
      .notNull()
      .references(() => user.id, { onDelete: "cascade" }),
    title: text("title").notNull(),
    slug: text("slug").notNull(),
    content: text("content").notNull().default(""),
    noteType: text("note_type", {
      enum: [
        "quick",
        "meeting",
        "research",
        "idea",
        "journal",
        "documentation",
        "reference",
        "learning",
      ],
    })
      .notNull()
      .default("quick"),
    area: text("area", {
      enum: [
        "health",
        "career",
        "finance",
        "personal_development",
        "relationships",
        "general",
      ],
    })
      .notNull()
      .default("general"),
    tags: jsonb("tags")
      .$type<string[]>()
      .notNull()
      .default(sql`'[]'::jsonb`),
    isPinned: boolean("is_pinned").notNull().default(false),
    isArchived: boolean("is_archived").notNull().default(false),
    // Entity links (composite foreign keys to existing tables)
    projectId: text("project_id"),
    goalId: text("goal_id"),
    taskId: text("task_id"),
    createdAt: timestamp("created_at", { withTimezone: true })
      .notNull()
      .defaultNow(),

      .defaultNow(),

  (table) => [

    unique("notes_user_id_slug_unique").on(table.userId, table.slug),
    foreignKey({
      name: "notes_user_project_fk",
      columns: [table.userId, table.projectId],
      foreignColumns: [projects.userId, projects.id],
    }).onDelete("set null"),
    foreignKey({
      name: "notes_user_goal_fk",
      columns: [table.userId, table.goalId],
      foreignColumns: [goals.userId, goals.id],
    }).onDelete("set null"),
    foreignKey({
      name: "notes_user_task_fk",
      columns: [table.userId, table.taskId],
      foreignColumns: [tasks.userId, tasks.id],
    }).onDelete("set null"),
    index("notes_user_id_idx").on(table.userId),
    index("notes_user_area_idx").on(table.userId, table.area),
    index("notes_user_note_type_idx").on(table.userId, table.noteType),
```

### 3.2 New Table: `note_links` (`src/server/db/schema/notes.ts`)
Tracks parsed wikilinks between notes for fast $O(1)$ backlink graph traversal and relationship inspection.
```typescript
export const noteLinks = pgTable(
  "note_links",
  {
    id: text("id")
      .primaryKey()
      .$defaultFn(() => crypto.randomUUID()),
    userId: text("user_id")
      .notNull()
      .references(() => user.id, { onDelete: "cascade" }),
    sourceNoteId: text("source_note_id").notNull(),
    targetNoteId: text("target_note_id"), // Nullable if the target note has not been created yet
    targetTitle: text("target_title").notNull(), // Exact target title parsed from [[Target Note Title]]
    displayText: text("display_text"), // Optional alias: [[Target Note Title|Display Text]]
    createdAt: timestamp("created_at", { withTimezone: true })
      .notNull()
      .defaultNow(),
  },
  (table) => [
    unique("note_links_unique").on(
      table.userId,
      table.sourceNoteId,
      table.targetTitle
    ),
    foreignKey({
      name: "note_links_source_note_fk",
      columns: [table.userId, table.sourceNoteId],
      foreignColumns: [notes.userId, notes.id],
    }).onDelete("cascade"),
    foreignKey({
      name: "note_links_target_note_fk",
      columns: [table.userId, table.targetNoteId],
      foreignColumns: [notes.userId, notes.id],
    }).onDelete("cascade"),
    index("note_links_source_idx").on(table.userId, table.sourceNoteId),
    index("note_links_target_idx").on(table.userId, table.targetNoteId),
    index("note_links_target_title_idx").on(table.userId, table.targetTitle),
  ]
);
```

## 4. Wikilink Engine Specification (`src/server/notes/wikilinks.ts`)

### 4.1 Syntax Rules
- Standard wikilink: `[[Note Title]]` -> `targetTitle = "Note Title"`, `displayText = "Note Title"`
- Aliased wikilink: `[[Note Title|Custom Display]]` -> `targetTitle = "Note Title"`, `displayText = "Custom Display"`
- Ignore inside fenced code blocks: ` ``` ` blocks and inline code ` ` ` blocks must NOT match wikilinks.
- Title normalization: trim whitespace, case-preserving target title with case-insensitive resolution matching.
- Slug generation: lowercase, replace non-alphanumeric with hyphens, trim trailing/leading hyphens (e.g., `Architecture Decisions` -> `architecture-decisions`).

### 4.2 Parsing & Sync Algorithm
When saving a note with `content`:
1. Strip code blocks from content prior to extraction.
2. Match all wikilinks: `/\[\[([^\]|]+)(?:\|([^\]]+))?\]\]/g`.
3. Deduplicate extracted links by normalized target title.
4. For each extracted link, check if a target note exists with that title or slug belonging to the same `userId`. If found, link `targetNoteId = targetNote.id`; otherwise `targetNoteId = null`.
5. Within an atomic database transaction:
   - Delete existing `note_links` for `(userId, sourceNoteId)`.
   - Batch insert the newly extracted `note_links`.
   - Additionally, check if any existing dangling `note_links` have `targetTitle` matching the newly saved note's title. If so, backfill `targetNoteId = newNote.id`.

## 5. Server Architecture & API Endpoints

### 5.1 Note Service (`src/server/notes/service.ts`)
- `createNote(userId, input)`: Validate Zod input, generate unique slug, insert into `notes`, extract & sync wikilinks, create audit log.
- `updateNote(userId, id, input)`: Verify ownership, update fields, re-extract & sync wikilinks, touch `updatedAt`, create audit log.
- `getNoteById(userId, id)`: Return NoteDTO with resolved outgoing links, incoming backlinks (`linkedMentions`), and unlinked mentions.
- `getNoteBySlug(userId, slug)`: Same as `getNoteById` but looking up by slug.
- `listNotes(userId, options)`: Filter by `area`, `noteType`, `tag`, `isArchived`, `projectId`, `goalId`, `taskId`, search query, sort by `updatedAt` / `title`.
- `deleteNote(userId, id)`: Archive or cascade delete note, clean up `note_links`, create audit log.
- `getBacklinks(userId, noteId)`: Query `note_links` where `targetNoteId = noteId` join with `notes` on `sourceNoteId` to get referring notes with contextual snippets.

### 5.2 API Routes
- `GET /api/notes`: List notes with optional filter query parameters (`area`, `noteType`, `tag`, `search`, `isArchived`).
- `POST /api/notes`: Create new note.
- `GET /api/notes/[id]`: Get single note with full backlink details.
- `PUT /api/notes/[id]`: Update note title, content, area, type, tags, and entity links.
- `DELETE /api/notes/[id]`: Delete or archive note.
- `GET /api/notes/[id]/backlinks`: Query incoming backlinks for the note.
