# Plan 03-02: Relationships / People CRM Module

## 1. Plan Overview & Executive Context

- **Phase:** 3 — Knowledge, Learning & Relationships
- **Plan Identification:** 03-02
- **Domain:** Relationships / People CRM (Contacts, Interactions, Follow-up Reminders, and Multi-Entity Linking)
- **Prerequisites:** Phase 2 Core Productivity and Phase 3 Plan 03-01 (Markdown Notes, Wikilinks, Tags & Backlinks Graph) verified and merged on `main` (baseline `3db2eb9a8e72c2632a4fa36c86bceb06e597961e`).
- **Goal:** Deliver a lightweight personal CRM within LifeOS: manage Person records with relationship types, contact information, notes, and tags; log and track Interaction history across channels; automatically track last interaction dates and surface upcoming/overdue follow-up reminders; link contacts to Tasks, Projects, and Notes without data duplication; and provide rich search, filtering, and grouping.
- **Requirements Satisfied:**
  - `CRM-01`: User can create, view, edit, and archive Person records with name, relationship type (`client`, `friend`, `family`, `colleague`, `prospect`, `mentor`, `professional`, `other`), company, role, contact information, and tags.
  - `CRM-02`: User can log Interactions with a Person (date, channel/type, summary notes, next follow-up date).
  - `CRM-03`: System automatically tracks and displays `lastInteraction` date and surfaces upcoming or overdue `nextFollowUp` reminders.
  - `CRM-04`: User can link a Person to Tasks, Projects, and Notes without data duplication.
  - `CRM-05`: User can filter, search, and group people by relationship type, company, tags, and follow-up status.
  - `NOTE-04` (Remaining partial item): Link notes directly to People (`personId` on `notes`).
- **Key Architectural Constraints:**
  1. **Vertical-Slice Rule**: Only introduce schemas and migrations for Relationships CRM (`people`, `interactions`) and entity foreign keys (`tasks.person_id`, `projects.person_id`, `notes.person_id`). Global search indexes across all entities and Learning Items belong to subsequent plans (03-03, 03-04).
  2. **Composite Tenant Isolation**: Every Person and Interaction record enforces `user_id` partitioning. Foreign keys between `interactions` and `people`, as well as `tasks`, `projects`, and `notes` to `people`, use composite ownership `(user_id, person_id) REFERENCES people(user_id, id)`.
  3. **Zero Data Duplication**: Contacts are referenced by ID across tasks, projects, and notes. Interaction logs maintain history without duplicating contact profiles.
  4. **Test Discipline**: All tests reside strictly in `scripts/tests/phase-03/plan-02/`. Zero test files in `src/`.

## 3. Database Architecture & Vertical-Slice Schema Evolution

### 3.1 New Table: `people` (`src/server/db/schema/people.ts`)
```typescript
export const people = pgTable(
  "people",
  {
    id: text("id")
      .primaryKey()
      .$defaultFn(() => crypto.randomUUID()),
    userId: text("user_id")
      .notNull()
      .references(() => user.id, { onDelete: "cascade" }),
    name: text("name").notNull(),
    relationshipType: text("relationship_type", {
      enum: [
        "client",
        "friend",
        "family",
        "colleague",
        "prospect",
        "mentor",
        "professional",
        "other",
      ],
    })
      .notNull()
      .default("colleague"),
    company: text("company"),
    role: text("role"),
    email: text("email"),
    phone: text("phone"),
    contactInfo: jsonb("contact_info")
      .$type<Record<string, any>>()
      .notNull()
      .default(sql`'{}'::jsonb`),
    tags: jsonb("tags")
      .$type<string[]>()
      .notNull()
      .default(sql`'[]'::jsonb`),
    notes: text("notes"),
    isArchived: boolean("is_archived").notNull().default(false),
    lastInteractionDate: timestamp("last_interaction_date", { withTimezone: true }),
    nextFollowUpDate: timestamp("next_follow_up_date", { withTimezone: true }),
    createdAt: timestamp("created_at", { withTimezone: true })
      .notNull()
      .defaultNow(),
    updatedAt: timestamp("updated_at", { withTimezone: true })
      .notNull()
      .defaultNow(),
  },
  (table) => [
    unique("people_user_id_id_unique").on(table.userId, table.id),
    check("people_name_non_empty", sql`length(trim(${table.name})) > 0`),
    check("people_name_max_length", sql`length(${table.name}) <= 255`),
    check(
      "people_relationship_type_check",
      sql`${table.relationshipType} IN ('client', 'friend', 'family', 'colleague', 'prospect', 'mentor', 'professional', 'other')`
    ),
    index("people_user_id_idx").on(table.userId),
    index("people_user_relationship_type_idx").on(table.userId, table.relationshipType),
    index("people_user_is_archived_idx").on(table.userId, table.isArchived),
    index("people_user_company_idx").on(table.userId, table.company),
    index("people_user_next_follow_up_idx").on(table.userId, table.nextFollowUpDate),
    index("people_user_last_interaction_idx").on(table.userId, table.lastInteractionDate),
  ]
);
```

### 3.2 New Table: `interactions` (`src/server/db/schema/people.ts`)
```typescript
export const interactions = pgTable(
  "interactions",
  {
    id: text("id")
      .primaryKey()
      .$defaultFn(() => crypto.randomUUID()),
    userId: text("user_id")
      .notNull()
      .references(() => user.id, { onDelete: "cascade" }),
    personId: text("person_id").notNull(),
    date: timestamp("date", { withTimezone: true }).notNull().defaultNow(),
    channel: text("channel", {
      enum: ["meeting", "call", "email", "message", "in_person", "other"],
    })
      .notNull()
      .default("call"),
    summary: text("summary").notNull(),
    nextFollowUpDate: timestamp("next_follow_up_date", { withTimezone: true }),
    createdAt: timestamp("created_at", { withTimezone: true })
      .notNull()
      .defaultNow(),
    updatedAt: timestamp("updated_at", { withTimezone: true })
      .notNull()
      .defaultNow(),
  },
  (table) => [
    unique("interactions_user_id_id_unique").on(table.userId, table.id),
    foreignKey({
      name: "interactions_user_person_fk",
      columns: [table.userId, table.personId],
      foreignColumns: [people.userId, people.id],
    }).onDelete("cascade"),
    check("interactions_summary_non_empty", sql`length(trim(${table.summary})) > 0`),
    check(
      "interactions_channel_check",
      sql`${table.channel} IN ('meeting', 'call', 'email', 'message', 'in_person', 'other')`
    ),
    index("interactions_user_person_idx").on(table.userId, table.personId),
    index("interactions_user_date_idx").on(table.userId, table.date),
  ]
);
```

### 3.3 Foreign Key Invariants for Tasks, Projects, and Notes
1. `tasks`: Composite FK `tasks(user_id, person_id) REFERENCES people(user_id, id) ON DELETE SET NULL`.
2. `projects`: Column `person_id text` added; Composite FK `projects(user_id, person_id) REFERENCES people(user_id, id) ON DELETE SET NULL`.
3. `notes`: Column `person_id text` added; Composite FK `notes(user_id, person_id) REFERENCES people(user_id, id) ON DELETE SET NULL`.

### 3.4 Migration: `0013_people_crm_and_relationships.sql`

- Create `interactions` table with composite FK to `people`.
- Add `person_id` column to `projects` and `notes`.

## 4. Server Architecture & API Endpoints

### 4.1 People Service (`src/server/people/service.ts`)
- `createPerson(userId, input)`: Validate with Zod, insert person, create audit log.
- `updatePerson(userId, id, input)`: Verify ownership, update fields, touch `updatedAt`, create audit log.
- `getPersonById(userId, id)`: Return PersonDetailDTO with interactions list, linked tasks, linked projects, linked notes, and computed `followUpStatus`.
- `listPeople(userId, query)`: Filter by `relationshipType`, `company`, `tag`, `followUpStatus`, `isArchived`, `search`, sort by selected field.
- `archivePerson(userId, id)` / `restorePerson(userId, id)`: Soft-archive toggling with audit log.
- `deletePerson(userId, id)`: Cascade delete interactions, nullify links in tasks/projects/notes, record audit log.
- `logInteraction(userId, personId, input)`: Validate input, create interaction, sync person `lastInteractionDate` and `nextFollowUpDate`, create audit log.
- `updateInteraction(userId, id, input)`: Verify ownership, update interaction, sync person dates, create audit log.
- `deleteInteraction(userId, id)`: Verify ownership, delete interaction, sync person dates, create audit log.
- `getFollowUpReminders(userId)`: Return overdue, today, and upcoming reminders categorized with counts.

### 4.2 API Routes
- `GET /api/people`: List contacts with query filters and search.
- `POST /api/people`: Create new contact.
- `GET /api/people/[id]`: Get contact details with interactions and linked entities.
- `PUT /api/people/[id]`: Update contact details.
- `DELETE /api/people/[id]`: Delete or archive contact.
- `GET /api/people/[id]/interactions`: List interaction history for a contact.
- `POST /api/people/[id]/interactions`: Log an interaction with a contact.
- `PUT /api/people/[id]/interactions/[interactionId]`: Update an interaction.
- `DELETE /api/people/[id]/interactions/[interactionId]`: Delete an interaction.
- `GET /api/people/reminders`: Query overdue, today, and upcoming follow-ups.

## 6. Automated Test Suites & Verification Plan
