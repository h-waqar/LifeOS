# Plan 03-04: Learning System (Books, Courses, Articles & Skill Notes)

## 1. Plan Overview & Executive Context

- **Phase:** 3 — Knowledge, Learning & Relationships
- **Plan Identification:** 03-04
- **Domain:** Learning System (Learning Items, Resource Tracking, Progress, Ratings, Key Takeaways, and Linked Notes)
- **Prerequisites:** Phase 3 Plan 03-01 (Markdown Notes), Plan 03-02 (Relationships / People CRM), and Plan 03-03 (PostgreSQL Full-Text Search & Command Palette) verified and merged on `main`.
- **Goal:** Deliver a personal learning tracker within LifeOS to track books, courses, articles, podcasts, and skill documentation with progress tracking, rating, key takeaways, and direct bidirectional linkage to Markdown Notes, Goals, and Projects.
- **Requirements Satisfied:**
  - `NOTE-06`: User can track Learning Items (books, courses, articles) with status, ratings, key takeaways, and linked notes.
  - `NOTE-04` (Completion): User can link notes directly to Projects, Goals, Tasks, People, and Learning Items (`learning_id` foreign key on `notes`).
- **Key Architectural Constraints:**
  1. **Vertical-Slice Database Scope Rule**: Introduce strictly the `learning_items` table schema, indexes, and the foreign key `notes.learning_id`.
  2. **Composite Multi-Tenant Isolation**: Every `learning_items` record enforces `user_id` partitioning. Foreign keys between `learning_items` and existing entities (`goals`, `projects`) enforce composite ownership `(user_id, entity_id) REFERENCES entity(user_id, id)`.
  3. **Zero Data Duplication**: Knowledge notes link to learning items via `notes.learning_id`. Summaries and key takeaways are stored structured on the learning item while in-depth long-form notes live in `notes`.
  4. **Strict Session Verification & Authorization**: All mutations and reads verify the authenticated session and enforce `userId = session.user.id`.
  5. **Test Organization**: All test files MUST reside in `scripts/tests/phase-03/plan-04/`. No test files inside `src/`.

## 3. Database Architecture & Vertical-Slice Schema Evolution

### 3.1 Migration `0015_learning_items.sql`

```sql
-- 1. Create learning_items table
CREATE TABLE IF NOT EXISTS learning_items (
  id text PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id text NOT NULL REFERENCES "user"(id) ON DELETE CASCADE,
  title text NOT NULL,
  type text NOT NULL DEFAULT 'book',
  status text NOT NULL DEFAULT 'not_started',
  author text,
  url text,
  rating integer,
  progress integer NOT NULL DEFAULT 0,
  current_units integer DEFAULT 0,
  total_units integer,
  unit_type text,
  summary text,
  key_takeaways jsonb NOT NULL DEFAULT '[]'::jsonb,
  tags jsonb NOT NULL DEFAULT '[]'::jsonb,
  goal_id text,
  project_id text,
  is_archived boolean NOT NULL DEFAULT false,
  completed_at timestamp with time zone,
  created_at timestamp with time zone NOT NULL DEFAULT now(),
  updated_at timestamp with time zone NOT NULL DEFAULT now(),
  CONSTRAINT learning_items_user_id_id_unique UNIQUE (user_id, id),
  CONSTRAINT learning_items_title_non_empty CHECK (length(trim(title)) > 0),
  CONSTRAINT learning_items_title_max_length CHECK (length(title) <= 255),
  CONSTRAINT learning_items_type_check CHECK (type IN ('book', 'course', 'article', 'podcast', 'skill', 'documentation', 'other')),
  CONSTRAINT learning_items_status_check CHECK (status IN ('not_started', 'in_progress', 'completed', 'archived')),
  CONSTRAINT learning_items_rating_check CHECK (rating IS NULL OR (rating >= 1 AND rating <= 5)),
  CONSTRAINT learning_items_progress_check CHECK (progress >= 0 AND progress <= 100),
  CONSTRAINT learning_items_current_units_check CHECK (current_units IS NULL OR current_units >= 0),
  CONSTRAINT learning_items_total_units_check CHECK (total_units IS NULL OR total_units >= 0),
  CONSTRAINT learning_items_user_goal_fk FOREIGN KEY (user_id, goal_id) REFERENCES goals(user_id, id) ON DELETE SET NULL,
  CONSTRAINT learning_items_user_project_fk FOREIGN KEY (user_id, project_id) REFERENCES projects(user_id, id) ON DELETE SET NULL
);

-- 2. Indexes for efficient lookup and tenant filtering
CREATE INDEX IF NOT EXISTS learning_items_user_id_idx ON learning_items(user_id);
CREATE INDEX IF NOT EXISTS learning_items_user_status_idx ON learning_items(user_id, status);
CREATE INDEX IF NOT EXISTS learning_items_user_type_idx ON learning_items(user_id, type);
CREATE INDEX IF NOT EXISTS learning_items_user_is_archived_idx ON learning_items(user_id, is_archived);
CREATE INDEX IF NOT EXISTS learning_items_user_goal_idx ON learning_items(user_id, goal_id);
CREATE INDEX IF NOT EXISTS learning_items_user_project_idx ON learning_items(user_id, project_id);

-- 3. Trigram & FTS indexes for global search
CREATE INDEX IF NOT EXISTS learning_items_title_trgm_idx ON learning_items USING gin (title gin_trgm_ops);
CREATE INDEX IF NOT EXISTS learning_items_fts_idx ON learning_items USING gin (to_tsvector('english', coalesce(title, '') || ' ' || coalesce(author, '') || ' ' || coalesce(summary, '')));

-- 4. Add learning_id to notes
ALTER TABLE notes ADD COLUMN IF NOT EXISTS learning_id text;

-- 5. Foreign key from notes to learning_items
DO $$ BEGIN
  IF NOT EXISTS (
    SELECT 1 FROM pg_constraint WHERE conname = 'notes_user_learning_fk'
  ) THEN
    ALTER TABLE notes
      ADD CONSTRAINT notes_user_learning_fk
      FOREIGN KEY (user_id, learning_id)
      REFERENCES learning_items(user_id, id)
      ON DELETE SET NULL;
  END IF;
END $$;

CREATE INDEX IF NOT EXISTS notes_user_learning_idx ON notes(user_id, learning_id);
```

## 4. Application Layer Architecture

### 4.1 Schema Definition (`src/server/db/schema/learning.ts`)
- TypeScript Drizzle definitions with strict types, constraints, and composite unique keys.
- Re-export from `src/server/db/schema/index.ts`.
- Update `src/server/db/schema/notes.ts` with `learningId` and composite FK.

### 4.2 Validation Schemas (`src/server/learning/validation.ts`)
- `createLearningItemSchema`: Zod validation for creating items.
- `updateLearningItemSchema`: Zod validation for updating items.
- `listLearningItemsSchema`: Zod validation for query filtering (type, status, goalId, projectId, tag, search, limit, offset).

### 4.3 Service Layer (`src/server/learning/service.ts`)
- `listLearningItems(userId, query)`
- `getLearningItemById(userId, id)`
- `createLearningItem(userId, data)`
- `updateLearningItem(userId, id, data)` (handles automated status completion when progress=100% or manual status changes)
- `deleteLearningItem(userId, id, { hard?: boolean })` (defaults to soft-archive `isArchived = true`, permanent delete on hard=true)
- `getLearningItemNotes(userId, learningItemId)`: fetches all notes linked to this learning item.

### 4.4 API Endpoints (`src/app/api/learning/...`)
- `GET /api/learning`: List items with filters.
- `POST /api/learning`: Create item.
- `GET /api/learning/[id]`: Get single item with linked notes and relations.
- `PATCH /api/learning/[id]`: Update item.
- `DELETE /api/learning/[id]`: Delete / archive item.

### 4.5 Search & Navigation Integration
- Add `searchLearningItems` to `src/server/search/service.ts` and `learning` entity type to `SearchEntityType`.
- Update `src/components/app-shell.tsx` with `/learning` nav item.
- Update `src/components/command-palette.tsx` with learning item deep linking (`/learning?id=`).

### 4.6 UI Layer (`src/app/learning/page.tsx`)
- Statistics cards: Active Courses/Books, Items In Progress, Completed, Total Hours/Items.
- Filter toolbar: Search, Type filter (`All`, `Book`, `Course`, `Article`, `Podcast`, `Skill`, `Other`), Status tabs (`All`, `In Progress`, `Not Started`, `Completed`).
- Card/Grid view: Progress bar, rating stars, type badge, author, tags, linked goal/project chip.
- Create/Edit modal with form validation.
- Detail inspector drawer showing summary, key takeaways, linked notes list, and "Create Linked Note" button.
