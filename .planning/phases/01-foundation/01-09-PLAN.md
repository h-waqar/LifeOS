# Plan: LifeOS Frontend Architecture, Core Workflows & Plan 01-09 Verification

## Context & Objectives
LifeOS currently has a verified backend domain model, PostgreSQL schema, migrations, Better Auth implementation, and hardened API routes (`/api/auth/*`, `/api/preferences`, `/api/projects`, `/api/tasks`). However, the frontend application UI is missing, causing browser-level user journeys in Plan 01-09 to fail.

Our mission is to implement a responsive frontend application shell, complete authentication UI, core workflows for projects and hierarchical tasks, operational healthcheck, and executable verification evidence for all 16 user journeys against a real production build and PostgreSQL database.

---

## 1. Existing Architecture & Boundaries
* **Framework:** Next.js 15 App Router, React 19, TypeScript strict mode (`noImplicitAny: true`, `strictNullChecks: true`).
* **Styling & Design Tokens:** Tailwind CSS with shadcn-compatible CSS custom properties in `src/app/globals.css` (`--background`, `--foreground`, `--primary`, `--muted`, `--border`, etc.) and `.dark` class strategy.
* **Authentication:** Better Auth with client instance `authClient` in `src/lib/auth-client.ts` (`signIn.email`, `signUp.email`, `signOut`, `useSession`).
* **Server Isolation Rule:** Server modules (`src/server/*`, `src/lib/env.ts`) throw immediate runtime errors if imported into browser client bundles. All client code must only use `@/lib/auth-client`, browser APIs, and typed HTTP API requests against `/api/*`.
* **Database Scope & Strict Invariants:**
  * Projects: name (1-255 chars), description (max 2000 chars), status (`planning` | `active` | `paused` | `completed` | `archived`), priority (`low` | `medium` | `high` | `critical`).
  * Tasks: title (1-255 chars), description (max 4000 chars), status (`inbox` | `todo` | `in_progress` | `blocked` | `completed` | `cancelled`), priority (`low` | `medium` | `high` | `critical`), `projectId`, `parentTaskId`, `dueDate`, `completedAt` (auto-set on `completed`, cleared on reopen). Cascade deletion of subtasks when parent task is deleted; nullification of `projectId` when project is deleted.
  * Payloads are strictly validated with `.strict()`; extra keys cause 400 Bad Request.

## 2. Component & UI Architecture

### 2.1 Shared Types (`src/types/index.ts`)
* Client-safe TypeScript DTOs matching backend JSON responses without importing server files:
  * `ProjectDTO`, `TaskDTO`, `UserPreferences`
  * `TaskStatus`, `ProjectStatus`, `Priority`

### 2.2 Application Shell & Layout (`src/app/layout.tsx`, `src/components/...`)
* **Theme Management (`src/components/theme-provider.tsx`):**
  * Synchronizes theme state (`dark` | `light` | `system`).
  * Toggles `.dark` on `document.documentElement`.
  * Fetches user preference from `GET /api/preferences` on load; persists changes via `PATCH /api/preferences`.
* **Global Feedback:** `sonner` `<Toaster position="bottom-right" richColors />` for non-leaking, clear toast feedback.
* **Navigation Shell (`src/components/app-shell.tsx`):**
  * Responsive sidebar (collapsible on desktop, drawer on mobile).
  * Brand header with LifeOS logo and version.
  * Nav items with active route indicator:
    * Dashboard (`/dashboard`)
    * Projects (`/projects`)
    * Tasks (`/tasks`)
  * User profile footer displaying user email, theme toggle button, and Sign Out button.
* **Global Command Palette (`src/components/command-palette.tsx`):**
  * Powered by `cmdk` with keyboard shortcut listener (`Ctrl+K` / `Cmd+K`).
  * Fast navigation: Dashboard, Projects, Tasks.
  * Quick actions: "Create Task", "Create Project", "Toggle Dark/Light Mode", "Sign Out".

### 2.3 Authentication Views (`/login`, `/register`)
* **`src/app/login/page.tsx`:**
  * Clean card with email & password inputs, validation feedback, and submit button with loading spinner.
  * Submits via `authClient.signIn.email({ email, password })`.
  * Handles errors gracefully (e.g. 401 invalid credentials) and redirects to `/dashboard` upon success.
  * Link to `/register`.
* **`src/app/register/page.tsx`:**
  * Name, email, password inputs.
  * Submits via `authClient.signUp.email({ name, email, password })`.
  * Displays single-user registration rejection if another user is already registered (403 Forbidden with message: "Registration is closed. LifeOS is configured for single-user mode.").
  * Redirects to `/dashboard` on successful registration.

### 2.4 Core Workflows
* **Root Page (`src/app/page.tsx`):**
  * Directs authenticated visitors to `/dashboard` and unauthenticated visitors to `/login`.
* **Dashboard (`src/app/dashboard/page.tsx`):**
  * KPI summary cards: Active Projects, Pending Tasks, Completed Tasks, Critical/High Priority Tasks.
  * Quick actions: "Add Task", "Add Project".
  * Urgent & recent tasks feed with direct checkbox completion toggle.
* **Projects View (`src/app/projects/page.tsx`):**
  * Grid/list of projects with status filter pill tabs (`all`, `active`, `planning`, `paused`, `completed`, `archived`).
  * Project cards displaying status badge, priority, description, task counts, and action menu.
  * Modal dialogs: Create Project, Edit Project, and Delete Project (with warning that tasks will become unassigned).
* **Tasks View (`src/app/tasks/page.tsx`):**
  * Tree view displaying hierarchical task structure (root tasks with nested subtasks indented with connector lines).
  * Status filter pills (`all`, `inbox`, `todo`, `in_progress`, `completed`, `blocked`, `cancelled`).
  * Checkbox toggle for instant completion (`status: "completed"`) / reopening (`status: "todo"` / `"in_progress"`).
  * "Create Task" modal supporting root task creation or nested subtask creation under any parent task.
  * "Edit Task" modal to modify title, description, status, priority, due date.
  * "Delete Task" modal with clear cascade deletion confirmation warning.

## 3. Operational Healthcheck (`src/app/api/health/route.ts`)
* Unauthenticated GET endpoint.
* Calls `checkDatabaseHealth()` from `@/server/db`.
* On healthy connection: HTTP 200 `{ status: "healthy", database: "connected", latencyMs: number }`.
* On database failure/unavailability: HTTP 503 `{ status: "unhealthy", database: "disconnected", error: string }`.
* Never exposes connection strings, passwords, or hostnames.
* Covered by integration test `scripts/tests/phase-01/plan-09/health.integration.test.ts`.
