**Phase:** Phase 6: AI Layer & Assistant  
**Plan:** 06-03  
**Status:** Planned  
**Dependencies:** Plan 06-02 (Context Engine & DB Schema)

## 1. Objective

Ground AI assistant responses in the user's personal information graph using a high-precision, PostgreSQL-native hybrid retrieval engine (`tsvector` + `pg_trgm`) augmented with 1-to-2 hop relational graph expansion. Enable the assistant to cite exact LifeOS sources and answer cross-domain questions without hallucinations.

## 4. Detailed Implementation Specification

### 4.1 Query Intent Routing (`src/server/ai/rag/intent-router.ts`)
Analyzes incoming user prompt:
- Direct Entity Mentions (e.g. "my goal for marathon", "the note on Next.js 15"): Directs query to specific entity type.
- Broad Inquiries (e.g. "what should I focus on?", "what did I do with Sarah?"): Fan-out search across multiple domains (people, interactions, tasks).
- Filters out non-retrieval conversational queries (e.g. "hello", "thank you", "explain quantum computing") to avoid unnecessary database overhead.

### 4.2 Relational Graph Expansion (`src/server/ai/rag/graph-expander.ts`)
When primary search returns candidate entities, the graph expander attaches 1-hop related records:
- **Task matched:** Attach parent Project name, milestone title, and linked Goal.
- **Goal matched:** Attach list of active child Projects and current metric progress.
- **Person matched:** Attach last 3 logged Interactions and any pending follow-up tasks.
- **Note matched:** Attach linked Learning Item and explicit `note_links` backlinks.

### 4.3 Ranking, Source Attribution & Formatting (`src/server/ai/rag/ranking.ts`)
- Computes composite relevance score: `score = search_score * recency_multiplier * relation_boost`.
- Enforces strict token budget (default: 2,500 tokens). Lowest-scoring entities are pruned.
- Generates structured Markdown citation references: `[Note: Q3 Strategy](/notes?id=uuid)`.
- Delimits context inside XML tags with `untrusted="true"` to prevent indirect prompt injection.

## 5. Testing Strategy

All tests strictly placed in `scripts/tests/phase-06/plan-03/`.

### Unit Tests (`scripts/tests/phase-06/plan-03/rag-engine.test.ts`):
- Intent router correctly detects entity domains and extracts clean search keywords.
- Graph expander successfully connects tasks to parent projects and goals.
- Relevance ranking prioritizes exact title matches and recent records.
- Token budget pruner discards lower-ranked context items when size limit is exceeded.
- Produces valid citation metadata mapping entity IDs to deep links.

### Integration Tests (`scripts/tests/phase-06/plan-03/rag-retrieval.integration.test.ts`):
- Executes live cross-domain queries against PostgreSQL (`tasks`, `notes`, `goals`, `people`).
- Verifies strict multi-tenant isolation: User A cannot retrieve User B's notes or goals even with identical search terms.
- Relational expansion respects user boundary: cannot expand to linked entities belonging to another user.
- Handles empty search results gracefully with empty context block.

---

## 6. Acceptance Criteria

1. RAG engine retrieves relevant personal data across notes, tasks, goals, projects, and people.
2. Relational graph traversal attaches meaningful linked context (e.g. task project name).
3. Retrieved items include accurate citation URLs (`/notes?id=...`, `/tasks?id=...`).
4. Strict multi-tenant isolation prevents any cross-user context leakage.
5. All tests in `scripts/tests/phase-06/plan-03/` pass with zero regressions.
