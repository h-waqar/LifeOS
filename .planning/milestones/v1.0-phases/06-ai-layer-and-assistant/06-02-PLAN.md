## 4. Detailed Implementation Specification

### 4.1 Database Schema (`src/server/db/schema/ai.ts`)
- `aiConversations`: `id`, `userId`, `title`, `provider`, `model`, `systemPromptOverride`, `metadata`, `createdAt`, `updatedAt`.
- `aiMessages`: `id`, `conversationId`, `userId`, `role` (`system` | `user` | `assistant` | `tool`), `content`, `toolCalls`, `toolResults`, `tokenCount`, `metadata`, `createdAt`.
- `aiActions`: `id`, `conversationId`, `messageId`, `userId`, `toolName`, `riskLevel`, `status`, `parameters`, `previewData`, `expiresAt`, `executedAt`, `auditLogId`, `errorMessage`, `createdAt`.
- `userAISettings`: `id`, `userId` (unique), `defaultProvider`, `defaultModel`, `encryptedGeminiKey`, `encryptedAnthropicKey`, `encryptedOpenAIKey`, `ollamaBaseUrl`, `temperature`, `createdAt`, `updatedAt`.

### 4.2 Context Assembly Engine (`src/server/ai/context/engine.ts`)
Assembles the complete LLM prompt context deterministically:
1. **System Persona:** Base instructions establishing LifeOS identity, safety bounds, and tool use rules.
2. **Temporal Anchor:** Current UTC and user local timestamp, day of week, time of day.
3. **Operational Snapshot (`state-snapshot.ts`):**
   - Active daily plan status from `src/server/daily-plan/service.ts`.
   - Top 3 overdue/critical tasks from `src/server/tasks/service.ts`.
   - Today's scheduled timeblocks from `src/server/calendar/service.ts`.
4. **Conversation Sliding Window:**
   - Retrieves recent messages up to token budget limit (default: 2,000 tokens).
   - Preserves message integrity and tool call / result pairs.
5. **Anti-Injection Sanitization (`sanitizer.ts`):**
   - External and user content enclosed in `<user_context untrusted="true">` tags.
   - Explicit system boundary stating untrusted context must never be parsed as instructions.

## 5. Testing Strategy

All tests strictly placed in `scripts/tests/phase-06/plan-02/`.

### Unit Tests (`scripts/tests/phase-06/plan-02/context-engine.test.ts`):
- Assembles system prompt with correct temporal anchor (date, day of week).
- Ingests operational state snapshot without exceeding token budget.
- Truncates/slides message history deterministically when token budget is reached.
- Wraps untrusted user content in structured XML tags and neutralizes nested injection attempts.

### Integration Tests (`scripts/tests/phase-06/plan-02/conversation-persistence.integration.test.ts`):
- Creates and persists conversations and messages in PostgreSQL.
- Verifies cascade deletion: deleting a conversation cascades to all messages and pending actions.
- Multi-tenant isolation: User A cannot read, update, or delete User B's conversations or messages.
- Schema integrity: enforces valid roles (`user`, `assistant`, `system`, `tool`) and status values.

## 6. Acceptance Criteria

1. Migration `0021_ai_layer_and_assistant.sql` applies cleanly with all foreign keys, cascades, and indexes.
2. Conversation CRUD endpoints operate with strict user isolation.
3. Context engine builds balanced prompts combining temporal anchor, active state, and history.
4. Token budget caps prevent prompt overflow.
5. All tests in `scripts/tests/phase-06/plan-02/` pass with zero regressions.
