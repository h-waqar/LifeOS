## 1. Objective

Build a typed, secure Tool Registry exposing bounded domain operations to the AI model. Ensure tools never execute raw SQL, strictly wrap existing domain services, enforce session-derived `user_id` ownership, validate all parameters using Zod, and assign explicit risk tiers (`tier1_readonly`, `tier2_low`, `tier3_consequential`, `tier4_destructive`).

## 4. Detailed Implementation Specification

### 4.1 Tool Security Boundary
1. **No Client-Supplied `userId`:** The `userId` is supplied directly by `ToolContext` (from the verified Better Auth session). Tool parameter schemas strictly forbid any `userId` parameter.
2. **Strict Zod Input Validation:** Every tool parameter is validated against a tight Zod schema (e.g. enum constraints, string lengths, UUID formats).
3. **Domain Service Dispatch:** Every tool delegates directly to canonical domain services (`createTask`, `updateTask`, `logHabitEntry`, etc.), ensuring all existing domain invariants, cascade triggers, and goal progress recalculations fire identically.

## 5. Testing Strategy

All tests strictly placed in `scripts/tests/phase-06/plan-04/`.

### Unit Tests (`scripts/tests/phase-06/plan-04/tool-registry.test.ts`):
- All tools validate parameters against Zod schemas and reject invalid inputs.
- Read-only tools are correctly marked `tier1_readonly`.
- Mutating tools (tasks, transactions, calendar) are assigned `tier3_consequential` or `tier4_destructive`.
- Action preview generators produce human-readable summaries and parameter diffs.

### Integration Tests (`scripts/tests/phase-06/plan-04/tool-execution.integration.test.ts`):
- Executing `tasks_create` through tool registry successfully calls `createTask` and persists task in database.
- Multi-tenant isolation: Tool execution cannot access or mutate resources belonging to another user.
- Financial tool execution invokes goal sync and account balance updates according to Phase 4 rules.
- Completing a task through `tasks_complete` automatically triggers goal progress recalculation.

## 6. Acceptance Criteria

1. Tool registry exposes all 17 initial domain tools with valid Zod schemas and descriptions.
2. Tools route execution through canonical domain services; no raw SQL or backdoor updates.
3. User ownership is enforced from session context, with zero client-controlled user IDs.
4. All tests in `scripts/tests/phase-06/plan-04/` pass with zero regressions.
