# Plan 06-01: Multi-Provider AI Abstraction Layer & Core Client Infrastructure

**Phase:** Phase 6: AI Layer & Assistant  
**Plan:** 06-01  
**Status:** Planned  
**Dependencies:** Phase 1 Foundation (Auth, Crypto, Env)  
**Requirements Covered:** AI-01, SEC-01  

---

## 1. Objective

Deliver a provider-agnostic, enterprise-grade AI client abstraction layer supporting Google Gemini, Anthropic Claude, OpenAI, and local Ollama models. Enable runtime model switching, encrypted per-user API credentials with environment variable fallbacks, token usage accounting, and graceful error handling.

- `src/lib/env.ts`: Environment validation for system default API keys.

## 4. Detailed Implementation Specification

### 4.1 Provider Registry & Model Resolution (`src/server/ai/providers/registry.ts`)
1. Define supported providers:
   - `google`: `gemini-2.5-flash` (default fast), `gemini-2.5-pro` (complex reasoning)
   - `anthropic`: `claude-3-7-sonnet` (deep reasoning), `claude-3-5-haiku` (fast)
   - `openai`: `gpt-4o` (general), `gpt-4o-mini` (fast)
   - `ollama`: `llama3.3`, `qwen2.5`, `mistral` (local offline)
2. Resolution precedence:
   - User encrypted key stored in `user_ai_settings` (decrypted in memory only)
   - System environment variable (`GEMINI_API_KEY`, etc.)
   - If neither exists, throw `ProviderConfigurationError` with user-friendly remediation prompt.
3. Health check utility:
   - `verifyProviderConnection(provider, model, apiKey)`: Sends a lightweight prompt (`ping`) to verify credentials before saving.

### 4.2 Security & Credential Storage (`src/server/ai/settings-service.ts`)
- Sensitive API keys are encrypted at rest using `encryptSecret(plaintext)` before writing to the database.
- Read operations never return plaintext keys to the browser; only a masked string (e.g. `sk-...4a9f`) and `isConfigured: true`.

## 5. Testing Strategy

All tests strictly placed in `scripts/tests/phase-06/plan-01/`.

### Unit Tests (`scripts/tests/phase-06/plan-01/provider-registry.test.ts`):
- Resolves Gemini, Anthropic, OpenAI, and Ollama model instances with correct configurations.
- Throws typed `ProviderConfigurationError` when credentials are completely missing.
- Falls back correctly from missing user key to system environment variable.
- Encrypts and masks user-supplied API keys without exposing secrets in return objects.
- Correctly calculates token costs across different model pricing tiers.

### Integration Tests (`scripts/tests/phase-06/plan-01/ai-settings.integration.test.ts`):
- Authenticated user can save encrypted provider credentials to database.
- Multi-tenant isolation: User A cannot read or use User B's encrypted API keys.
- Endpoint `/api/ai/models` returns correct list of supported models and active provider state.
- Unauthenticated requests to `/api/ai/settings` fail closed with 401.

---

## 6. Acceptance Criteria

1. Model registry seamlessly instantiates language models for Gemini, Claude, OpenAI, and Ollama.
2. API keys are encrypted at rest via AES-256-GCM and never leaked in client API responses.
3. System gracefully falls back to environment variables when user keys are unset.
4. Token usage calculator deterministically scores prompt and completion token costs.
5. All tests in `scripts/tests/phase-06/plan-01/` pass with zero regressions.
