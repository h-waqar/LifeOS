# Plan 01-02: PostgreSQL + Drizzle Foundation

## 1. Plan Objective

Establish a production-grade, type-safe PostgreSQL data layer using Drizzle ORM and Drizzle Kit. Strictly enforce the project's vertical-slice architecture by limiting the database schema exclusively to foundational infrastructure: Better Auth prerequisite tables (`user`, `session`, `account`, `verification`, `passkey`), `user_preferences`, and `audit_log`. Implement connection pooling with Next.js development hot-reload protection, server-only runtime isolation, automated migration generation and execution, database health verification with graceful offline handling, and a dedicated test suite located strictly in `scripts/tests/phase-01/plan-02/`.

---

## 2. Exact Scope and Non-Goals

### In Scope
- **Drizzle Kit Configuration**: `drizzle.config.ts` configured for PostgreSQL, referencing `DATABASE_URL` and schema definitions.
- **Database Client & Connection Pool**: `src/server/db/index.ts` exporting a singleton Drizzle client (`db`) and node-postgres `Pool` with development cache (`globalThis`), graceful shutdown (`closeDatabase()`), and runtime server-only protection.
- **Foundational Schemas**:
  - `src/server/db/schema/auth.ts`: Better Auth prerequisite tables (`user`, `session`, `account`, `verification`, `passkey`) with required column types, foreign keys, cascades, and unique constraints.
  - `src/server/db/schema/preferences.ts`: User preferences table (`user_preferences`) storing theme, date/time formats, and working hours with foreign key to `user`.
  - `src/server/db/schema/audit.ts`: Immutable `audit_log` table storing security, auth, and mutation events with JSONB details and query performance indexes.
  - `src/server/db/schema/index.ts`: Barrel export aggregating all foundational tables, relations, and TypeScript inferred types.
- **Migration Pipeline**:
  - `src/server/db/migrate.ts`: Programmatic migration runner utilizing `drizzle-orm/node-postgres/migrator` with error handling and live connectivity checks.
  - `src/server/db/migrations/`: Initial SQL DDL migration files and `meta/_journal.json` generated via `pnpm db:generate`.
- **Database Health & Connectivity Verification**: `checkDatabaseHealth()` utility returning `{ ok: boolean, latencyMs?: number, error?: string }` without throwing unhandled exceptions when PostgreSQL is down.
- **Integration Test Configuration**: `vitest.integration.config.ts` for running live integration tests against a running PostgreSQL container.
- **Test Suite**: Comprehensive tests located strictly in `scripts/tests/phase-01/plan-02/` covering database configuration, schema constraints, server-only boundaries, migration integrity, and connectivity failure handling.
- **Documentation**: Docker workflow runbook and database migration guide.

### Non-Goals (Explicitly Out of Scope)
- **Better Auth Implementation & Routes**: Auth route handlers (`/api/auth/[...all]`), client auth hooks, login/signup form logic, session issuance, and session validation (deferred to Plan 01-03).
- **Authentication Credentials & Recovery**: Password hashing, passkey registration flows, emergency recovery codes, and `auth:reset` CLI script (deferred to Plan 01-03).
- **Application Authorization**: Server action ownership guards (`verifyResourceOwnership`) (deferred to Plan 01-03).
- **Application Shell & UI**: Sidebar navigation, layout components, command palette (`cmdk`), theme toggle components, and settings views (deferred to Plan 01-04).
- **Audit Log UI**: Audit viewer page at `/settings/audit-log` (deferred to Plan 01-04).
- **Domain Tables & Logic**: Tasks, projects, goals, habits, calendar time blocks, notes, people/CRM, finances, content, AI (strictly prohibited until Phases 2–9 per the vertical-slice rule).
- **External Integrations**: Third-party APIs, OAuth providers, S3 backups (Phases 7–8).

## 7. Database Architecture

### Layer Position & Invariants
```
┌────────────────────────────────────────────────────────┐
│                   Domain Services                      │  (Phase 2+: TaskService, etc.)
│              (src/server/services/**)                  │
└───────────────────────────┬────────────────────────────┘
                            │ imports
┌───────────────────────────▼────────────────────────────┐
│                    Database Layer                      │  (Phase 1, Plan 01-02)
│                 (src/server/db/**)                     │
│  - db (Drizzle instance with typed schema)             │
│  - pool (pg.Pool singleton with Fast Refresh cache)    │
│  - checkDatabaseHealth() / closeDatabase()             │
│  - schema/ (auth, preferences, audit)                  │
│  - migrate.ts & migrations/                            │
└───────────────────────────┬────────────────────────────┘
                            │ TCP / Wire protocol
┌───────────────────────────▼────────────────────────────┐
│                  PostgreSQL 16+                        │
│                 (Docker / Hosted)                      │
└────────────────────────────────────────────────────────┘
```

### Invariants:
1. **Server-Only Execution**: The database client can only be instantiated in Node.js runtime. Browser imports trigger immediate runtime exceptions.
2. **Layer Independence**: `src/server/db/**` never imports from domain services, features, components, or UI views.
3. **No Direct UI Access**: Presentation layers (`src/app/**`, `src/components/**`) must never import from `src/server/db/**`. Access is permitted only via server actions and domain services.
4. **Single Source of Pool State**: In development mode, `pg.Pool` is cached on `globalThis.__lifeos_pg_pool__` to prevent connection exhaustion from Next.js HMR reloads. In production, a single pool instance is created.
5. **Connection Resilience**: Pool defaults: `max: 10`, `idleTimeoutMillis: 30000`, `connectionTimeoutMillis: 5000`. If PostgreSQL is unreachable, operations time out cleanly and report errors rather than locking the Node event loop.

## 8. Schema and Migration Design

### Foundational Tables Specification

#### 1. Better Auth Prerequisite Tables (`src/server/db/schema/auth.ts`)
Aligned with Better Auth 1.7.4 + `@better-auth/passkey` schema requirements:

- **`user` table**:
  - `id`: `text("id").primaryKey()`
  - `name`: `text("name").notNull()`
  - `email`: `text("email").notNull().unique()`
  - `emailVerified`: `boolean("email_verified").notNull().default(false)`
  - `image`: `text("image")`
  - `createdAt`: `timestamp("created_at", { withTimezone: true }).notNull().defaultNow()`
  - `updatedAt`: `timestamp("updated_at", { withTimezone: true }).notNull().defaultNow()`

- **`session` table**:
  - `id`: `text("id").primaryKey()`
  - `userId`: `text("user_id").notNull().references(() => user.id, { onDelete: "cascade" })`
  - `token`: `text("token").notNull().unique()`
  - `expiresAt`: `timestamp("expires_at", { withTimezone: true }).notNull()`
  - `ipAddress`: `text("ip_address")`
  - `userAgent`: `text("user_agent")`
  - `createdAt`: `timestamp("created_at", { withTimezone: true }).notNull().defaultNow()`
  - `updatedAt`: `timestamp("updated_at", { withTimezone: true }).notNull().defaultNow()`

- **`account` table**:
  - `id`: `text("id").primaryKey()`
  - `userId`: `text("user_id").notNull().references(() => user.id, { onDelete: "cascade" })`
  - `accountId`: `text("account_id").notNull()`
  - `providerId`: `text("provider_id").notNull()`
  - `accessToken`: `text("access_token")`
  - `refreshToken`: `text("refresh_token")`
  - `idToken`: `text("id_token")`
  - `accessTokenExpiresAt`: `timestamp("access_token_expires_at", { withTimezone: true })`
  - `refreshTokenExpiresAt`: `timestamp("refresh_token_expires_at", { withTimezone: true })`
  - `scope`: `text("scope")`
  - `password`: `text("password")`
  - `createdAt`: `timestamp("created_at", { withTimezone: true }).notNull().defaultNow()`
  - `updatedAt`: `timestamp("updated_at", { withTimezone: true }).notNull().defaultNow()`

- **`verification` table**:
  - `id`: `text("id").primaryKey()`
  - `identifier`: `text("identifier").notNull()`
  - `value`: `text("value").notNull()`
  - `expiresAt`: `timestamp("expires_at", { withTimezone: true }).notNull()`
  - `createdAt`: `timestamp("created_at", { withTimezone: true }).notNull().defaultNow()`
  - `updatedAt`: `timestamp("updated_at", { withTimezone: true }).notNull().defaultNow()`

- **`passkey` table**:
  - `id`: `text("id").primaryKey()`
  - `name`: `text("name")`
  - `publicKey`: `text("public_key").notNull()`
  - `userId`: `text("user_id").notNull().references(() => user.id, { onDelete: "cascade" })`
  - `credentialID`: `text("credential_id").notNull().unique()`
  - `counter`: `integer("counter").notNull().default(0)`
  - `deviceType`: `text("device_type").notNull()`
  - `backedUp`: `boolean("backed_up").notNull().default(false)`
  - `transports`: `text("transports")`
  - `createdAt`: `timestamp("created_at", { withTimezone: true }).notNull().defaultNow()`
  - `updatedAt`: `timestamp("updated_at", { withTimezone: true }).notNull().defaultNow()`

#### 2. User Preferences Table (`src/server/db/schema/preferences.ts`)
- **`user_preferences` table**:
  - `id`: `text("id").primaryKey().$defaultFn(() => crypto.randomUUID())`
  - `userId`: `text("user_id").notNull().unique().references(() => user.id, { onDelete: "cascade" })`
  - `theme`: `text("theme", { enum: ["dark", "light", "system"] }).notNull().default("dark")`
  - `dateFormat`: `text("date_format").notNull().default("YYYY-MM-DD")`
  - `timeFormat`: `text("time_format", { enum: ["12h", "24h"] }).notNull().default("24h")`
  - `workingHoursStart`: `text("working_hours_start").notNull().default("09:00")`
  - `workingHoursEnd`: `text("working_hours_end").notNull().default("18:00")`
  - `createdAt`: `timestamp("created_at", { withTimezone: true }).notNull().defaultNow()`
  - `updatedAt`: `timestamp("updated_at", { withTimezone: true }).notNull().defaultNow()`

#### 3. Audit Log Table (`src/server/db/schema/audit.ts`)
- **`audit_log` table**:
  - `id`: `text("id").primaryKey().$defaultFn(() => crypto.randomUUID())`
  - `userId`: `text("user_id").references(() => user.id, { onDelete: "set null" })`
  - `category`: `text("category", { enum: ["auth", "security", "mutation", "system"] }).notNull()`
  - `action`: `text("action").notNull()` (e.g. `auth.login.success`, `auth.signup`, `settings.theme_changed`)
  - `status`: `text("status", { enum: ["success", "failure"] }).notNull()`
  - `actor`: `text("actor")` (email, user ID, or 'system')
  - `details`: `jsonb("details")` (context metadata, changes, request params)
  - `ipAddress`: `text("ip_address")`
  - `userAgent`: `text("user_agent")`
  - `createdAt`: `timestamp("created_at", { withTimezone: true }).notNull().defaultNow()`
  - **Indexes**:
    - `audit_log_category_idx` on `category`
    - `audit_log_action_idx` on `action`
    - `audit_log_created_at_idx` on `createdAt`
    - `audit_log_user_id_idx` on `userId`

#### 4. Relations & Schema Aggregation (`src/server/db/schema/index.ts`)
- Exports Drizzle `relations` linking `user` to `sessions`, `accounts`, `passkeys`, `user_preferences`, and `audit_log`.
- Inferred TypeScript types: `User`, `Session`, `Account`, `Passkey`, `UserPreferences`, `AuditLog`, `NewUserPreferences`, `NewAuditLog`.
- Anti-drift schema verification: exports an explicit array of table names for programmatic assertion.

### Migration Strategy
1. **Drizzle Kit Generation**: Command `pnpm db:generate` executes `drizzle-kit generate`. It inspects `src/server/db/schema/index.ts` and outputs versioned SQL scripts to `src/server/db/migrations/0000_initial_foundation.sql` alongside `meta/_journal.json`.
2. **Programmatic Migration Runner**: `src/server/db/migrate.ts` applies migrations using `drizzle-orm/node-postgres/migrator`. Drizzle automatically creates and manages `__drizzle_migrations` in PostgreSQL, preventing duplicate executions.
3. **Failure Handling**: If PostgreSQL is unreachable, `migrate.ts` catches `ECONNREFUSED` / timeout errors and exits cleanly with error code 1 and actionable instructions (`Ensure PostgreSQL is running: docker compose up -d postgres`).

## 15. Risks and Mitigations

| Risk | Impact | Mitigation Strategy |
|------|--------|---------------------|
| Docker socket permission denied on host | Developers or CI cannot run live container commands without setup | Separate unit/schema tests (`pnpm test`) from live integration tests (`pnpm test:integration`). Unit tests run offline using schema inspection and mocks. Clear documentation for Docker group setup (`sudo usermod -aG docker $USER`). |
| Connection pool leak during Next.js hot reload | Database exhausts connection limit in development | Cache `pg.Pool` on `globalThis.__lifeos_pg_pool__` during development, matching official Next.js database recommendations. |
| Client component accidentally importing database client | Server secrets or Node.js native modules leak to browser bundle | Architecture boundary test Rule 2, 4, 6 and runtime guard in `src/server/db/index.ts` immediately flag and prevent illegal imports. |
| Schema drift between Drizzle tables and Better Auth expectations | Better Auth runtime queries fail in Plan 01-03 | Fields and column names in `auth.ts` are strictly modeled against Better Auth 1.7.4 core schema and passkey plugin specifications. |
| Premature domain entity introduction | Violates Phase 1 vertical-slice boundary | Explicit anti-regression tests in `schema.test.ts` verify zero domain tables exist in the schema. |
