# Plan 01-04.1: Close Authentication Boundary Race Conditions & Production Hardening — Summary

## Execution Summary

Plan 01-04.1 closed the registration race condition identified during adversarial review of Plan 01-04, transitioning LifeOS from application-level TOCTOU checks to an atomic, PostgreSQL storage-engine enforced single-user invariant.

### Key Deliverables Implemented

1. **PostgreSQL Storage-Engine Single-User Invariant**:
   - Added column `single_user_lock boolean DEFAULT true NOT NULL` on table `"user"`.
   - Added unique constraint `CONSTRAINT user_single_user_lock_unique UNIQUE (single_user_lock)`.
   - Added check constraint `CONSTRAINT user_single_user_lock_check CHECK (single_user_lock = true)`.
   - Applied via migration `0004_single_user_lock.sql` and registered in `_journal.json`.
   - Verified live in PostgreSQL catalog.

2. **Auth Engine Hardening (`src/server/auth/index.ts`)**:
   - Added `.onConflictDoNothing()` for automatic `userPreferences` initialization upon registration to prevent preference creation races.
   - Retained fast fail-closed pre-checks in `hooks.before` and `databaseHooks.user.create.before` to reject subsequent registrations immediately with `403 Forbidden`.

3. **Concurrency Test Suite (`scripts/tests/phase-01/plan-04.1/auth-race.integration.test.ts`)**:
   - Live PostgreSQL test suite respecting the three-state authenticity contract (`REQUIRE_DB=true`).
   - Implemented a barrier/latch synchronization mechanism to launch concurrent registration requests simultaneously into the event loop.
   - Executed across 5 iterations: proved that under heavy concurrent overlap, exactly 1 registration succeeds, all others are rejected, and exactly 1 user row exists in PostgreSQL.
   - Proved that subsequent registrations receive `403 Forbidden`.
   - Proved that direct SQL insertion of a second user fails with `23505 unique_violation`.
   - Proved that raw SQL bypassing Better Auth is rejected by PostgreSQL.
   - Proved that `single_user_lock = false` is rejected with `23514 check_violation`.
   - Proved that `single_user_lock = NULL` is rejected with `23502 not_null_violation`.
   - Proved that concurrent uncommitted transactions block on index tuple locks and serialize atomically.
   - Proved that rolled-back transactions leave the database clean and allow subsequent registrations.

4. **Unit Test Suite (`scripts/tests/phase-01/plan-04.1/auth-race.test.ts`)**:
   - Verified Drizzle schema definitions for `singleUserLock` column, data type, default value, and nullability.
   - Verified foundational 7-table vertical slice constraint.

5. **Integration Test Suite Serialization (`vitest.integration.config.ts`)**:
   - Configured `fileParallelism: false` to ensure database integration test suites run sequentially against the live database without table truncation interference.

6. **Alignment of Plan 01-04 Integration Tests (`scripts/tests/phase-01/plan-04/auth-session.integration.test.ts`)**:
   - Updated IDOR and ownership tests to verify that PostgreSQL rejects inserting a second user row directly, and tested IDOR boundaries against unauthorized identifiers without violating the single-user database invariant.
