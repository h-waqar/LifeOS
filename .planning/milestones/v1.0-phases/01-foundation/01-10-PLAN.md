# Plan 01-10: Human Verification Loop Framework (`.human-loop/`)

## 1. Context & Objectives

Plan 01-09 implemented the LifeOS application shell, core productivity views (`/login`, `/register`, `/dashboard`, `/projects`, `/tasks`), public operational healthcheck (`GET /api/health`), and verified 16 browser user journeys via automated CDP Chromium tests.

While automated verification, static analysis, unit tests, and integration tests passed with a 100% rate, **genuine human verification has not yet been performed**. Automated headless browser scripts cannot evaluate subjective visual polish, user ergonomic feel, assistive accessibility with screen readers, or edge-case sensory feedback.

The objective of Plan 01-10 is to create a repository-native, Git-friendly, and auditable `.human-loop/` framework to govern all manual human verification activities, enforcing a strict zero-fabrication policy and maintaining a clear separation between automated evidence and human sign-off.

## 2. Framework Architecture & Components

### 2.1 Repository Directory Structure
```text
.human-loop/
├── README.md                          # Framework specification, state machine, and operating guide
├── INDEX.md                           # Top-level navigation, active plans, and metric overview
├── progress/
│   ├── README.md                      # Progress computation rules and maintenance protocols
│   ├── current.md                     # Active plan verification dashboard
│   └── plan-01-09.md                  # Comprehensive progress report for Plan 01-09
├── pending/
│   └── plan-01-09/                    # Active pending human check suites (H01-H12)
├── verified/
│   └── plan-01-09/                    # Human-verified suites (empty until human testing passes)
└── artifacts/
    └── plan-01-09/
        ├── screenshots/               # Directory for genuine human screenshots
        ├── recordings/                # Directory for genuine human video recordings
        └── reports/                   # Directory for genuine human accessibility/audit reports
```

### 2.2 Human Verification State Machine
Every check document enforces one of six explicit states:
1. `PENDING` (Default): Not yet tested by a human.
2. `IN_PROGRESS`: Actively undergoing manual testing.
3. `BLOCKED`: Blocked by external/environment dependency (reason documented).
4. `FAILED`: Defect discovered (defect documented with reproduction steps).
5. `VERIFIED`: Human explicitly confirmed expected behavior with attached evidence.
6. `WAIVED`: Formal documented waiver (never silent).

### 2.3 File Movement Protocol
- Checks remain in `.human-loop/pending/<plan>/` during `PENDING`, `IN_PROGRESS`, `BLOCKED`, and `FAILED` states.
- When and only when a check achieves `STATUS: VERIFIED`, the file is moved to `.human-loop/verified/<plan>/`.
- History is preserved in Git; files are never deleted upon passing.

## 3. Plan 01-09 Human Verification Suites

Twelve concrete, reproducible manual verification documents were created in `.human-loop/pending/plan-01-09/`:

1. **`H01-authentication.md` (RELEASE-BLOCKING):** Sign-in rendering, input validation, invalid credentials handling, loading states, `/dashboard` redirect, logout termination, route guard enforcement, back-navigation security.
2. **`H02-registration.md` (RELEASE-BLOCKING):** First-owner initialization, single-user 403 Forbidden lock enforcement, input validation (>=8 char passwords), sanitized error presentation.
3. **`H03-dashboard.md` (HIGH):** KPI calculations (Active Projects, Pending Tasks, Completed Tasks, Critical Priority), empty states, quick-create modals, inline task completion toggle with strikethrough.
4. **`H04-project-management.md` (HIGH):** Projects grid, status filter tabs, creation, editing, deletion with explicit task unassignment warning.
5. **`H05-task-hierarchy.md` (HIGH):** Hierarchical tree visualization, visual indentation, multi-level nesting (depth 0 to 3+), inline checkbox completion, cascading deletion warning and execution, long title text wrapping.
6. **`H06-responsive-mobile.md` (RELEASE-BLOCKING):** Desktop (1440x900), Tablet (768x1024), Mobile (390x844), sidebar collapsibility, mobile drawer auto-close, touch targets (>=44px), zero horizontal overflow.
7. **`H07-theme-preferences.md` (MEDIUM):** Dark, Light, System themes, contrast compliance, persistence to `localStorage` and `/api/preferences` across reload and logout.
8. **`H08-command-palette.md` (MEDIUM):** `Ctrl+K` / `Cmd+K` shortcuts, command search/filtering, navigation actions, modal triggers, theme toggle, sign out, focus management.
9. **`H09-error-states.md` (HIGH):** Slow 3G network latency, offline recovery, rapid click double-submit defense, long input bounds, XSS script escaping, session invalidation.
10. **`H10-accessibility.md` (HIGH):** Keyboard-only navigation, focus rings, modal focus traps, Escape key dismissal, form control label bindings, WCAG AA color contrast.
11. **`H11-visual-polish.md` (HIGH):** Spacing, typography, alignment, component states, modal centering, zero placeholder text ("Lorem Ipsum"), zero console errors or hydration mismatches.
12. **`H12-operational-healthcheck.md` (HIGH):** Public `GET /api/health`, database connectivity verification, latency reporting, security cache headers, database pause 503 test, zero credential leakage.
