## 1. Executive Summary & Context

Plan 02-06 delivers the **Unified Home Dashboard & Executive Control Center** for LifeOS, answering the user's primary operating question: **"What matters right now?"**.

Acting as the central cockpit of the personal operating system, the dashboard unifies all Phase 2 execution engines:
1. **Goals & Projects Hierarchy (Plan 02-02 / DASH-03):** Multi-horizon visualization (long-term, medium-term, short-term) with canonical progress rollups, child goal counts, and active project health.
2. **Deterministic Priority Execution (Plan 02-01 / DASH-01, DASH-02):** Highlights today's top-priority tasks ranked by deterministic scoring (importance + urgency + deadline proximity - dependency penalty), overdue work needing immediate triage, and scheduled work.
3. **Daily Planning Integration (Plan 02-05 / DASH-02):** Real-time morning routine status, evening review status, today's productivity score, rollover state, and 7-day productivity trends.
4. **Habits & Streaks Engine (Plan 02-03 / DASH-04, HABT-02):** Active daily habits, single-click check-ins directly from the dashboard, current streaks, and daily completion rate.
5. **Calendar & Time Blocking (Plan 02-04 / DASH-05):** Today's scheduled focus periods, commitment levels (hard/soft), and single-click time block completion.
6. **Actionable Interaction Model (DASH-06):** Universal quick capture (`Q`), quick modals for tasks and projects, direct navigation to morning routine and evening review, and deep links to full domain modules.
7. **Multi-Tenant Security & Tenant Isolation (DASH-08):** Complete server-side resource ownership validation with zero client-trusted user identifiers.

The dashboard functions strictly as a read-oriented integration layer over existing domain services—**no duplicate business logic, no duplicate task or time-block records, and no parallel persistence tables**.

## 3. Database Architecture & Vertical-Slice Scope

In strict compliance with the **Vertical-Slice Database Evolution Rule**, Plan 02-06 does **not** introduce any new PostgreSQL tables.
- The dashboard is a pure read-oriented aggregation layer over the verified Phase 1 and Phase 2 relational tables (`users`, `tasks`, `projects`, `goals`, `habits`, `habit_entries`, `time_blocks`, `daily_plans`, `evening_reviews`).
- Zero database migrations are needed.
- In-place mutation rules for tasks (`tasks.scheduled_date`, `tasks.status`) and time blocks (`time_blocks.status`, `time_blocks.actual_minutes`) are strictly honored to preserve zero-duplication rollover and stable primary keys.

## 4. Architecture & Service Design

### 4.1 Dependency Flow
```text
src/app/dashboard/page.tsx (Client UI)
       │
       ▼ (HTTP GET /api/dashboard?date=YYYY-MM-DD)
src/app/api/dashboard/route.ts (Route Handler + Auth Guard)
       │
       ▼ (getDashboardOverview)
src/server/dashboard/service.ts (Dashboard Aggregation Service)
       ├──> src/server/daily-plan/service.ts (getDailyPlan, getDailyPlanHistory)
       ├──> src/server/goals/service.ts (listGoals)
       ├──> src/server/projects/service.ts (listProjects)
       ├──> src/server/tasks/service.ts (listTasks, priority scoring)
       └──> src/server/habits/service.ts (listHabits)
```

### 4.2 Aggregation View Model (`DashboardOverviewDTO`)
```ts
export interface DashboardOverviewDTO {
  date: string; // ISO calendar date YYYY-MM-DD
  greeting: {
    userName: string;
    todayFormatted: string; // e.g. "Wednesday, September 16, 2026"
  };
  metrics: {
    activeGoalsCount: number;
    activeProjectsCount: number;
    pendingTasksCount: number;
    completedTasksCount: number;
    overdueTasksCount: number;
    criticalTasksCount: number;
    todayHabitsTotal: number;
    todayHabitsCompleted: number;
    todayTimeBlocksCount: number;
    todayProductivityScore: number | null;
  };
  dailyPlan: {
    hasPlan: boolean;
    planStatus: "none" | "in_progress" | "completed";
    completedAt: string | null;
    morningNotes: string | null;
    hasReview: boolean;
    reviewCompleted: boolean;
    productivityScore: number | null;
    rolledOverCount: number;
  };
  priorities: {
    todayTasks: TaskDTO[];       // Today's scheduled or morning plan priority tasks (ranked by priority score)
    overdueTasks: TaskDTO[];     // Incomplete overdue tasks requiring immediate attention
    criticalTasks: TaskDTO[];    // Unscheduled critical/high priority tasks
  };
  schedule: {
    todayBlocks: TimeBlockDTO[]; // Sorted by startTime
    totalScheduledMinutes: number;
    completedMinutes: number;
  };
  habits: {
    items: HabitDTO[];           // Active habits for today with streak info and isCompletedToday
    completionRateToday: number; // 0-100%
  };
  goalsAndProjects: {
    activeGoals: GoalDTO[];      // In-progress goals with canonical progress rollups
    activeProjects: ProjectDTO[]; // Active projects with canonical progress rollups
  };
  recentTrend?: {
    averageProductivityScore: number;
    morningPlanCompletionRate: number;
    eveningReviewCompletionRate: number;
  };
}
```
