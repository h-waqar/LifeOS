# Plan 02-04: Calendar & Time Blocking Engine with Task Scheduling, Conflict Prevention, and Actual Time Analytics

## 1. Plan Overview & Executive Context

- **Phase:** 2 — Core Productivity
- **Plan Identification:** 02-04
- **Domain:** Calendar & Time Blocking Engine
- **Prerequisites:** Phase 1 Foundation conditionally accepted and closed for development. Phase 2 Plan 02-01 (Task Management Engine), Plan 02-02 (Goals & Projects Hierarchy), and Plan 02-03 (Habits & Streaks Engine) verified, audited, and closed.
- **Goal:** Deliver the complete Calendar & Time Blocking Engine supporting Day, Week, and Month calendar visualizations, drag-and-drop / click-to-block task scheduling, hard commitment overlap prevention, soft scheduling conflict detection and highlighting, completed time block actual time tracking with automatic task analytics updates, habit check-in timeblock integration, composite tenant isolation, and responsive calendar UI integrated with AppShell and Dashboard.
- **Requirements Satisfied:**
  - **CAL-01**: User can view a day, week, and month calendar displaying scheduled time blocks and deadlines.
  - **CAL-02**: User can create time blocks directly linked to canonical tasks (drag-and-drop or click-to-block).
  - **CAL-03**: Completed time blocks reflect actual time spent and update linked task analytics.
  - **CAL-04**: System prevents overlapping hard commitments and highlights scheduling conflicts.
  - **Deferred from Plan 02-03**: Habit check-in timeblock integration (link habit to time block; completing block can register habit check-in).
- **Key Architectural Principles:**
  - **Strict Composite Isolation:** Every entity relationship enforces composite foreign keys `(user_id, [parent/foreign]_id)` (e.g. `(user_id, task_id)`, `(user_id, project_id)`, `(user_id, goal_id)`, `(user_id, habit_id)`) to guarantee zero cross-tenant leakage.
  - **Hard vs. Soft Commitments & Overlap Prevention (CAL-04):**
    - `commitment_level = 'hard'`: Hard commitments (e.g., fixed appointments, client meetings) MUST NOT overlap with any other non-cancelled hard commitment for the same user. Rejection with 409 Conflict at service and API boundary.
    - `commitment_level = 'soft'`: Flexible focus time blocks can overlap but system detects and highlights all conflicts (soft vs soft, soft vs hard) with visual badges and warnings.
  - **Pure Algorithmic Conflict Engine:** Pure module `src/server/calendar/conflicts.ts` evaluates temporal intervals $[start, end)$ deterministically with zero database or framework dependencies.
  - **Transactional Task Analytics Synchronization (CAL-03):** When a time block linked to a task transitions to `completed` status:
    - The block records `actualMinutes` and `completedAt`.
    - In the same ACID transaction, the linked task's `actualDuration` is incremented by `actualMinutes`.
    - If uncompleted or cancelled, `actualDuration` is decremented accordingly.
    - If a completed block is deleted, task `actualDuration` is decremented in transaction.
  - **Habit Check-in Timeblock Integration:** When a time block linked to a habit is marked completed, the system can transactionally log or trigger a habit entry for that day, closing the loop with the habit engine.
  - **Multi-View Unified Calendar Data Aggregation (CAL-01):** Aggregates time blocks, task deadlines (`due_date`), task scheduled dates (`scheduled_date`), project target deadlines, and habit schedule cues across Day, Week, and Month timeframes.

## 3. Database Architecture & Schema Evolution

### 3.1 New Table: `time_blocks`
```sql
CREATE TABLE IF NOT EXISTS "time_blocks" (
  "id" text PRIMARY KEY NOT NULL,
  "user_id" text NOT NULL,
  "title" text NOT NULL,
  "description" text,
  "start_time" timestamp with time zone NOT NULL,
  "end_time" timestamp with time zone NOT NULL,
  "duration_minutes" integer NOT NULL,
  "status" text DEFAULT 'scheduled' NOT NULL,
  "commitment_level" text DEFAULT 'soft' NOT NULL,
  "actual_minutes" integer,
  "completed_at" timestamp with time zone,
  "color" text,
  "task_id" text,
  "project_id" text,
  "goal_id" text,
  "habit_id" text,
  "created_at" timestamp with time zone DEFAULT now() NOT NULL,
  "updated_at" timestamp with time zone DEFAULT now() NOT NULL,
  CONSTRAINT "time_blocks_user_id_id_unique" UNIQUE("user_id", "id"),
  CONSTRAINT "time_blocks_title_non_empty" CHECK (length(trim("title")) > 0),
  CONSTRAINT "time_blocks_title_max_length" CHECK (length("title") <= 255),
  CONSTRAINT "time_blocks_description_max_length" CHECK ("description" IS NULL OR length("description") <= 4000),
  CONSTRAINT "time_blocks_time_order" CHECK ("end_time" > "start_time"),
  CONSTRAINT "time_blocks_duration_bounds" CHECK ("duration_minutes" > 0 AND "duration_minutes" <= 1440),
  CONSTRAINT "time_blocks_actual_minutes_bounds" CHECK ("actual_minutes" IS NULL OR ("actual_minutes" >= 0 AND "actual_minutes" <= 1440)),
  CONSTRAINT "time_blocks_status_check" CHECK ("status" IN ('scheduled', 'completed', 'cancelled')),
  CONSTRAINT "time_blocks_commitment_check" CHECK ("commitment_level" IN ('soft', 'hard')),
  CONSTRAINT "time_blocks_completed_at_invariant" CHECK ("status" != 'completed' OR "completed_at" IS NOT NULL)
);
```

### 3.2 Composite Foreign Keys & Tenant Isolation
- `(user_id) REFERENCES user(id) ON DELETE CASCADE`
- `(user_id, task_id) REFERENCES tasks(user_id, id) ON DELETE SET NULL`
- `(user_id, project_id) REFERENCES projects(user_id, id) ON DELETE SET NULL`
- `(user_id, goal_id) REFERENCES goals(user_id, id) ON DELETE SET NULL`
- `(user_id, habit_id) REFERENCES habits(user_id, id) ON DELETE SET NULL`

### 3.3 Indexes
- `time_blocks_user_id_idx` ON `(user_id)`
- `time_blocks_user_range_idx` ON `(user_id, start_time, end_time)`
- `time_blocks_user_task_idx` ON `(user_id, task_id)`
- `time_blocks_user_habit_idx` ON `(user_id, habit_id)`
- `time_blocks_user_status_idx` ON `(user_id, status)`
- `time_blocks_user_commitment_idx` ON `(user_id, commitment_level)`

## 4. Algorithmic Conflict Engine (`src/server/calendar/conflicts.ts`)

- Pure functions with no DB/HTTP/React dependencies:
  - `doIntervalsOverlap(startA: Date, endA: Date, startB: Date, endB: Date): boolean`:
    $$(startA < endB) \land (endA > startB)$$
    Adjacent intervals ($endA = startB$) do not overlap.
  - `findHardCommitmentConflict(candidate: { startTime: Date; endTime: Date }, existingBlocks: TimeBlockDTO[], ignoreId?: string): TimeBlockDTO | null`:
    Finds if the candidate hard commitment overlaps with any existing non-cancelled hard commitment.
  - `detectConflicts(blocks: TimeBlockDTO[]): Map<string, ConflictDetail>`:
    Scans blocks within a timeframe, identifying all soft/hard collisions and returning conflict markers for UI rendering.

## 5. Service & API Layer

### 5.1 Service Layer (`src/server/calendar/service.ts`)
- `createTimeBlock(userId, input)`:
  - Validates input with Zod.
  - Checks hard commitment overlaps; rejects if conflicting.
  - Verifies foreign key ownership (`taskId`, `projectId`, `goalId`, `habitId`).
  - Auto-calculates `durationMinutes` if omitted based on start/end.
  - Writes audit log.
- `getTimeBlock(userId, blockId)`:
  - Retrieves block with conflict status.
- `listTimeBlocks(userId, filters)`:
  - Filter by date range `(startDate, endDate)`, `status`, `taskId`, `habitId`.
- `updateTimeBlock(userId, blockId, input)`:
  - Checks hard commitment overlap on updated time range.
  - Adjusts task analytics if `actualMinutes` changes on a completed block.
- `completeTimeBlock(userId, blockId, actualMinutes?, completeLinkedTask?, logHabitEntry?)`:
  - Transactional update: sets status = `'completed'`, `actual_minutes`, `completed_at`.
  - Increments linked `task.actual_duration`.
  - Optionally completes task if requested.
  - Optionally logs habit entry if linked to a habit.
- `deleteTimeBlock(userId, blockId)`:
  - If completed, transactional rollback of task `actual_duration`.
- `getCalendarFeed(userId, { startDate, endDate, view })`:
  - Aggregates time blocks (with conflicts), tasks due/scheduled, projects due, habit cues.

### 5.2 API Routes
- `GET, POST /api/time-blocks`
- `GET, PATCH, DELETE /api/time-blocks/[id]`
- `POST /api/time-blocks/[id]/complete`
- `GET /api/calendar`
