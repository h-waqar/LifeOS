# Plan 02-03: Habits & Streaks Engine with Flexible Frequency Rules and Single-Click Check-Ins

## 1. Plan Overview & Executive Context

- **Phase:** 2 — Core Productivity
- **Plan Identification:** 02-03
- **Domain:** Habits & Streaks Engine
- **Prerequisites:** Phase 1 Foundation conditionally accepted and closed for development. Phase 2 Plan 02-01 (Task Management Engine, Priority Scoring, Recurrence, Universal Quick Capture) and Plan 02-02 (Goals, Projects Hierarchy & Multi-Horizon Progress Rollups) verified, audited, and closed.
- **Goal:** Deliver the complete Habits & Streaks engine supporting multi-frequency schedules (Daily, Weekdays, Weekly X times per week, Specific weekdays, Custom intervals), time-of-day cues, single-click idempotent daily check-ins, accurate deterministic streak calculations (current streak, longest streak, completion rate), goal and identity statement linkage, task-to-habit composite referential integrity, and a responsive habit tracker UI.
- **Requirements Satisfied:**
  - **HABT-01**: User can create habits with frequency rules (Daily, Weekdays, X times per week, Specific days) and time-of-day cues.
  - **HABT-02**: User can log habit completions with a single click from the Dashboard or Habit Tracker.
  - **HABT-03**: System calculates current streak, longest streak, and completion rate percentages accurately.
  - **HABT-04**: User can link habits to long-term goals or identity statements.
- **Key Architectural Principles:**
  - **Strict Composite Isolation:** Every relationship enforces composite foreign keys `(user_id, [parent/foreign]_id)` to guarantee zero cross-tenant leakage.
  - **Check-in Idempotency:** Daily check-ins are anchored to local calendar day `date` (`YYYY-MM-DD`) with database-level uniqueness on `(user_id, habit_id, date)`.
  - **Deterministic Pure Calculations:** Pure calculation engine (`src/server/habits/streaks.ts`) for streak, rest-day handling, and completion-rate calculations with 100% unit-tested math. Streaks are based on scheduled occurrences, not raw calendar dates.
  - **Target-Value Semantics:** Supports boolean (target_value = 1) and quantitative habits. Entries are completed only when `value >= target_value`. Partial values do not count toward streaks or completion rates.
  - **Persisted Fields As Derived Cache:** The habit-entry history is the canonical source of truth for streak metrics. Persisted `current_streak` and `longest_streak` in `habits` are derived cached values, never blindly trusted.
  - **Non-Destructive Goal Rollup Preservation:** Habit completion MUST NOT modify the existing Goal Progress Rollup formula from Plan 02-02. Plan 02-02 rollup remains authoritative.
  - **Timezone-Aware Date Handling:** User's calendar day is evaluated without UTC midnight drift. Reference date is explicitly passed to pure calculations for deterministic execution.

## 3. Database Architecture & Vertical-Slice Schema Evolution

### 3.1 New Table: `habits`
```sql
CREATE TABLE IF NOT EXISTS "habits" (
  "id" text PRIMARY KEY NOT NULL,
  "user_id" text NOT NULL,
  "title" text NOT NULL,
  "description" text,
  "frequency" text NOT NULL DEFAULT 'daily',
  "frequency_target" integer NOT NULL DEFAULT 1,
  "frequency_days" jsonb NOT NULL DEFAULT '[]'::jsonb,
  "interval_days" integer NOT NULL DEFAULT 1,
  "target_value" double precision NOT NULL DEFAULT 1,
  "unit" text,
  "time_of_day" text NOT NULL DEFAULT 'anytime',
  "reminder_time" text,
  "goal_id" text,
  "identity_statement" text,
  "status" text NOT NULL DEFAULT 'active',
  "current_streak" integer NOT NULL DEFAULT 0,
  "longest_streak" integer NOT NULL DEFAULT 0,
  "created_at" timestamp with time zone DEFAULT now() NOT NULL,
  "updated_at" timestamp with time zone DEFAULT now() NOT NULL,
  CONSTRAINT "habits_user_id_id_unique" UNIQUE("user_id", "id"),
  CONSTRAINT "habits_title_non_empty" CHECK (length(trim("title")) > 0),
  CONSTRAINT "habits_title_max_length" CHECK (length("title") <= 255),
  CONSTRAINT "habits_description_max_length" CHECK ("description" IS NULL OR length("description") <= 4000),
  CONSTRAINT "habits_identity_statement_max_length" CHECK ("identity_statement" IS NULL OR length("identity_statement") <= 500),
  CONSTRAINT "habits_frequency_check" CHECK ("frequency" IN ('daily', 'weekdays', 'weekly', 'specific_days', 'custom')),
  CONSTRAINT "habits_frequency_target_positive" CHECK ("frequency_target" >= 1),
  CONSTRAINT "habits_interval_days_positive" CHECK ("interval_days" >= 1),
  CONSTRAINT "habits_target_value_positive" CHECK ("target_value" > 0),
  CONSTRAINT "habits_time_of_day_check" CHECK ("time_of_day" IN ('morning', 'afternoon', 'evening', 'anytime')),
  CONSTRAINT "habits_status_check" CHECK ("status" IN ('active', 'paused', 'archived')),
  CONSTRAINT "habits_current_streak_non_negative" CHECK ("current_streak" >= 0),
  CONSTRAINT "habits_longest_streak_non_negative" CHECK ("longest_streak" >= 0)
);
```

Composite foreign keys & indexes:
- `(user_id) REFERENCES user(id) ON DELETE CASCADE`
- `(user_id, goal_id) REFERENCES goals(user_id, id) ON DELETE SET NULL`
- Indexes:
  - `habits_user_id_idx` ON `(user_id)`
  - `habits_user_status_idx` ON `(user_id, status)`
  - `habits_user_goal_idx` ON `(user_id, goal_id)`
  - `habits_user_time_of_day_idx` ON `(user_id, time_of_day)`

## 4. Streak & Recurrence Calculation Engine

Module: `src/server/habits/streaks.ts`

### 4.1 Deterministic Streak Semantics
Streaks are based on **scheduled occurrences**, not raw calendar dates.
1. **Scheduled Day Habits (`daily`, `weekdays`, `specific_days`, `custom`):**
   - Non-scheduled days do NOT break a streak and do NOT count as missed.
   - An entry is completed only when `value >= target_value`. Partial entries do not count toward streaks or completion rates.
   - If the active reference day is a scheduled day and not yet completed:
     - The streak does NOT immediately reset to 0.
     - The streak remains the accumulated streak through the previous completed scheduled occurrence.
   - A scheduled day that has fully passed without completion breaks the streak (resets to 0).
   - If the reference day is completed, the streak increments.
   - **Weekdays habit:** Mon-Fri scheduled; Saturday & Sunday are rest days and do not break streaks (e.g., Friday completed carries over through Saturday and Sunday to Monday).
   - **Specific days habit:** e.g. Mon/Wed/Fri. Non-scheduled days (Tue, Thu, Sat, Sun) do not break streaks.
2. **Weekly X-times Habit (`weekly`):**
   - Evaluated on explicit **Monday–Sunday calendar weeks**.
   - A week qualifies if total qualifying completions (`value >= target_value`) in that week $\ge$ `frequency_target`.
   - The streak is consecutive qualifying weeks.
   - The current incomplete week is NOT treated as failed until the week has fully passed (i.e. reference date is past Sunday). If the current week already meets the target, it counts toward the streak; if not yet met, the streak from previous qualifying weeks remains active.
3. **Canonical Source of Truth:**
   - Habit entries + habit configuration + explicit `referenceDate` are the canonical source of truth.
   - `calculateStreakStats(habit, entries, referenceDate)` computes `currentStreak`, `longestStreak`, `completionRate30d`, `completionRateAllTime`, and `isCompletedToday`.
   - Persisted counters in the `habits` table (`current_streak`, `longest_streak`) are strictly derived cached values.
4. **Completion Rate:**
   $$\text{Completion Rate} = \frac{\text{Completed Scheduled Occurrences in Window}}{\text{Total Scheduled Occurrences in Window}} \times 100\%$$
   Bounded strictly $[0, 100]$. In an empty window with 0 scheduled occurrences, completion rate is $0\%$.

## 5. Service & API Layer

### 5.1 Service Layer (`src/server/habits/service.ts`)
- `createHabit(userId, input)`: Transactional creation with Zod validation, goal verification, and audit log.
- `getHabit(userId, habitId, referenceDate)`: Returns HabitDTO with calculated current streak, longest streak, today's completion status, and recent entries.
- `listHabits(userId, filters, referenceDate)`: List habits with streak stats, filterable by `status`, `timeOfDay`, and `goalId`.
- `updateHabit(userId, habitId, input)`: Updates habit parameters with optimistic locking and streak recalculation if schedule changes.
- `deleteHabit(userId, habitId)`: Cascading deletion of habit and associated entries.
- `logHabitEntry(userId, habitId, input)`: Idempotent upsert of completion entry for specified date, recalculates and updates `current_streak` and `longest_streak`.
- `toggleHabitEntry(userId, habitId, date)`: Single-click toggle: removes entry if present, creates entry if absent. Recalculates and updates streaks.
- `deleteHabitEntry(userId, habitId, date)`: Removes completion for date and updates streaks.
- `getHabitHistory(userId, habitId, startDate, endDate)`: Retrieves calendar completion matrix for heatmaps and trend graphs.

### 5.2 API Routes
- `GET /api/habits`: List habits with streak metrics and today's status.
- `POST /api/habits`: Create new habit.
- `GET /api/habits/[id]`: Retrieve single habit with entry history.
- `PATCH /api/habits/[id]`: Update habit configuration.
- `DELETE /api/habits/[id]`: Delete habit.
- `POST /api/habits/[id]/entries`: Idempotent check-in entry creation.
- `POST /api/habits/[id]/toggle`: Single-click toggle check-in for a date.
- `DELETE /api/habits/[id]/entries`: Delete check-in entry for a date.
