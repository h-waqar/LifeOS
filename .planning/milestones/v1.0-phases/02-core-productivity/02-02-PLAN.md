# Plan 02-02: Goals & Projects Hierarchy with Multi-Horizon Tracking and Automated Progress Rollups

## 1. Plan Overview & Executive Context

- **Phase:** 2 — Core Productivity
- **Plan Identification:** 02-02
- **Domain:** Goals, Projects & Multi-Horizon Progress Rollups
- **Prerequisites:** Phase 1 Foundation conditionally accepted (Plan 01-09, Plan 01-10) and Phase 2 Plan 02-01 (Task Management Engine, Priority Scoring, Recurrence, Quick Capture) verified and closed.
- **Goal:** Deliver the multi-horizon goal planning hierarchy (Long-term, Medium-term, Short-term), key metric tracking, life area alignment, project-to-goal and task-to-project/goal links, project milestones, automated progress rollups, and project archival.
- **Requirements Satisfied:**
  - **GOAL-01**: Define hierarchical goals across horizons: Long-term (1-5 years), Medium-term (Quarterly/Annual), Short-term (Monthly).
  - **GOAL-02**: Define key metrics for goals (Numeric target, Currency target, Boolean milestone, Percentage).
  - **GOAL-03**: Goal progress automatically recalculates based on linked project progress, metric updates, and task completions.
  - **GOAL-04**: Link goals to life Areas (Health, Career, Finance, Personal Development, Relationships).
  - **PROJ-01**: Create projects with title, description, area, status (Planning, Active, Paused, Completed, Archived), target deadline, and linked goal.
  - **PROJ-02**: Project view displays linked tasks, milestones, progress percentage, notes, and documents in one unified view.
  - **PROJ-03**: Project progress updates automatically based on task and milestone completion.
  - **PROJ-04**: Archive completed or paused projects while preserving task and history links.
- **Key Architectural Principles:**
  - **Strict Composite Isolation:** Every relationship enforces composite foreign keys `(user_id, [parent/foreign]_id)` to guarantee zero cross-tenant leakage.
  - **No Duplicate Entry:** Tasks connect to projects and/or goals without duplicating task records.
  - **Deterministic Rollup Algorithms:** Pure mathematical rollup functions for milestones, tasks, metrics, and child goals.

## 3. Database Architecture & Migrations

### 3.1 New Table: `goals`
```sql
CREATE TABLE IF NOT EXISTS "goals" (
  "id" text PRIMARY KEY NOT NULL,
  "user_id" text NOT NULL,
  "title" text NOT NULL,
  "description" text,
  "horizon" text NOT NULL DEFAULT 'medium_term',
  "area" text NOT NULL DEFAULT 'general',
  "status" text NOT NULL DEFAULT 'in_progress',
  "priority" text NOT NULL DEFAULT 'medium',
  "metric_type" text NOT NULL DEFAULT 'none',
  "target_value" double precision,
  "current_value" double precision DEFAULT 0,
  "unit" text,
  "start_date" timestamp with time zone,
  "target_date" timestamp with time zone,
  "parent_goal_id" text,
  "progress" integer NOT NULL DEFAULT 0,
  "completed_at" timestamp with time zone,
  "created_at" timestamp with time zone DEFAULT now() NOT NULL,
  "updated_at" timestamp with time zone DEFAULT now() NOT NULL,
  CONSTRAINT "goals_user_id_id_unique" UNIQUE("user_id", "id"),
  CONSTRAINT "goals_parent_not_self" CHECK ("parent_goal_id" IS NULL OR "parent_goal_id" != "id"),
  CONSTRAINT "goals_title_non_empty" CHECK (length(trim("title")) > 0),
  CONSTRAINT "goals_title_max_length" CHECK (length("title") <= 255),
  CONSTRAINT "goals_description_max_length" CHECK ("description" IS NULL OR length("description") <= 4000),
  CONSTRAINT "goals_horizon_check" CHECK ("horizon" IN ('long_term', 'medium_term', 'short_term')),
  CONSTRAINT "goals_area_check" CHECK ("area" IN ('health', 'career', 'finance', 'personal_development', 'relationships', 'general')),
  CONSTRAINT "goals_status_check" CHECK ("status" IN ('not_started', 'in_progress', 'completed', 'paused', 'archived')),
  CONSTRAINT "goals_priority_check" CHECK ("priority" IN ('low', 'medium', 'high', 'critical')),
  CONSTRAINT "goals_metric_type_check" CHECK ("metric_type" IN ('none', 'numeric', 'currency', 'boolean', 'percentage')),
  CONSTRAINT "goals_progress_bounds" CHECK ("progress" >= 0 AND "progress" <= 100),
  CONSTRAINT "goals_completed_at_invariant" CHECK ("status" != 'completed' OR "completed_at" IS NOT NULL)
);
```

### 3.2 Extensions to `projects` Table
- `area`: text check constraint `('health', 'career', 'finance', 'personal_development', 'relationships', 'general')`.
- `start_date`: timestamp with time zone.
- `deadline`: timestamp with time zone.
- `goal_id`: text referencing `goals(user_id, id)` via composite FK on delete set null.

### 3.3 New Table: `project_milestones`
```sql
CREATE TABLE IF NOT EXISTS "project_milestones" (
  "id" text PRIMARY KEY NOT NULL,
  "user_id" text NOT NULL,
  "project_id" text NOT NULL,
  "title" text NOT NULL,
  "description" text,
  "target_date" timestamp with time zone,
  "status" text NOT NULL DEFAULT 'pending',
  "completed_at" timestamp with time zone,
  "sort_order" integer NOT NULL DEFAULT 0,
  "created_at" timestamp with time zone DEFAULT now() NOT NULL,
  "updated_at" timestamp with time zone DEFAULT now() NOT NULL,
  CONSTRAINT "project_milestones_user_id_id_unique" UNIQUE("user_id", "id"),
  CONSTRAINT "project_milestones_title_non_empty" CHECK (length(trim("title")) > 0),
  CONSTRAINT "project_milestones_status_check" CHECK ("status" IN ('pending', 'completed')),
  CONSTRAINT "project_milestones_completed_at_invariant" CHECK ("status" != 'completed' OR "completed_at" IS NOT NULL)
);
```

### 3.4 Extensions to `tasks` Table
- Composite FK on `(user_id, goal_id)` referencing `goals(user_id, id)` on delete set null.
- Add `milestone_id`: text referencing `project_milestones(user_id, id)` on delete set null.

### 3.5 PostgreSQL Cycle Prevention Trigger for Hierarchical Goals
A recursive CTE trigger function `check_goal_hierarchy_cycle()` and trigger `trg_goals_prevent_cycle` to prevent cycle deadlocks in goal trees (e.g., A -> B -> A).

## 4. Deterministic Progress Rollup Engine

The progress calculation engine is implemented as a pure TypeScript module (`src/server/goals/rollup.ts`):

1. **Project Progress Calculation ($P_{project}$):**
   - Let $N_{tasks}$ be total tasks linked to project, $C_{tasks}$ be completed tasks.
   - Let $N_{milestones}$ be total milestones, $C_{milestones}$ be completed milestones.
   - If project has tasks and milestones:
     $$P_{project} = \text{round}\left(0.5 \times \frac{C_{tasks}}{N_{tasks}} \times 100 + 0.5 \times \frac{C_{milestones}}{N_{milestones}} \times 100\right)$$
   - If only tasks: $P_{project} = \text{round}\left(\frac{C_{tasks}}{N_{tasks}} \times 100\right)$.
   - If only milestones: $P_{project} = \text{round}\left(\frac{C_{milestones}}{N_{milestones}} \times 100\right)$.
   - If neither: 100 if project status is `completed`, else 0.

2. **Goal Progress Calculation ($P_{goal}$):**
   - **Metric Component ($P_{metric}$):**
     - Boolean: $100$ if $current \ge target$, else $0$.
     - Numeric / Currency / Percentage: $\min\left(100, \max\left(0, \text{round}\left(\frac{current}{target} \times 100\right)\right)\right)$.
   - **Deliverables Component ($P_{deliv}$):**
     - Linked projects average progress: $\bar{P}_{proj}$.
     - Direct tasks progress (tasks with `goal_id` and no `project_id`): $\frac{C_{direct}}{N_{direct}} \times 100$.
     - Child goals average progress: $\bar{P}_{children}$.
     - Combine active deliverable categories with equal weight.
   - **Total Goal Progress:**
     - If metric defined and deliverables exist: $\text{round}\left(0.5 \times P_{metric} + 0.5 \times P_{deliv}\right)$.
     - If metric only: $P_{metric}$.
     - If deliverables only: $\text{round}(P_{deliv})$.
     - If neither: 100 if status is `completed`, else 0.
   - Status sync: if progress reaches 100% and status was `in_progress`, auto-complete; if status explicitly set to `completed`, progress is clamped to 100%.

## 5. Service & API Layer

### 5.1 Goals Service (`src/server/goals/service.ts`)
- `createGoal(userId, input)`: atomic transaction with validation and audit logging.
- `getGoal(userId, goalId)`: returns goal DTO with computed real-time progress, child goals count, linked projects count, direct tasks count.
- `listGoals(userId, filters)`: filters by horizon, area, status; includes real-time progress rollup.
- `updateGoal(userId, goalId, input)`: row-level lock, updates fields, recalculates progress, and triggers upward rollup to parent goals.
- `deleteGoal(userId, goalId)`: deletes goal; children set parentGoalId to null; projects and tasks set goalId to null.
- `recalculateGoalProgress(userId, goalId)`: cascades recalculation up the hierarchy tree.

### 5.2 Projects Service Extensions (`src/server/projects/service.ts`)
- Add support for `area`, `startDate`, `deadline`, `goalId` in `createProject` and `updateProject`.
- Include real-time progress rollup in `getProject` and `listProjects`.
- Milestones sub-service:
  - `addMilestone(userId, projectId, input)`
  - `updateMilestone(userId, projectId, milestoneId, input)`
  - `deleteMilestone(userId, projectId, milestoneId)`
  - `listMilestones(userId, projectId)`
  - Automatically triggers project and goal progress rollups.

### 5.3 API Endpoints
- `GET /api/goals`: List goals with filters (`horizon`, `area`, `status`).
- `POST /api/goals`: Create goal.
- `GET /api/goals/[id]`: Get goal details with hierarchy, linked projects, and tasks.
- `PATCH /api/goals/[id]`: Update goal fields / metric values.
- `DELETE /api/goals/[id]`: Delete goal.
- `GET, POST /api/projects/[id]/milestones`: List and create project milestones.
- `PATCH, DELETE /api/projects/[id]/milestones/[milestoneId]`: Update and delete project milestones.

## 8. Acceptance Criteria

2. User can define metrics (Numeric, Currency, Boolean, Percentage) and update current values with instant progress recalculation.
3. User can link goals to life Areas (Health, Career, Finance, Personal Development, Relationships).
4. User can nest goals into hierarchies without circular reference errors.
5. User can create projects linked to goals and assign target deadlines and areas.
6. User can manage project milestones and link tasks to projects.
7. Project progress automatically reflects task and milestone completion percentages.
8. Goal progress automatically rolls up linked project progress, task completions, metric updates, and child goal progress.
9. User can archive projects while retaining all task associations and historical links.
10. All operations are strictly user-isolated at both application and database foreign key levels.
11. Full test suite passes: unit tests, integration tests, TypeScript type checking (`tsc --noEmit`), and Next.js production build (`pnpm build`).
