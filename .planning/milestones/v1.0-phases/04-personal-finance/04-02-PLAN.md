# Plan 04-02: Monthly Budgets, Net Worth Computation, Financial Goal Linkage, and Progress Reports

## 1. Plan Overview & Executive Context

- **Phase:** 4 — Personal Finance
- **Plan Identification:** 04-02
- **Domain:** Category Budgets, Financial Goal Linkage, Net Worth, Cash Flow, and Savings Rate Engine
- **Prerequisites:** Phase 4 Plan 04-01 (Financial accounts, categories, and transaction ledger) implemented and verified. Phase 2 Goals & Projects Engine (`goals`, `src/server/goals/rollup.ts`) operational.
- **Goal:** Deliver the analytical and decision-support layer of LifeOS Personal Finance: monthly category budgets with real-time spending vs targets; bidirectional linkage between financial transactions / savings targets and Phase 2 Financial Goals (`area = 'finance'`); and a pure, 100% test-verified calculation engine computing Net Worth, Monthly Cash Flow, and Savings Rate in PKR without double-counting transfers.
- **Requirements Satisfied:**
  - `FIN-03`: Monthly category budgets displaying real-time spending vs monthly targets.
  - `FIN-04`: Link transactions or savings targets to Financial Goals.
  - `FIN-05`: Net worth, monthly cash flow, and savings rate calculations with 100% verified test math.
- **Key Architectural Constraints:**
  1. **Vertical-Slice Rule**: Schema additions in Plan 04-02 are strictly restricted to `finance_budgets`. No premature schemas for Phase 5 (content) or Phase 6 (AI).
  2. **100% Deterministic Financial Math**: All formulas for Net Worth, Cash Flow, Savings Rate, Budget Utilization, and Goal Progress are isolated in a pure TypeScript calculation module (`src/server/finance/calculations.ts`) with exhaustive unit tests covering zero-values, negative cash flow, edge cases, transfer exclusions, and floating-point precision bounds.
  3. **Zero Transfer Double-Counting**: Transfers between accounts are strictly excluded from monthly income, monthly expenses, category budget spending, and cash flow calculations.
  4. **Composite Tenant Isolation**: `finance_budgets` enforces composite uniqueness `(userId, categoryId, month)` and composite foreign key `(userId, categoryId) REFERENCES finance_categories(userId, id)`.
  5. **Direct Goal Integration without Duplication**: Transactions reference Phase 2 `goals(userId, id)` via composite FK `goalId`. When savings transactions are recorded, the linked goal's `currentValue` updates and triggers Phase 2's cascade progress rollup.
  6. **Clean Repository & Test Organization**: All tests reside strictly in `scripts/tests/phase-04/plan-02/`. Zero test files inside `src/`.

### 3.1 Table: `finance_budgets` (`src/server/db/schema/finance.ts`)

```typescript
import {
  pgTable,
  text,
  timestamp,
  numeric,
  unique,
  check,
  foreignKey,
  index,
} from "drizzle-orm/pg-core";
import { sql } from "drizzle-orm";
import { user } from "./auth";
import { financeCategories } from "./finance";

/**
 * Financial Budgets Table
 * Monthly spending targets per category.
 */
export const financeBudgets = pgTable(
  "finance_budgets",
  {
    id: text("id")
      .primaryKey()
      .$defaultFn(() => crypto.randomUUID()),
    userId: text("user_id")
      .notNull()
      .references(() => user.id, { onDelete: "cascade" }),
    categoryId: text("category_id").notNull(),
    month: text("month").notNull(), // Format: 'YYYY-MM'
    targetAmount: numeric("target_amount", { precision: 14, scale: 2 }).notNull(),
    currency: text("currency").notNull().default("PKR"),
    notes: text("notes"),
    createdAt: timestamp("created_at", { withTimezone: true })
      .notNull()
      .defaultNow(),
    updatedAt: timestamp("updated_at", { withTimezone: true })
      .notNull()
      .defaultNow(),
  },
  (table) => [
    unique("finance_budgets_user_id_id_unique").on(table.userId, table.id),
    unique("finance_budgets_user_category_month_unique").on(
      table.userId,
      table.categoryId,
      table.month
    ),
    foreignKey({
      name: "finance_budgets_user_category_fk",
      columns: [table.userId, table.categoryId],
      foreignColumns: [financeCategories.userId, financeCategories.id],
    }).onDelete("cascade"),
    check("finance_budgets_target_positive", sql`${table.targetAmount} > 0`),
    check(
      "finance_budgets_month_format",
      sql`${table.month} ~ '^\\d{4}-(0[1-9]|1[0-2])$'`
    ),
    index("finance_budgets_user_month_idx").on(table.userId, table.month),
    index("finance_budgets_user_category_idx").on(
      table.userId,
      table.categoryId
    ),
  ]
);

export type FinanceBudget = typeof financeBudgets.$inferSelect;
export type NewFinanceBudget = typeof financeBudgets.$inferInsert;
```

## 4. Pure Calculation Engine & Mathematical Specification

Location: `src/server/finance/calculations.ts`

### 4.1 Net Worth Calculation
$$\text{Net Worth} = \sum_{a \in \text{Assets}} \text{balance}(a) - \sum_{l \in \text{Liabilities}} \text{balance}(l)$$
- **Assets**: Accounts where `accountType` is `checking`, `savings`, `investment`, or `cash`.
- **Liabilities**: Accounts where `accountType` is `credit_card`.
- **Invariants**:
  - If a user has no accounts, $\text{Net Worth} = 0.00$.
  - Credit card balance represents current amount owed (liability).
  - Net Worth can be negative if liabilities exceed assets.

### 4.2 Monthly Cash Flow Calculation
$$\text{Cash Flow} = \text{Total Monthly Income} - \text{Total Monthly Expenses}$$
- $\text{Total Monthly Income} = \sum \{ t.\text{amount} \mid t.\text{type} = \text{'income'} \land t.\text{month} = M \}$
- $\text{Total Monthly Expenses} = \sum \{ t.\text{amount} \mid t.\text{type} = \text{'expense'} \land t.\text{month} = M \}$
- **Transfer Exclusion Rule**: Transactions where $t.\text{type} = \text{'transfer'}$ contribute exactly $0$ to both income and expenses.
- **Invariants**:
  - Cash flow is positive (surplus) when Income > Expenses.
  - Cash flow is negative (deficit) when Expenses > Income.
  - Cash flow is $0.00$ when no income and no expenses exist.

### 4.3 Savings Rate Calculation
$$\text{Savings Rate} = \begin{cases}
\text{round}\left(\frac{\text{Income} - \text{Expenses}}{\text{Income}} \times 100, 2\right) & \text{if Income} > 0 \\
0.00 & \text{if Income} \le 0
\end{cases}$$
- **Invariants**:
  - If $\text{Income} = 0$, Savings Rate is $0.00\%$ (guards against division by zero).
  - If $\text{Expenses} > \text{Income}$, Savings Rate is negative (e.g. $-25.50\%$).
  - If $\text{Expenses} = 0$ and $\text{Income} > 0$, Savings Rate is $100.00\%$.

### 4.4 Category Budget Utilization
$$\text{Spent} = \sum \{ t.\text{amount} \mid t.\text{type} = \text{'expense'} \land t.\text{categoryId} = C \land t.\text{month} = M \}$$
$$\text{Remaining} = \text{Target} - \text{Spent}$$
$$\text{Utilization} = \begin{cases}
\text{round}\left(\frac{\text{Spent}}{\text{Target}} \times 100, 1\right) & \text{if Target} > 0 \\
0.0 & \text{if Target} = 0
\end{cases}$$
$$\text{isOverBudget} = \text{Spent} > \text{Target}$$

### 4.5 Financial Rounding Behavior
All monetary values are rounded to 2 decimal places using deterministic financial rounding:
```typescript
export function roundMoney(amount: number): number {
  return Math.round((amount + Number.EPSILON) * 100) / 100;
}
```

## 5. Server & Service Architecture

### 5.1 Budget Service (`src/server/finance/budget-service.ts`)

- `upsertBudget(userId: string, input: UpsertBudgetInput): Promise<FinanceBudget>`
  - Inserts or updates budget for `(userId, categoryId, month)`.
  - Emits audit log event: `finance.budget.upserted`.
- `listBudgetsForMonth(userId: string, month: string): Promise<CategoryBudgetProgress[]>`
  - Queries all budgets for the month and joins category metadata.
  - Aggregates actual spending from `finance_transactions` in the same month.
  - Computes `spentAmount`, `remainingAmount`, `utilizationPercentage`, and `isOverBudget`.
- `copyBudgetsFromPreviousMonth(userId: string, targetMonth: string): Promise<{ copiedCount: number }>`
  - Fetches preceding month's budgets (`targetMonth - 1 month`) and copies to `targetMonth` for categories that do not already have a budget set.
  - Emits audit log event: `finance.budget.copied`.
- `deleteBudget(userId: string, budgetId: string): Promise<void>`
  - Emits audit log event: `finance.budget.deleted`.

### 5.2 Financial Reports Service (`src/server/finance/reports-service.ts`)

- `getFinanceSummary(userId: string, month: string): Promise<FinanceSummaryReport>`
  - Retrieves active accounts, calculates Net Worth.
  - Retrieves transactions for `month`, calculates Monthly Income, Expenses, Cash Flow, and Savings Rate.
  - Returns category spending breakdown sorted by total expenditure.
- `getNetWorthBreakdown(userId: string): Promise<NetWorthBreakdown>`
  - Returns total assets, total liabilities, net worth, and account-by-account breakdown.

### 5.3 Goal Linkage Service (`src/server/finance/goal-linkage-service.ts`)

- `syncFinancialGoalProgress(userId: string, goalId: string): Promise<void>`
  - Queries all transactions linked to `goalId`.
  - Sums contributions: `currentValue = sum(transactions with goalId)`.
  - Updates `goals.currentValue` where `id = goalId AND userId = userId`.
  - Invokes `recalculateGoalProgress(userId, goalId)` from Phase 2 to cascade progress percentage and milestone checks.
  - Emits audit log event: `finance.goal.progress_synced`.
- `listFinancialGoals(userId: string): Promise<FinancialGoalSummary[]>`
  - Queries Phase 2 goals where `area = 'finance'`.
  - Returns goal title, target value, current value, progress percentage, target date, and recent linked transactions.

## 6. API & Server Action Contracts

- `GET /api/finance/budgets?month=YYYY-MM` -> Returns array of `CategoryBudgetProgress`.
- `POST /api/finance/budgets` -> Accepts `{ categoryId, month, targetAmount, notes? }`; returns 200/201 with upserted budget.
- `DELETE /api/finance/budgets/[id]` -> Deletes budget; returns 200.
- `POST /api/finance/budgets/copy-previous` -> Accepts `{ targetMonth }`; copies previous month targets; returns `{ copiedCount }`.
- `GET /api/finance/reports/summary?month=YYYY-MM` -> Returns `{ netWorth, monthlyCashFlow, savingsRate, totalIncome, totalExpenses, categoryBreakdown }`.
- `GET /api/finance/goals` -> Returns list of financial goals with contribution totals and progress.

All endpoints enforce session authentication and composite user isolation. Unauthorized requests return 401.

## 8. Security, Authorization & Audit Logging Boundary

- **Session Ownership**: Every service and endpoint verifies `session.user.id`.
- **Tenant Isolation**: `finance_budgets` strictly filters and joins on `user_id`.
- **Goal Cross-Tenant Protection**: Transaction goal linkage verifies that `goals.user_id == transaction.user_id` via composite foreign key `(userId, goalId) REFERENCES goals(userId, id)`.
- **Audit Logging**: Every budget creation, update, deletion, and goal sync logs to `audit_log`.

  - Deficit: Income (50,000 PKR) - Expenses (80,000 PKR) = -30,000 PKR.

  - Normal surplus: Income 100,000, Expenses 40,000 -> Savings Rate = 60.00%.
