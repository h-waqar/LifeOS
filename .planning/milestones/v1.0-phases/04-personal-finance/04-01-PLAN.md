# Plan 04-01: Financial Accounts, Categories, and Transaction Ledger with Transfer Handling

## 1. Plan Overview & Executive Context

- **Phase:** 4 — Personal Finance
- **Plan Identification:** 04-01
- **Domain:** Accounts, Categories, and Transaction Ledger with Multi-Account Transfer Handling
- **Prerequisites:** Phase 1 Foundation, Phase 2 Core Productivity, and Phase 3 Knowledge, Learning & Relationships verified on `main` (commit `99bc07f`). PostgreSQL database with Drizzle ORM, Better Auth session authentication, server-side resource ownership authorization via authenticated `user_id`, composite tenant isolation, and audit logging are operational.
- **Goal:** Deliver the private financial ledger foundation of LifeOS: manage user-owned financial accounts (Checking, Savings, Investments, Credit Cards, Cash) with opening balances; maintain category taxonomy with system seed defaults (income and expense); record income, expense, and transfer transactions with atomic balance updates; enforce strict multi-account transfer integrity without double-counting; and provide an intuitive `/finance` UI shell with account cards, transaction table, and quick modals.
- **Requirements Satisfied:**
  - `FIN-01`: User can manage financial accounts (Checking, Savings, Investments, Credit Cards) and balances.
  - `FIN-02`: User can record income, expense, and transfer transactions with date, payee, amount, category, and account.
- **Key Architectural Constraints:**
  1. **Vertical-Slice Rule**: Introduce only schemas and migrations required for accounts, categories, and transactions (`finance_accounts`, `finance_categories`, `finance_transactions`). Monthly budgets (`finance_budgets`), net worth history snapshots, and advanced financial goal reports belong strictly to Plan 04-02.
  2. **Composite Tenant Isolation**: Every financial entity row is partitioned by `user_id`. Composite foreign keys enforce that transfers reference two accounts owned by the same user: `(user_id, account_id)` and `(user_id, to_account_id)` referencing `finance_accounts(user_id, id)`.
  3. **Simplified Single-Entry Ledger with Transfers**: Avoid over-engineered double-entry accounting per PRD Section 16 ("awareness and decision support, not accounting software"). Transactions have types `income`, `expense`, and `transfer`. Transfers atomically debit source account and credit destination account within an ACID transaction (`db.transaction`).
  4. **PKR Currency Foundation**: Initial currency default is `"PKR"`. All account and transaction records store an ISO currency code, defaulting to `"PKR"`, with exact 2-decimal precision (`numeric(14, 2)`).
  5. **Clean Repository & Test Organization**: All tests reside strictly in `scripts/tests/phase-04/plan-01/`. Zero test files inside `src/`.

## 3. Database Architecture & Vertical-Slice Schema Evolution

All database changes for Plan 04-01 begin at migration `0016_personal_finance.sql` in `src/server/db/migrations/`.

### 3.1 New Schema File: `src/server/db/schema/finance.ts`

```typescript
import {
  pgTable,
  text,
  timestamp,
  numeric,
  boolean,
  unique,
  check,
  foreignKey,
  index,
  jsonb,
} from "drizzle-orm/pg-core";
import { sql } from "drizzle-orm";
import { user } from "./auth";
import { goals } from "./goals";

/**
 * Financial Accounts Table
 * Represents user accounts: checking, savings, investment, credit_card, cash.
 */
export const financeAccounts = pgTable(
  "finance_accounts",
  {
    id: text("id")
      .primaryKey()
      .$defaultFn(() => crypto.randomUUID()),
    userId: text("user_id")
      .notNull()
      .references(() => user.id, { onDelete: "cascade" }),
    name: text("name").notNull(),
    accountType: text("account_type", {
      enum: ["checking", "savings", "investment", "credit_card", "cash"],
    }).notNull(),
    currency: text("currency").notNull().default("PKR"),
    initialBalance: numeric("initial_balance", { precision: 14, scale: 2 })
      .notNull()
      .default("0.00"),
    balance: numeric("balance", { precision: 14, scale: 2 })
      .notNull()
      .default("0.00"),
    color: text("color"),
    icon: text("icon"),
    isArchived: boolean("is_archived").notNull().default(false),
    createdAt: timestamp("created_at", { withTimezone: true })
      .notNull()
      .defaultNow(),
    updatedAt: timestamp("updated_at", { withTimezone: true })
      .notNull()
      .defaultNow(),
  },
  (table) => [
    unique("finance_accounts_user_id_id_unique").on(table.userId, table.id),
    check(
      "finance_accounts_name_non_empty",
      sql`length(trim(${table.name})) > 0`
    ),
    check(
      "finance_accounts_type_check",
      sql`${table.accountType} IN ('checking', 'savings', 'investment', 'credit_card', 'cash')`
    ),
    index("finance_accounts_user_idx").on(table.userId),
    index("finance_accounts_user_archived_idx").on(
      table.userId,
      table.isArchived
    ),
  ]
);

/**
 * Financial Categories Table
 * Income and expense categories.
 */
export const financeCategories = pgTable(
  "finance_categories",
  {
    id: text("id")
      .primaryKey()
      .$defaultFn(() => crypto.randomUUID()),
    userId: text("user_id")
      .notNull()
      .references(() => user.id, { onDelete: "cascade" }),
    name: text("name").notNull(),
    categoryType: text("category_type", {
      enum: ["expense", "income"],
    }).notNull(),
    icon: text("icon"),
    color: text("color"),
    isArchived: boolean("is_archived").notNull().default(false),
    isSystem: boolean("is_system").notNull().default(false),
    createdAt: timestamp("created_at", { withTimezone: true })
      .notNull()
      .defaultNow(),
    updatedAt: timestamp("updated_at", { withTimezone: true })
      .notNull()
      .defaultNow(),
  },
  (table) => [
    unique("finance_categories_user_id_id_unique").on(table.userId, table.id),
    unique("finance_categories_user_name_type_unique").on(
      table.userId,
      table.name,
      table.categoryType
    ),
    check(
      "finance_categories_name_non_empty",
      sql`length(trim(${table.name})) > 0`
    ),
    check(
      "finance_categories_type_check",
      sql`${table.categoryType} IN ('expense', 'income')`
    ),
    index("finance_categories_user_idx").on(table.userId),
    index("finance_categories_user_type_idx").on(
      table.userId,
      table.categoryType
    ),
  ]
);

/**
 * Financial Transactions Table
 * Income, expense, and transfer records.
 */
export const financeTransactions = pgTable(
  "finance_transactions",
  {
    id: text("id")
      .primaryKey()
      .$defaultFn(() => crypto.randomUUID()),
    userId: text("user_id")
      .notNull()
      .references(() => user.id, { onDelete: "cascade" }),
    accountId: text("account_id").notNull(),
    toAccountId: text("to_account_id"),
    transactionType: text("transaction_type", {
      enum: ["income", "expense", "transfer"],
    }).notNull(),
    amount: numeric("amount", { precision: 14, scale: 2 }).notNull(),
    currency: text("currency").notNull().default("PKR"),
    date: timestamp("date", { withTimezone: true }).notNull(),
    categoryId: text("categoryId"),
    payee: text("payee"),
    description: text("description"),
    goalId: text("goal_id"),
    tags: jsonb("tags")
      .$type<string[]>()
      .notNull()
      .default(sql`'[]'::jsonb`),
    createdAt: timestamp("created_at", { withTimezone: true })
      .notNull()
      .defaultNow(),
    updatedAt: timestamp("updated_at", { withTimezone: true })
      .notNull()
      .defaultNow(),
  },
  (table) => [
    unique("finance_transactions_user_id_id_unique").on(table.userId, table.id),
    foreignKey({
      name: "finance_transactions_user_account_fk",
      columns: [table.userId, table.accountId],
      foreignColumns: [financeAccounts.userId, financeAccounts.id],
    }).onDelete("cascade"),
    foreignKey({
      name: "finance_transactions_user_to_account_fk",
      columns: [table.userId, table.toAccountId],
      foreignColumns: [financeAccounts.userId, financeAccounts.id],
    }).onDelete("cascade"),
    foreignKey({
      name: "finance_transactions_user_category_fk",
      columns: [table.userId, table.categoryId],
      foreignColumns: [financeCategories.userId, financeCategories.id],
    }).onDelete("set null"),
    foreignKey({
      name: "finance_transactions_user_goal_fk",
      columns: [table.userId, table.goalId],
      foreignColumns: [goals.userId, goals.id],
    }).onDelete("set null"),
    check("finance_transactions_amount_positive", sql`${table.amount} > 0`),
    check(
      "finance_transactions_type_check",
      sql`${table.transactionType} IN ('income', 'expense', 'transfer')`
    ),
    check(
      "finance_transactions_transfer_invariants",
      sql`(${table.transactionType} != 'transfer' AND ${table.toAccountId} IS NULL) OR (${table.transactionType} = 'transfer' AND ${table.toAccountId} IS NOT NULL AND ${table.toAccountId} != ${table.accountId})`
    ),
    index("finance_transactions_user_date_idx").on(table.userId, table.date),
    index("finance_transactions_user_account_idx").on(
      table.userId,
      table.accountId
    ),
    index("finance_transactions_user_type_idx").on(
      table.userId,
      table.transactionType
    ),
    index("finance_transactions_user_category_idx").on(
      table.userId,
      table.categoryId
    ),
  ]
);

export type FinanceAccount = typeof financeAccounts.$inferSelect;
export type NewFinanceAccount = typeof financeAccounts.$inferInsert;
export type FinanceCategory = typeof financeCategories.$inferSelect;
export type NewFinanceCategory = typeof financeCategories.$inferInsert;
export type FinanceTransaction = typeof financeTransactions.$inferSelect;
export type NewFinanceTransaction = typeof financeTransactions.$inferInsert;
```

## 4. Server & Service Architecture

### 4.1 Account Service (`src/server/finance/account-service.ts`)

- `createAccount(userId: string, input: CreateAccountInput): Promise<FinanceAccount>`
  - Runs in ACID transaction: inserts `finance_accounts` with `balance = input.initialBalance`.
  - Emits audit log event: `finance.account.created`.
- `listAccounts(userId: string, options?: { includeArchived?: boolean }): Promise<FinanceAccount[]>`
  - Returns accounts ordered by `isArchived ASC, createdAt ASC`.
- `getAccountById(userId: string, accountId: string): Promise<FinanceAccount | null>`
- `updateAccount(userId: string, accountId: string, input: UpdateAccountInput): Promise<FinanceAccount>`
  - Disallows modifying initial balance if transactions exist, or recalculates balance delta.
  - Emits audit log event: `finance.account.updated`.
- `archiveAccount(userId: string, accountId: string): Promise<FinanceAccount>`
  - Soft-archives account; preserves all historical transactions.
  - Emits audit log event: `finance.account.archived`.
- `deleteAccount(userId: string, accountId: string): Promise<void>`
  - Disallowed if active transactions exist (returns error recommending archival); deletes only if zero transactions exist.
  - Emits audit log event: `finance.account.deleted`.

### 4.2 Category Service (`src/server/finance/category-service.ts`)

- `seedDefaultCategories(userId: string): Promise<void>`
  - Seeds PRD Section 16 defaults if user has no categories:
    - Expense: `Food`, `Transport`, `Hardware`, `Software`, `Entertainment`, `Education`, `Business`, `Bills`, `Other`
    - Income: `Salary`, `Freelance`, `Investment`, `Gift`, `Other Income`
  - Marked with `isSystem = true`.
- `listCategories(userId: string, options?: { type?: 'expense' | 'income', includeArchived?: boolean }): Promise<FinanceCategory[]>`
- `createCategory(userId: string, input: CreateCategoryInput): Promise<FinanceCategory>`
  - Emits audit log event: `finance.category.created`.
- `updateCategory(userId: string, categoryId: string, input: UpdateCategoryInput): Promise<FinanceCategory>`
  - Emits audit log event: `finance.category.updated`.
- `archiveCategory(userId: string, categoryId: string): Promise<FinanceCategory>`
  - Emits audit log event: `finance.category.archived`.

### 4.3 Transaction Ledger Service (`src/server/finance/transaction-service.ts`)

- `createTransaction(userId: string, input: CreateTransactionInput): Promise<FinanceTransaction>`
  - Runs in `db.transaction`:
    1. Validates account ownership: verifies `accountId` (and `toAccountId` if transfer) belongs to `userId`.
    2. Inserts `finance_transactions` row.
    3. Updates account balance(s):
       - If `income`: increases `accountId.balance` by `+amount`.
       - If `expense`: decreases `accountId.balance` by `-amount`.
       - If `transfer`: decreases `accountId.balance` by `-amount`, increases `toAccountId.balance` by `+amount`.
    4. Emits audit log event: `finance.transaction.created`.
- `listTransactions(userId: string, filters: TransactionFilters): Promise<{ transactions: FinanceTransaction[]; total: number }>`
  - Filters: `accountId`, `categoryId`, `transactionType`, `startDate`, `endDate`, `search` (payee/description), `limit`, `offset`.
- `getTransactionById(userId: string, transactionId: string): Promise<FinanceTransaction | null>`
- `updateTransaction(userId: string, transactionId: string, input: UpdateTransactionInput): Promise<FinanceTransaction>`
  - Runs in `db.transaction`:
    1. Reverses previous transaction's balance effects on previous account(s).
    2. Updates transaction fields.
    3. Applies new transaction's balance effects on new account(s).
    4. Emits audit log event: `finance.transaction.updated`.
- `deleteTransaction(userId: string, transactionId: string): Promise<void>`
  - Runs in `db.transaction`:
    1. Reverses transaction's balance effects.
    2. Deletes row.
    3. Emits audit log event: `finance.transaction.deleted`.

### 4.4 Validation Schemas (`src/server/finance/validation.ts`)

- `createAccountSchema`: name (min 1, max 100), accountType enum, currency (default "PKR"), initialBalance (numeric string or number >= 0), color, icon.
- `updateAccountSchema`: partial of createAccountSchema + isArchived.
- `createCategorySchema`: name (min 1, max 100), categoryType enum (`expense` | `income`), color, icon.
- `updateCategorySchema`: name, color, icon, isArchived.
- `createTransactionSchema`: accountId (uuid), toAccountId (optional uuid), transactionType enum (`income` | `expense` | `transfer`), amount (positive number), currency (default "PKR"), date (ISO string/timestamp), categoryId (optional uuid), payee (optional string), description (optional string), goalId (optional uuid), tags (array of strings).
- `updateTransactionSchema`: partial of createTransactionSchema.
- `listTransactionsQuerySchema`: pagination & filter query params.

## 5. API & Server Action Contracts

- `GET /api/finance/accounts` -> Returns array of `FinanceAccount`.
- `POST /api/finance/accounts` -> Accepts `createAccountSchema`; returns 201 with created account.
- `PATCH /api/finance/accounts/[id]` -> Accepts `updateAccountSchema`; returns updated account.
- `DELETE /api/finance/accounts/[id]` -> Deletes empty account or archives; returns 200.
- `GET /api/finance/categories` -> Returns array of `FinanceCategory` (auto-seeds defaults on first call).
- `POST /api/finance/categories` -> Accepts `createCategorySchema`; returns 201 with created category.
- `PATCH /api/finance/categories/[id]` -> Accepts `updateCategorySchema`; returns updated category.
- `GET /api/finance/transactions` -> Accepts query parameters; returns `{ transactions, total }`.
- `POST /api/finance/transactions` -> Accepts `createTransactionSchema`; returns 201 with created transaction.
- `PATCH /api/finance/transactions/[id]` -> Accepts `updateTransactionSchema`; returns updated transaction.
- `DELETE /api/finance/transactions/[id]` -> Deletes transaction and reverts balance; returns 200.

All endpoints require session authentication via `await auth.api.getSession()`. Unauthorized requests return 401.

## 7. Security, Authorization & Audit Logging Boundary

- **Session Authentication**: Every endpoint extracts `session.user.id`. No client-provided `userId` is trusted.
- **Resource Ownership Authorization**: Queries enforce composite isolation `(userId, id)`. Cross-user access returns 404 or 403.
- **Audit Logging**: Every mutating action calls `recordAuditLog({ userId, action, entityType: 'finance_account' | 'finance_category' | 'finance_transaction', entityId, details })`.

## 9. Acceptance Criteria

1. User can create, edit, archive, and view accounts across all 5 supported types (`checking`, `savings`, `investment`, `credit_card`, `cash`) with opening balances in PKR.
2. System auto-seeds standard default categories and allows creating custom expense/income categories.
3. User can record an income transaction; the target account balance increases by the transaction amount.
4. User can record an expense transaction; the target account balance decreases by the transaction amount.
5. User can record a transfer transaction; source account decreases and destination account increases by the exact same amount with zero net worth change.
6. Transfers between accounts belonging to different users are strictly blocked at database and application layers.
7. Updating or deleting a transaction updates or reverses the account balances atomically in PostgreSQL.
8. Every mutating action generates an immutable audit log entry.
9. All tests pass in `scripts/tests/phase-04/plan-01/` with 0 TypeScript errors and clean build.
