- **Phase:** 3 — Knowledge, Learning & Relationships

- **Prerequisites:** Phase 2 Core Productivity, Phase 3 Plan 03-01 (Markdown Notes), and Plan 03-02 (Relationships / People CRM) verified and merged on `main`.
- **Goal:** Deliver native, production-grade PostgreSQL full-text and fuzzy trigram search across all 5 implemented vertical-slice entities (Notes, Tasks, Projects, Goals, People), exposed via a unified `/api/search` endpoint and seamlessly integrated into the global Command Palette (`Cmd+K` / `Ctrl+K`) with debouncing, cross-domain grouping, keyboard navigation, and deep linking.

  - `NOTE-05`: User can perform instant full-text search across all notes, tasks, projects, goals, and people using PostgreSQL full-text indexing.

- **Key Architectural Constraints:**
  - **PostgreSQL-Native Primitives**: Leverage `to_tsvector`, `websearch_to_tsquery`, `ts_rank_cd`, `pg_trgm` extension with GIN indexes (`gin_trgm_ops`), and similarity scoring. No naive `SELECT * -> JS filter` anti-pattern.

  - **Lifecycle & Soft-Delete Semantics**: Filter out archived notes (`is_archived = false`), cancelled tasks (`status != 'cancelled'`), archived projects (`status != 'archived'`), archived goals (`status != 'archived'`), and archived contacts (`is_archived = false`).
  - **Unified Normalized API Contract**: Clean DTO structure (`SearchResultDTO`) with consistent `id`, `type`, `title`, `subtitle`, `href`, `score`, and domain-specific `metadata`.
  - **Test Organization**: All test files MUST reside in `scripts/tests/phase-03/plan-03/`. No test files inside `src/`.

## 3. Database Architecture & Vertical-Slice Schema Evolution

### 3.1 Migration: `0014_postgresql_full_text_search.sql`

1. **Enable PostgreSQL Extension**:
   ```sql
   CREATE EXTENSION IF NOT EXISTS pg_trgm;
   ```

2. **GIN Trigram Indexes for Fuzzy/Partial Matching**:
   - `notes`: `CREATE INDEX IF NOT EXISTS notes_title_trgm_idx ON notes USING gin (title gin_trgm_ops);`
   - `tasks`: `CREATE INDEX IF NOT EXISTS tasks_title_trgm_idx ON tasks USING gin (title gin_trgm_ops);`
   - `projects`: `CREATE INDEX IF NOT EXISTS projects_name_trgm_idx ON projects USING gin (name gin_trgm_ops);`
   - `goals`: `CREATE INDEX IF NOT EXISTS goals_title_trgm_idx ON goals USING gin (title gin_trgm_ops);`
   - `people`: `CREATE INDEX IF NOT EXISTS people_name_trgm_idx ON people USING gin (name gin_trgm_ops);`
   - `people`: `CREATE INDEX IF NOT EXISTS people_company_trgm_idx ON people USING gin (company gin_trgm_ops);`

3. **GIN Full-Text Search Functional Indexes**:
   - `notes`: `CREATE INDEX IF NOT EXISTS notes_fts_idx ON notes USING gin (to_tsvector('english', coalesce(title, '') || ' ' || coalesce(content, '')));`
   - `tasks`: `CREATE INDEX IF NOT EXISTS tasks_fts_idx ON tasks USING gin (to_tsvector('english', coalesce(title, '') || ' ' || coalesce(description, '')));`
   - `projects`: `CREATE INDEX IF NOT EXISTS projects_fts_idx ON projects USING gin (to_tsvector('english', coalesce(name, '') || ' ' || coalesce(description, '')));`
   - `goals`: `CREATE INDEX IF NOT EXISTS goals_fts_idx ON goals USING gin (to_tsvector('english', coalesce(title, '') || ' ' || coalesce(description, '')));`
   - `people`: `CREATE INDEX IF NOT EXISTS people_fts_idx ON people USING gin (to_tsvector('english', coalesce(name, '') || ' ' || coalesce(company, '') || ' ' || coalesce(role, '') || ' ' || coalesce(notes, '')));`

## 4. Search Service Architecture

### 4.1 Normalized Contract (`src/types/index.ts` / `src/server/search/types.ts`)
```typescript
export type SearchEntityType = "note" | "task" | "project" | "goal" | "person";

export interface SearchResultItem {
  id: string;
  type: SearchEntityType;
  title: string;
  subtitle?: string;
  snippet?: string;
  href: string;
  score: number;
  metadata?: Record<string, unknown>;
  updatedAt: string;
}

export interface SearchResponseDTO {
  query: string;
  results: SearchResultItem[];
  total: number;
  byType: Record<SearchEntityType, number>;
}
```

### 4.2 Query Strategy
For an input query `q`:
- Validate input with Zod (`searchQuerySchema`): minimum 1 character, max 200 characters, trimmed, sanitized.
- Construct parameterized SQL using `to_tsvector('english', ...) @@ websearch_to_tsquery('english', ${q})` or prefix `to_tsquery('english', ${prefixQuery})`, combined with `similarity(title, ${q}) > 0.15` or `title ILIKE ${'%' + q + '%'}`.
- Calculate composite score:
  - Exact match (`LOWER(title) = LOWER(q)`): +10.0
  - Prefix match (`title ILIKE q%`): +5.0
  - FTS relevance rank (`ts_rank_cd(..., websearch_to_tsquery(...))`): +3.0 * rank
  - Trigram similarity (`similarity(...)`): +2.0 * sim
- Enforce per-entity limit (e.g., up to 10 per type, total 50) and sort by composite score descending.

## 5. REST API Architecture

### `GET /api/search`
- Query parameters:
  - `q`: Search query string (required, min 1, max 200)
  - `type`: Optional filter by entity type (`note`, `task`, `project`, `goal`, `person`, or `all`)
  - `limit`: Optional max results (default: 20, max: 100)
- Enforces session authentication via `requireAuthenticatedUser`.
- Returns `SearchResponseDTO`.
