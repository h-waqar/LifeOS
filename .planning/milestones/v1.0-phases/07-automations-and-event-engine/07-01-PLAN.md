## 1. Objective

Deliver a strongly typed, in-process, asynchronous Event Bus that decouples domain mutations from downstream consumers. Implement canonical event publishers across all core LifeOS domains (Tasks, Goals, Projects, Habits, Finance, Content, AI, System) that emit events strictly after successful database commits, with full tenant isolation, error boundary isolation, and execution recursion limits.

## 4. Detailed Implementation Specification

### 4.1 Event System Core (`src/server/events/types.ts` & `event-bus.ts`)
1. **Base Event Contract:**
   ```typescript
   export interface BaseDomainEvent<TName extends string, TPayload> {
     id: string; // crypto.randomUUID()
     name: TName;
     userId: string;
     timestamp: string; // ISO 8601
     payload: TPayload;
     metadata?: {
       correlationId?: string;
       depth?: number;
       actor?: string;
     };
   }
   ```
2. **Event Bus API:**
   - `publish<T extends DomainEventName>(event: DomainEvent<T>): Promise<void>`
     - Enforces `event.userId` presence.
     - Checks `event.metadata?.depth ?? 0`. If `depth >= 3`, halts propagation and logs security warning to `audit_log` (`system.recursion_limit_exceeded`).
     - Dispatches to matched topic subscribers and wildcard subscribers concurrently via `Promise.allSettled`.
     - Catches and logs subscriber errors without throwing to caller.
   - `subscribe<T extends DomainEventName>(eventName: T, handler: (event: DomainEvent<T>) => Promise<void> | void): () => void`
     - Returns unsubscribe cleanup function.
   - `subscribeAll(handler: (event: AnyDomainEvent) => Promise<void> | void): () => void`
     - Used by the Rule Engine and Audit loggers.
   - `clearSubscribers(): void` (utility for test isolation).

### 4.2 Post-Commit Event Emission Pattern
To guarantee zero phantom events:
- In routines utilizing `db.transaction`, domain events are accumulated in a local array: `const pendingEvents: AnyDomainEvent[] = [];`.
- Immediately following transaction commit, events are flushed:
  ```typescript
  for (const event of pendingEvents) {
    void eventBus.publish(event);
  }
  ```

## 5. Security & Invariants

1. **User Scoping:** Every domain event must include a valid `userId`. Handlers must never process events across user boundaries.
2. **Fail-Safe Dispatch:** A catastrophic error in a subscriber (e.g. malformed notification) must never roll back or fail the originating domain service mutation.
3. **Loop Prevention:** Maximum event cascade depth is clamped to 3.

## 6. Testing Strategy

All tests strictly placed in `scripts/tests/phase-07/plan-01/`.

### Unit Tests (`scripts/tests/phase-07/plan-01/event-bus.test.ts`):
- Subscribes and receives matching events.
- Does not receive non-matching event topics.
- Wildcard subscriber receives all events.
- Handles multiple concurrent subscribers cleanly.
- Error isolation: failing subscriber does not prevent other subscribers from executing.
- Recursion depth limit: events with `depth >= 3` are rejected.
- Unsubscribe function stops delivery.

### Integration Tests (`scripts/tests/phase-07/plan-01/domain-publishers.integration.test.ts`):
- `createTask` publishes `task.created` with correct task payload.
- `updateTask` to `completed` publishes `task.completed`.
- `createGoal` and `recalculateGoalProgress` publish goal events.
- `logHabitEntry` publishes `habit.logged`.
- `createTransaction` publishes `finance.transaction_created`.
- Rolled-back database transaction does NOT emit phantom events.
