## 1. Objective

Build the core Trigger-Condition-Action Automation Rule Engine. Implement a pure, deterministic condition evaluator with comprehensive operators and dot-notation path extraction. Implement the bounded action executor that dispatches actions strictly through canonical domain services without raw SQL. Enforce loop detection, maximum recursion limits, execution timers, and immutable run history in `automation_runs`. Provide REST APIs for automation CRUD and rule testing.

## 4. Detailed Implementation Specification

### 4.1 Condition Evaluator (`src/server/automations/condition-evaluator.ts`)
- Pure TypeScript function: `evaluateConditionGroup(context: Record<string, unknown>, group: ConditionGroup): boolean`.
- Dot-notation extraction: `getNestedValue(obj, "task.priority")` safely extracts nested properties.
- Operators supported:
  - `equals`, `not_equals`
  - `greater_than`, `greater_than_or_equal`, `less_than`, `less_than_or_equal`
  - `contains`, `not_contains`
  - `in`, `not_in`
  - `is_empty`, `is_not_empty`
  - `starts_with`, `ends_with`
- Type coercions handled safely (e.g. numeric strings compared to numbers).

### 4.2 Action Executor (`src/server/automations/action-executor.ts`)
- Dispatches based on `actionType`:
  1. `create_notification`: Calls `createNotification(userId, config)`.
  2. `create_task`: Calls `createTask(userId, config)`.
  3. `update_task`: Calls `updateTask(userId, taskId, updates)`.
  4. `update_project`: Calls `updateProject(userId, projectId, updates)`.
  5. `log_audit`: Calls `createAuditLog(...)`.
  6. `trigger_ai_suggestions`: Calls proactive AI generators.
- Parameter interpolation: Allows templates like `"Task completed: {{task.title}}"`.
- Strict domain invariants: Never execute raw SQL; mutations pass through validation schemas and audit logging.

### 4.3 Engine Lifecycle & Recursion Guard (`src/server/automations/engine.ts`)
1. On Event Bus dispatch:
   - Extract `userId`, `eventName`, `metadata.depth ?? 0`.
   - If `depth >= 3`: Abort execution, log `status: "failed"` with error `"MAX_DEPTH_EXCEEDED"`, emit audit alert.
2. Query active rules:
   - `SELECT * FROM automations WHERE user_id = ? AND is_active = true AND trigger_type = 'event' AND trigger_config->>'eventName' = ?`.
3. For each matching rule:
   - Evaluate conditions against event context.
   - If match: Start performance timer (`performance.now()`).
   - Execute action with `depth: depth + 1`.
   - Record `automation_runs` row with duration, status (`success` or `failed`), context snapshot, action output, and error message.
   - Increment `executionCount` on the automation rule.

## 5. Security & Invariants

1. **Service Boundaries:** Automation engine cannot bypass domain validation or auth guards.
2. **Infinite Loop Defense:** Max depth strictly enforced.
3. **Audit Trail:** Every automation execution logs both an `automation_runs` record and an `audit_log` event.

## 6. Testing Strategy

All tests strictly placed in `scripts/tests/phase-07/plan-03/`.

### Unit Tests (`scripts/tests/phase-07/plan-03/condition-evaluator.test.ts`):
- Evaluates equality, numeric comparisons, array inclusion, and null checks.
- Evaluates combined `AND` / `OR` condition groups.
- Safely handles missing or undefined nested fields.
- Correctly resolves template string interpolation (`{{task.title}}`).

### Integration Tests (`scripts/tests/phase-07/plan-03/automation-engine.integration.test.ts`):
- Emitting `task.completed` triggers configured automation and creates notification.
- Emitting `task.completed` when all project tasks are done updates project status to `completed`.
- Inactive rules are ignored.
- Rules with non-matching conditions are skipped (`status: "skipped"` or not executed).
- Recursion loop is detected and halted at depth 3.
- `automation_runs` stores accurate execution duration and context snapshot.
- Endpoints `/api/automations` enforce authenticated user ownership.
