## 4. Detailed Implementation Specification

### 4.1 Automations Dashboard (`src/app/(dashboard)/automations/page.tsx`)
- Metrics summary cards:
  - Total Rules, Active Automations, Total Executions (24h), Failed Runs.
- Search and filter bar (filter by active/inactive, trigger type: Event vs Schedule).
- "New Automation" primary button triggering `RuleBuilderModal`.

### 4.2 Interactive Rule Builder Modal (`rule-builder-modal.tsx`)
1. **Trigger Step:**
   - Dropdown of supported triggers:
     - "When a task is completed" (`task.completed`)
     - "When a task is created" (`task.created`)
     - "When a task is overdue" (`task.overdue`)
     - "When all project tasks are completed" (`project.all_tasks_completed`)
     - "When a habit is logged" (`habit.logged`)
     - "When a goal progress updates" (`goal.progress_updated`)
     - "When goal is stagnant for 14 days" (`goal.stagnant`)
     - "Every morning (8:00 AM)" (`system.morning_routine_due`)
     - "Every evening (9:00 PM)" (`system.evening_review_due`)
2. **Condition Step:**
   - Add/Remove condition rows.
   - Field selector mapped to trigger context (e.g. `priority`, `status`, `streak`).
   - Operator selector (`equals`, `greater_than`, `contains`, `is_empty`, etc.).
   - Value input with type-appropriate UI (dropdown for priority/status, number input for streak/progress, text for tags/title).
   - "Match ALL conditions (AND)" vs "Match ANY condition (OR)" toggle.
3. **Action Step:**
   - Action type:
     - "Send In-App Notification" (configure title, message, type)
     - "Create Follow-up Task" (configure task title, priority, due offset)
     - "Mark Project as Completed"
     - "Trigger AI Planning Suggestions"
4. **Validation & Dry Run:**
   - "Test Rule" button sends mock event to `/api/automations/test` to preview evaluation without mutating data.

### 4.3 Run History Inspector (`run-history-drawer.tsx`)
- Slide-over sheet showing recent runs for the selected automation.
- Detailed card for each run:
  - Status badge: `Success` (Green), `Failed` (Red), `Skipped` (Gray).
  - Relative timestamp ("5 minutes ago") and duration ("14ms").
  - Triggering event name.
  - Expandable JSON viewers for `Context Snapshot` and `Action Output`.
  - Stack trace / error message if status is `failed`.

## 6. Testing Strategy

All tests strictly placed in `scripts/tests/phase-07/plan-05/`.

### Unit / Component Tests (`scripts/tests/phase-07/plan-05/automations-ui.test.tsx`):
- Renders automations list with status badges and metrics.

- Opens Rule Builder modal and validates required fields.

- Displays Run History drawer with formatted JSON snapshots.

### End-to-End Integration Tests (`scripts/tests/phase-07/plan-05/e2e-automations.integration.test.ts`):
- Complete user journey:
  1. Create automation via API/UI: "When task completed with priority high → send notification".
  2. Complete high-priority task via `updateTask`.
  3. Verify automation executes, `automation_runs` record is created, and in-app notification is received.
  4. Verify notification appears in `AppShell` header bell with unread badge = 1.
  5. Mark notification as read and verify badge clears.
  6. Inspect run history drawer and verify execution status is `success`.
