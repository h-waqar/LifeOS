## 4. Detailed Implementation Specification

### 4.1 Database Migration (`0022_automations_and_event_engine.sql`)
1. Create tables:
   - `notifications` (with indexes on `user_id, is_read, created_at DESC`).
   - `automations` (with indexes on `user_id, is_active` and `user_id, trigger_type`).
   - `automation_runs` (with indexes on `user_id, automation_id, created_at DESC`).
   - `scheduler_locks` (with unique constraint on `user_id, idempotency_key`).
2. Update Drizzle migration journal `_journal.json`.

### 4.2 Notification Service (`src/server/notifications/service.ts`)
- `createNotification(userId, input)`:
  - Validates `userId` ownership.
  - Inserts notification record.
  - Optionally logs audit event for high-priority alerts.
- `listNotifications(userId, { unreadOnly, limit, offset })`:
  - Returns paginated list of notifications + total unread count.
- `markAsRead(userId, notificationId)`:
  - Updates `isRead = true`, `readAt = NOW()`.
- `markAllAsRead(userId)`:
  - Batch updates all unread notifications for the user.
- `getUnreadCount(userId)`:
  - Fast index-assisted `COUNT(*)` where `user_id = ? AND is_read = false`.

### 4.3 Notification Center UI Component
- Bell icon button positioned in `AppShell` header (next to Theme toggle and Quick Capture).
- Real-time/polling badge showing number of unread notifications (e.g. `3`).
- Popover displays:
  - Header: "Notifications" with "Mark all as read" button.
  - List of notifications grouped by time or recency.
  - Icons indicating notification type (`info` = Blue Info, `warning` = Amber Alert, `success` = Green Check, `error` = Red Exclamation, `reminder` = Purple Clock).
  - Clicking item navigates to `linkUrl` and automatically marks notification as read.
  - Empty state when no notifications exist.

## 5. Security & Invariants

1. **Multi-Tenant Isolation:** Users can only query and mutate their own notifications (`eq(notifications.userId, session.user.id)`).
2. **Input Sanitization:** Notification titles and messages are strictly sanitized against XSS before storage and rendering.

## 6. Testing Strategy

All tests strictly placed in `scripts/tests/phase-07/plan-02/`.

### Unit Tests (`scripts/tests/phase-07/plan-02/notification-service.test.ts`):
- Creates notification with default and custom types.
- Correctly computes unread count.
- Marks single notification as read.
- Marks all notifications as read in one batch.
- Handles pagination and `unreadOnly` filter.
- Prevents cross-user modification.

### Integration Tests (`scripts/tests/phase-07/plan-02/notifications-api.integration.test.ts`):
- `GET /api/notifications` returns 200 with user's notifications.
- `PATCH /api/notifications/[id]/read` marks as read.
- `POST /api/notifications/read-all` updates all user notifications.
- Unauthenticated requests fail closed with 401.
- User A cannot mark User B's notification as read (fails closed with 404 or 403).
- Database foreign key cascade: deleting user deletes all associated notifications.
