### Investigation of SEC-03:
- **Requirement text:** `SEC-03: User can export the entire database in standardized JSON and Markdown formats at any time. *(Deferred to data portability milestone)*`
- **Traceability status:** `| SEC-03 | Phase 1 | Pending |`
- **Audit finding:** In Phase 8 (Plan 08-02), the system implemented `BackupExporter` (`src/server/integrations/backup/exporter.ts`) and API route `/api/integrations/backup/create`. This service exports all user database tables in JSON and all notes with Markdown frontmatter, calculates SHA-256 checksums, and saves them to local storage or S3. The technical capability is fully functional, but `REQUIREMENTS.md` was never updated from `Pending` to `Satisfied`.

### Deep Dive: Final Phase 9 Requirements
1. **INTEL-02 (Goal Risk Forecasting):**
   - **Engine:** `src/server/goals/forecasting/calculations.ts` (pure deterministic calculations) and `service.ts`.
   - **Verification Evidence:** Tested in `scripts/tests/phase-09/plan-02/forecasting-service.test.ts` (5 passing tests).
   - **Mathematical Bounds:** Progress clamped to [0, 100]; completed goals yield risk score 0 and completed status; overdue goals assign critical risk (90-100); elapsed days clamped with `Math.max(0.1, ...)` preventing division by zero.
   - **Explainability:** Generates contributing risk factors (`OVERDUE_DEADLINE`, `STALLED_PROGRESS`, `SEVERE_VELOCITY_DEFICIT`, `OVERDUE_TASKS`, `TIMELINE_SLIPPAGE`) with severity and metric observations, paired with actionable recommendations.
   - **UI Integration:** Rendered via `GoalRiskBadge` and interactive `GoalForecastDialog` on `/goals`.

2. **INTEL-03 (pgvector Semantic Knowledge Search):**
   - **Schema & Migration:** `src/server/db/schema/embeddings.ts` and `0026_pgvector_knowledge_embeddings.sql` with 768-dimensional vector column, foreign key cascade to `user.id`, composite uniqueness on `(user_id, entity_type, entity_id, chunk_index)`, and HNSW cosine index (`vector_cosine_ops`).
   - **Provider & Fallback:** `src/server/ai/embedding/provider.ts` supports Google Gemini (`text-embedding-004`) and OpenAI (`text-embedding-3-small`), falling back to a deterministic 768-dimensional L2-normalized vector embedding generator when API keys are unconfigured.
   - **Graceful Fallback:** If PostgreSQL or the `vector` extension is unavailable, `src/server/search/semantic-service.ts` catches the database error, logs a warning, and returns an empty result set gracefully without crashing.
   - **UI Integration:** Integrated into the global `CommandPalette` (`Cmd+K`) with a mode toggle ("Keyword" vs "Semantic").

## 6. Security & Authorization Audit

- **Authentication:** All protected routes verify identity using Better Auth session tokens via `requireAuthenticatedUser(req)`.
- **Authorization & Ownership Isolation:**
  - Client-supplied user IDs from request bodies or parameters are never trusted.
  - Queries enforce tenant isolation via `withUserScope(table.userId, user.id)` or explicit SQL WHERE clauses (`user_id = ${userId}`).
  - Cascading deletes ensure deleting a user wipes all their data across all domain tables.
- **Cache-Control:**
  - All API routes handling private user data return `Cache-Control: private, no-cache, no-store, max-age=0, must-revalidate`.
- **Secrets Encryption:**
  - OAuth tokens, API keys, S3 secrets, and webhook secrets are encrypted at rest with AES-256-GCM using `encryptSecret` (`src/lib/crypto.ts`).
- **AI Safety:**
  - Zero-trust model: AI tool calls with side effects are held in `ai_actions` as pending with a 5-minute TTL and require explicit human-in-the-loop confirmation before database execution.
