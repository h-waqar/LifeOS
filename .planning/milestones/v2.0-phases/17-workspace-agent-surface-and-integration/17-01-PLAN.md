# Plan 17-01: Workspace Agent Surface & Development Workflow Integration

## Executive Summary
Exposes the Phase 16 workspace execution harness, plan materializer, and pre-commit verification gate through the official LifeOS agent surfaces:
1. **Headless CLI (`src/cli/commands/workspace.ts` & `src/cli/index.ts`)**:
   - `lifeos workspace run <command> [--subpath <path>] [--args <arg1,arg2>] [--timeout <ms>] [--json]`
   - `lifeos workspace verify [--checks <check1,check2>] [--subpath <path>] [--timeout <ms>] [--json]`
   - `lifeos workspace materialize --project-id <id> --plan-file <file> [--version <v>] [--json]`
   - Strictly enforces session token authentication, rejects caller spoofing (`assertNoCallerSpoofing`), validates all inputs with Zod, and routes exclusively through canonical sandboxed functions (`runSandboxedWorkspaceCommand`, `runSandboxedPreCommitVerification`, `runSandboxedPlanMaterialization`).
2. **Model Context Protocol Tools (`src/server/mcp/tools/workspace-tools.ts` & `src/server/mcp/tools/registry.ts`)**:
   - Registers standard MCP tools:
     - `lifeos_workspace_run`: executes allowlisted workspace commands (`test`, `typecheck`, `build`, `lint`) within the sandboxed project root.
     - `lifeos_workspace_verify`: executes sequential pre-commit verification checks and returns read-only git status.
     - `lifeos_workspace_materialize_plan`: parses and materializes development plans into prioritized LifeOS tasks linked to an active project.
   - Preserves MCP adapter architecture: zero raw SQL, zero duplicate logic, strict delegation to canonical services with authenticated `user_id`. Preserves the read-only financial shield boundary assertion.
3. **Procedural Skills Registry (`skills/lifeos/workspace-development/SKILL.md`)**:
   - Standard frontmatter (`name`, `description`, `trigger_when`, `allowed_operations`, `required_context`, `verification_requirements`).
   - Guides external agents step-by-step through reading plans, converting them to tasks, running sandboxed tests/builds, and executing pre-commit verification before committing.
4. **Adversarial & End-to-End Integration Test Suite**:
   - `scripts/tests/phase-17/plan-01/workspace-cli.test.ts`: CLI argument parsing, `--json` stream separation, auth token validation, caller anti-spoofing, error formatting, and command dispatch.
   - `scripts/tests/phase-17/plan-01/workspace-mcp.test.ts`: MCP tool registry, schema validation, tool execution, session user binding, financial shield enforcement.
   - `scripts/tests/phase-17/plan-01/workspace-integration.test.ts`: Complete end-to-end integration: Plan reading -> task materialization -> command execution -> verification gate -> commit gating, with zero-trust audit attribution and multi-tenant isolation.

## Objectives & Delivered Components

### 1. Headless CLI Workspace Commands (`src/cli/commands/workspace.ts`)
- Subcommands:
  - `run`: Validates command allowlist (`test`, `typecheck`, `build`, `lint`), parses optional `--args`, `--subpath`, `--timeout`. Formats tabular output (Command, Passed, Exit Code, Duration) or deterministic JSON.
  - `verify`: Executes deterministic verification pipeline (`typecheck` -> `test` -> `build` -> `lint`), parses `--checks`, `--timeout`, `--subpath`. Formats checks summary table and git status or deterministic JSON.
  - `materialize`: Reads plan JSON/YAML from file path (or inline JSON), validates project ownership, parses `--project-id`, `--plan-file`, `--version`. Formats materialized tasks and dependency counts or deterministic JSON.
- Security:
  - `requiresAuth: true`.
  - Rejects caller identity flags (`--userId`, `--user_id`, `--user-id`) fail-closed.
  - Path inputs canonicalized and asserted within project workspace sandbox.

### 2. Model Context Protocol Tools (`src/server/mcp/tools/workspace-tools.ts`)
- Register tools with MCP Server:
  - `lifeos_workspace_run`: Input schema with `command: z.enum(["test", "typecheck", "build", "lint"])`, `subpath: z.string().optional()`, `args: z.array(z.string()).optional()`, `timeoutMs: z.number().int().positive().max(120000).optional()`.
  - `lifeos_workspace_verify`: Input schema with `checks: z.array(z.enum(["typecheck", "test", "build", "lint"])).optional()`, `timeoutMs: z.number().int().positive().max(120000).optional()`, `subpath: z.string().optional()`.
  - `lifeos_workspace_materialize_plan`: Input schema with `projectId: z.string().uuid()`, `plan: developmentPlanSchema`.
- Context & Attribution:
  - Derives `userId` exclusively from authenticated `McpContext.sessionUser.id`.
  - Dispatches through `runSandboxedWorkspaceCommand`, `runSandboxedPreCommitVerification`, and `runSandboxedPlanMaterialization`.

### 3. Procedural Skill (`skills/lifeos/workspace-development/SKILL.md`)
- Authoritative guide for agent harnesses with standardized YAML frontmatter.
- Documents trigger conditions, allowed workspace operations, plan specification structure, verification checklist, and commit gate requirements.

### 4. Comprehensive Test Suites
- Centralized in `scripts/tests/phase-17/plan-01/`.
- Verifies CLI, MCP, and end-to-end integration workflows.
- Contains adversarial vectors (traversal, unauthenticated, spoofed identity, malicious flags, cycles, foreign projects).
