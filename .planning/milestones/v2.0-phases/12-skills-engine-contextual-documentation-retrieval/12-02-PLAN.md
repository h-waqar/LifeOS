**Phase:** Phase 12: Skills Engine & Contextual Documentation Retrieval  
**Plan:** 12-02

**Requirements Covered:** SKILL-03, SKILL-04

## 1. Objective

Provide dynamic documentation retrieval and planning graph inspection mechanisms allowing agent harnesses and CLI users to search, retrieve, and follow domain rules, architecture records, and planning state without dumping the entire codebase into context:
1. **Document Sandbox & Path Traversal Shield:** Implement `src/server/docs/path-safety.ts`:
   - Enforce strict repository containment: document paths are normalized, canonicalized via `path.resolve` and `fs.realpath`, and asserted to reside strictly within allowed roots (`docs/`, `.planning/`, `skills/`).
   - Reject path traversal attempts (`../`, null bytes, encoded slashes, symlink escapes) with fail-closed errors.
   - Clean path sanitization ensuring returned paths are relative to project root without exposing underlying filesystem paths.
2. **Contextual Documentation Search Engine (SKILL-03):** Implement `src/server/docs/search-service.ts`:
   - Scans and indexes markdown documentation across `docs/`, `.planning/`, and `skills/`.
   - In-memory inverted index and term index cached by file modification timestamps (`mtime`), eliminating database migrations and providing <15ms retrieval latency.
   - Multi-tier hybrid scoring:
     - Exact title/H1 phrase match: 10.0 boost.
     - Heading match (H2/H3): 5.0 boost.
     - Keyword frequency and BM25 term relevance in body sections: 2.0–4.0 boost.
     - Scope filtering: `--source docs|planning|skills|all`.
   - Contextual snippet extraction: produces 120-character excerpts highlighting matched terms in context (leveraging snippet boundaries).
   - Strict payload bounding (default limit 5, max 20) and automatic secret scrubbing (`scrubSecrets`).
3. **Planning Graph Inspector (SKILL-04):** Implement `src/server/docs/planning-inspector.ts`:
   - `getCurrentPlanningState()`: Reads and structures `.planning/STATE.md` and `.planning/state.json`, returning milestone, current phase, phase status, velocity metrics, and next steps.
   - `getMilestoneDecisions()`: Parses the Key Decisions table from `.planning/PROJECT.md`, returning structured records (`decision`, `rationale`, `outcome`, `dateOrPhase`).
   - `getPhaseSummary(phase)`: Locates and parses `*-SUMMARY.md` from `.planning/phases/` or `.planning/milestones/v1.0-phases/` for completed phase learnings.
   - `getPendingRoadmap()`: Extracts upcoming roadmap phases, plan statuses, and active requirements from `ROADMAP.md` and `REQUIREMENTS.md`.
4. **Headless CLI Integration:** Implement `src/cli/commands/docs.ts` and register `docs` subcommand in `src/cli/index.ts`:
   - `lifeos docs search <query> [--source <source>] [--limit <n>] [--json]`: Search documentation and return ranked results with snippets.
   - `lifeos docs get <path> [--section <name>] [--json]`: Retrieve sanitized markdown document content or a specific heading section.
   - `lifeos docs planning [status|decisions|summary|roadmap] [--phase <phase>] [--json]`: Inspect current planning state, decisions, or phase summaries.
5. **MCP Protocol Integration:**
   - Tools (`src/server/mcp/tools/doc-tools.ts`):
     - `lifeos_search_docs`: Search repository documentation, ADRs, specifications, and phase plans with ranking.
     - `lifeos_get_doc`: Retrieve sanitized document text by path or ID with optional section filter.
     - `lifeos_get_planning_state`: Query current milestone, phase status, key architectural decisions, and pending roadmap tasks.
   - Resources (`src/server/mcp/resources/planning.ts`):
     - `lifeos://docs/planning/state`: Structured JSON of current planning state.
     - `lifeos://docs/planning/decisions`: Structured JSON of architectural decisions log.
   - Register tools and resources into existing registries (`src/server/mcp/tools/registry.ts`, `src/server/mcp/resources/registry.ts`).

## 4. Implementation Steps

1. **Path Safety & Sandbox Shield (`src/server/docs/path-safety.ts`):**
   - Define allowed documentation root directories: `["docs", ".planning", "skills"]`.
   - Implement `resolveSafeDocPath(requestedPath: string): { absolutePath: string; relativePath: string }`:
     - Reject null bytes, empty strings, and non-string inputs.
     - Normalize path and resolve against project root: `path.resolve(PROJECT_ROOT, requestedPath)`.
     - Check `fs.realpathSync` to resolve symlinks and assert target resides inside an allowed directory.
     - If path falls outside allowed roots, throw `UsageError("Security violation: Path traversal outside documentation root rejected.")`.
     - Assert file exists and is a regular file; if not, throw `NotFoundError("Document not found: " + relativePath)`.
     - Return verified absolute and clean relative paths.

2. **Doc Search Data Structures & Ranking (`src/server/docs/types.ts` & `src/server/docs/search-service.ts`):**
   - Define `DocSearchResult`:
     ```ts
     export interface DocSearchResult {
       id: string; // relative path
       title: string;
       source: "docs" | "planning" | "skills";
       snippet: string;
       score: number;
       path: string;
       headings: string[];
     }
     ```
   - Implement `DocSearchService`:
     - Discovers markdown files (`.md`) across `docs/`, `.planning/`, and `skills/`.
     - Parses markdown structure into sections: Title (H1 or first heading), Subheadings (H2, H3), and content paragraphs.
     - Indexes words with lowercase normalization and stop-word filtering.
     - Maintains in-memory document index with file `mtime` check for automatic invalidation.
     - Computes relevance score:
       - Exact phrase match in title: +10.0
       - Word match in title: +5.0 per term
       - Word match in subheadings: +3.0 per term
       - BM25 term frequency in body: +1.0 to +4.0
       - Boost active planning documents over archived milestone files.
     - Extracts 120-character contextual snippet highlighting matched terms using ellipsis boundaries.
     - Implements `getDocContent(relativePath, sectionName?)`: returns full content or filtered section.
     - Scrubs all output through `scrubSecrets`.

3. **Planning Graph Inspector (`src/server/docs/planning-inspector.ts`):**
   - Implement `PlanningInspector`:
     - `getCurrentPlanningState()`: Reads `.planning/STATE.md` frontmatter and body + `.planning/state.json`. Extracts `milestone`, `current_phase`, `current_phase_name`, `status`, `stopped_at`, `progress`, `recent_trend`.
     - `getMilestoneDecisions()`: Reads `.planning/PROJECT.md` `## Key Decisions` Markdown table. Parses columns: `Decision`, `Rationale`, `Outcome`, mapping to structured DTOs.
     - `getPhaseSummary(phaseIdentifier)`: Matches phase number or slug (e.g. `11` or `11-lifeos-model-context-protocol-mcp-server`), locates matching `*-SUMMARY.md` file(s), and returns structured summary content.
     - `getPendingRoadmap()`: Reads `.planning/ROADMAP.md` and `.planning/REQUIREMENTS.md`, extracting pending phases, remaining plans, and unsatisfied requirement IDs.

4. **CLI Subcommand Integration (`src/cli/commands/docs.ts` & `src/cli/index.ts`):**
   - Implement `handleDocs(parsed: ParsedArgs)`:
     - `lifeos docs search <query> [--source <source>] [--limit <n>]`: prints tabular or JSON search results with titles, scores, snippets, and paths.
     - `lifeos docs get <path> [--section <name>]`: prints document markdown or JSON.
     - `lifeos docs planning [status|decisions|summary|roadmap] [--phase <phase>]`: prints structured planning graph information.
   - Register `docs` in `COMMAND_REGISTRY` in `src/cli/index.ts`.

5. **MCP Server Integration (`src/server/mcp/tools/doc-tools.ts` & `src/server/mcp/resources/planning.ts`):**
   - Tools:
     - `lifeos_search_docs`: input `{ q: string, source?: string, limit?: number }`. Delegates to `DocSearchService.searchDocs`.
     - `lifeos_get_doc`: input `{ path: string, section?: string }`. Delegates to `DocSearchService.getDocContent`.
     - `lifeos_get_planning_state`: input `{ view?: "state" | "decisions" | "summary" | "roadmap", phase?: string }`. Delegates to `PlanningInspector`.
   - Resources:
     - `lifeos://docs/planning/state`: resource returning JSON of current planning state.
     - `lifeos://docs/planning/decisions`: resource returning JSON of key architectural decisions.
   - Wire tools into `src/server/mcp/tools/registry.ts` and resources into `src/server/mcp/resources/registry.ts`.

6. **Automated Verification (`scripts/tests/phase-12/plan-02/doc-search.test.ts`):**
   - Test `resolveSafeDocPath`:
     - Successfully resolves valid doc paths in `docs/`, `.planning/`, and `skills/`.
     - Rejects path traversal attempts (`../../../../etc/passwd`, `/etc/shadow`, `docs/../../package.json`).
     - Rejects nonexistent files with `NotFoundError`.
   - Test `DocSearchService`:
     - Indexes documents and returns ranked results for exact phrases, single terms, and multi-term queries.
     - Validates source filtering (`--source docs`, `--source planning`, `--source skills`).
     - Validates snippet extraction bounds and term highlighting.
     - Validates secret scrubbing in snippets and content.
   - Test `PlanningInspector`:
     - Correctly extracts current planning state and milestone from `STATE.md`.
     - Correctly extracts key decisions from `PROJECT.md`.
     - Correctly extracts phase summaries for completed phases.
     - Correctly extracts pending roadmap phases and requirements.
   - Test CLI `lifeos docs` commands and MCP doc tools/resources.
