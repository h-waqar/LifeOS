**Requirements Covered:** SKILL-01, SKILL-02

## 1. Objective

Deliver a discoverable, validated procedural skills registry that provides standardized, step-by-step guidance for agent harnesses and human operators executing domain workflows:
1. **Frontmatter Specification & Schema Validation (SKILL-02):** Define a strict Zod schema for procedural skill metadata in `src/server/skills/types.ts`:
   - `name`: unique kebab-case skill identifier (e.g. `task-breakdown`).
   - `description`: clear summary of the skill's purpose and scope.
   - `version`: semantic version string (e.g. `1.0.0`).
   - `trigger_when`: non-empty list of concrete conditions or user intents triggering the skill.
   - `allowed_operations`: allowlist of domain operations / MCP tool names permitted during execution.
   - `required_context`: list of MCP resource URIs or context descriptors required before execution.
   - `verification_requirements`: post-execution assertions to verify success before task completion.
   - `tags`: classification labels (e.g. `["planning", "tasks"]`).
2. **YAML Frontmatter Parser & Validation Engine (SKILL-02):** Implement `src/server/skills/parser.ts`:
   - Safely parses YAML frontmatter blocks bounded by `---` delimiters without executing arbitrary code.
   - Separates frontmatter metadata from Markdown instruction body.
   - Validates frontmatter against `SkillFrontmatterSchema`, raising structured `SkillValidationError` on schema mismatches with actionable error details.
3. **Curated Domain Procedural Skills (SKILL-01):** Author 4 production-grade procedural skills in `skills/lifeos/`:
   - `skills/lifeos/task-breakdown/SKILL.md`: Structured decomposition of goals or projects into 3–7 sequenced, atomic tasks with duration estimates, dependencies, and priority scoring.
   - `skills/lifeos/goal-alignment/SKILL.md`: Aligning tasks and active projects with quarterly goals, metric rollups, and focus areas.
   - `skills/lifeos/weekly-review/SKILL.md`: Comprehensive weekly reflection, habit streak evaluation, stalled project triage, and task rollover.
   - `skills/lifeos/bug-remediation/SKILL.md`: Systematic software defect diagnosis, reproduction script authoring in `scripts/tests/`, minimal fix implementation, and regression verification.
4. **Authoritative Skills Registry Service:** Implement `src/server/skills/registry.ts`:
   - Discovers all `skills/lifeos/*/SKILL.md` skill files dynamically from the project root.
   - In-memory caching with mtime invalidation for rapid execution in headless CLI and MCP server.
   - Query methods: `listSkills(filter?)`, `getSkill(name)`, `matchSkillsForIntent(query)`.
   - Deterministic alphabetical ordering and secret-scrubbed responses.
5. **Headless CLI Integration:** Implement `src/cli/commands/skills.ts` and register `skills` subcommand in `src/cli/index.ts`:
   - `lifeos skills list [--tag <tag>] [--json]`: List all registered skills with descriptions, triggers, and tags.
   - `lifeos skills get <name> [--json]`: Display full skill frontmatter and markdown instructions.
   - `lifeos skills match <intent> [--json]`: Rank and recommend matching skills based on intent text.
6. **MCP Protocol Integration:**
   - Tools (`src/server/mcp/tools/skill-tools.ts`):
     - `lifeos_list_skills`: Query available skills, descriptions, and trigger conditions.
     - `lifeos_get_skill`: Retrieve complete skill guidance, allowed operations, and verification criteria by name.
   - Resources (`src/server/mcp/resources/skills.ts`):
     - `lifeos://skills/list`: JSON catalog of all available skills.
     - `lifeos://skills/{name}`: Full markdown content and metadata for a specific skill.
   - Register tools and resources into existing registries (`src/server/mcp/tools/registry.ts`, `src/server/mcp/resources/registry.ts`).

## 4. Implementation Steps

1. **Skill Type Definitions & Schema (`src/server/skills/types.ts`):**
   - Define `SkillFrontmatterSchema`:
     ```ts
     import { z } from "zod";

     export const SkillFrontmatterSchema = z.object({
       name: z.string().regex(/^[a-z0-9-]+$/, "Skill name must be lowercase alphanumeric with hyphens"),
       description: z.string().min(10).max(300),
       version: z.string().regex(/^\d+\.\d+\.\d+$/, "Version must follow semver format (e.g. 1.0.0)"),
       trigger_when: z.array(z.string().min(3)).min(1, "At least one trigger condition is required"),
       allowed_operations: z.array(z.string().min(1)).min(1, "At least one allowed operation is required"),
       required_context: z.array(z.string().min(1)).default([]),
       verification_requirements: z.array(z.string().min(3)).min(1, "At least one verification requirement is required"),
       tags: z.array(z.string()).default([]),
     });

     export type SkillFrontmatter = z.infer<typeof SkillFrontmatterSchema>;

     export interface SkillDetail extends SkillFrontmatter {
       path: string;
       body: string;
       rawContent: string;
     }

     export type SkillSummary = Omit<SkillFrontmatter, "allowed_operations" | "required_context" | "verification_requirements"> & {
       path: string;
     };
     ```

2. **YAML Frontmatter Parser (`src/server/skills/parser.ts`):**
   - Implement `parseSkillMarkdown(rawContent: string, filePath?: string): SkillDetail`:
     - Locate leading YAML frontmatter delimited by `^---\r?\n([\s\S]*?)\r?\n---\r?\n?`.
     - Parse YAML key-value pairs and string arrays (supporting double-quoted strings, unquoted scalar strings, and standard list items `- "..."` or `- item`).
     - Validate parsed object using `SkillFrontmatterSchema.safeParse()`.
     - On failure, throw `SkillValidationError` detailing missing or malformed fields and the file path.
     - Return `{ ...frontmatter, body, rawContent, path: filePath ?? "" }`.

3. **Curated Skills Authoring (`skills/lifeos/*/SKILL.md`):**
   - Author `skills/lifeos/task-breakdown/SKILL.md` with frontmatter and actionable instructions covering: input goal/project inspection, scope splitting into 15–120 minute tasks, dependency DAG construction, priority scoring, and output verification.
   - Author `skills/lifeos/goal-alignment/SKILL.md` with frontmatter and instructions covering: quarterly objective hierarchy, metric tracking, task-to-goal linking, and alignment audits.
   - Author `skills/lifeos/weekly-review/SKILL.md` with frontmatter and instructions covering: 7-day retrospective, habit consistency calculation, overdue task rollover/cancellation, and week-ahead focus blocks.
   - Author `skills/lifeos/bug-remediation/SKILL.md` with frontmatter and instructions covering: defect reproduction in `scripts/tests/`, root-cause localization, minimal diff implementation, verification across regression suite, and commit hygiene.

4. **Skills Registry Service (`src/server/skills/registry.ts`):**
   - Implement `SkillsRegistry` singleton class:
     - Discovers `skills/lifeos/*/SKILL.md` using `fs.readdir` / `fs.stat`.
     - In-memory map `Map<string, { mtime: number; skill: SkillDetail }>`.
     - `listSkills(filter?: { tag?: string; query?: string })`: returns deterministic, sorted `SkillSummary[]`.
     - `getSkill(name: string)`: returns `SkillDetail` or throws `NotFoundError`.
     - `matchSkillsForIntent(query: string)`: tokenizes query, computes relevance score against `name`, `description`, `tags`, and `trigger_when`, returning sorted matches.

5. **CLI Subcommand Integration (`src/cli/commands/skills.ts` & `src/cli/index.ts`):**
   - Implement `handleSkills(parsed: ParsedArgs)`:
     - `lifeos skills list`: tabular list of skills (Name, Version, Description, Tags) or JSON with `--json`.
     - `lifeos skills get <name>`: prints frontmatter summary + markdown instructions or JSON.
     - `lifeos skills match <query>`: prints matching skills ranked by relevance.
   - Register `skills` in `COMMAND_REGISTRY` with `requiresAuth: false` (skills are static repository procedural knowledge, accessible offline).

6. **MCP Server Integration (`src/server/mcp/tools/skill-tools.ts` & `src/server/mcp/resources/skills.ts`):**
   - `lifeos_list_skills`: tool accepting optional `tag` and `query` parameters, returning registered skill summaries.
   - `lifeos_get_skill`: tool accepting required `name` parameter, returning complete skill instructions, frontmatter, and verification rules.
   - `lifeos://skills/list`: resource returning JSON catalog of all available skills.
   - `lifeos://skills/{name}`: resource returning skill markdown and metadata.
   - Wire both into `src/server/mcp/tools/registry.ts` and `src/server/mcp/resources/registry.ts`.

7. **Automated Verification (`scripts/tests/phase-12/plan-01/skills-registry.test.ts`):**
   - Test YAML frontmatter parsing against valid and invalid markdown strings.
   - Test schema validation failure on missing required fields (`name`, `description`, `trigger_when`, etc.).
   - Test all 4 curated skills parse without error and satisfy the schema.
   - Test `SkillsRegistry.listSkills`, `getSkill`, and `matchSkillsForIntent`.
   - Test CLI `lifeos skills list`, `lifeos skills get`, and `lifeos skills match` in both tabular and JSON modes.
   - Test MCP tools `lifeos_list_skills` and `lifeos_get_skill`.
   - Test MCP resources `lifeos://skills/list` and `lifeos://skills/{name}`.
