**Requirements Covered:** MCP-01, MCP-05

## 1. Objective

Establish the official Model Context Protocol server over stdio transport using `@modelcontextprotocol/sdk`:
1. **MCP SDK Integration:** Add `@modelcontextprotocol/sdk` to `package.json` dependencies and create the core server architecture under `src/server/mcp/`.
2. **Server Architecture & Capability Negotiation (MCP-01):** Implement `createLifeOSMcpServer(context: McpContext)` in `src/server/mcp/server.ts` utilizing `McpServer` from `@modelcontextprotocol/sdk/server/mcp.js`. Advertise capabilities:
   - `resources`: readable graph and context resources.
   - `tools`: structured domain tools.
   - `prompts`: planning and breakdown prompt templates.
   - `logging`: stderr-based diagnostic log level forwarding.
3. **Stdio Transport & Stream Discipline (MCP-01):** Implement `src/server/mcp/transport.ts` wrapping `StdioServerTransport` from `@modelcontextprotocol/sdk/server/stdio.js`:
   - Enforce absolute stream discipline: `process.stdout` is exclusively dedicated to framed JSON-RPC 2.0 protocol messages.
   - All server diagnostics, startup announcements, lifecycle logs, and debug traces are directed strictly to `process.stderr`.
   - Prevent any third-party or console logging from contaminating stdout.
4. **Authentication Boundary & Token Resolution (MCP-05):** Implement `src/server/mcp/auth.ts`:
   - Resolve token from `--token` CLI flag, `LIFEOS_TOKEN` environment variable, or stored credentials file (`~/.config/lifeos/credentials.json`).
   - Support encrypted tokens: if token begins with `v1:`, automatically decrypt using AES-256-GCM via `decryptSecret(token)`.
   - Query PostgreSQL Better Auth `session` and `user` tables to verify active, unexpired session (`expiresAt > NOW()`).
   - Enforce caller identity invariant: derive `userId` strictly from verified session. Prohibit and reject any attempt to pass `userId` or spoof caller identity.
   - Connection/Disconnection logging: log connection establishment and termination events to stderr.
5. **Process Lifecycle & Database Teardown:** Implement graceful shutdown hooks in `src/server/mcp/transport.ts` ensuring `await closeDatabase()` is executed on `SIGINT`, `SIGTERM`, transport close, and process exit.
6. **CLI Integration Subcommand:** Implement `src/cli/commands/mcp.ts` and register `lifeos mcp` in `src/cli/index.ts`, allowing agents to launch the server directly via `lifeos mcp` or `node bin/lifeos.js mcp`.

## 4. Implementation Steps

1. **Add Dependency & Core Types (`package.json`, `src/server/mcp/types.ts`):**
   - Install `@modelcontextprotocol/sdk`.
   - Define `McpContext`:
     ```ts
     export interface McpContext {
       user: { id: string; name: string; email: string };
       session: { id: string; userId: string; expiresAt: Date; token: string };
       token: string;
     }
     ```
   - Define `McpServerOptions` and capability definitions.

2. **Authentication & Identity Resolution (`src/server/mcp/auth.ts`):**
   - Implement `resolveMcpAuth(tokenOverride?: string)`:
     - Check `tokenOverride` -> `process.env.LIFEOS_TOKEN` -> `loadCredentials()?.token`.
     - If token starts with `v1:`, call `decryptSecret(token)`.
     - Query Better Auth `session` and `user` tables in PostgreSQL:
       `SELECT s.*, u.* FROM session s JOIN "user" u ON s.user_id = u.id WHERE s.token = :token AND s.expires_at > NOW() LIMIT 1`.
     - If missing or invalid, throw `AuthError("Authentication required: missing or invalid LifeOS session token.")`.
     - Return validated `McpContext`.
   - Implement `assertNoCallerSpoofing(record)` to reject `userId`, `user_id`, or `user-id`.

3. **Server Factory & Capability Configuration (`src/server/mcp/server.ts`):**
   - Instantiate `McpServer({ name: "lifeos", version: "0.1.0" })`.
   - Register server metadata and capability handlers.
   - Attach context to server instance.

4. **Stdio Transport & Lifecycle Runner (`src/server/mcp/transport.ts`):**
   - Implement `startStdioServer(tokenOverride?: string)`:
     - Resolve auth context via `resolveMcpAuth(tokenOverride)`.
     - Log connection event to `process.stderr`: `[lifeos-mcp] Authenticated session established for <user.email> (<user.id>)`.
     - Initialize `StdioServerTransport`.
     - Connect server to transport: `await mcpServer.connect(transport)`.
     - Register shutdown handlers on `SIGINT`, `SIGTERM`, and transport `onclose`:
       - Log disconnection event to `process.stderr`.
       - Execute `await closeDatabase()`.
       - Exit cleanly with code 0 (or signal code).

5. **CLI Subcommand Integration (`src/cli/commands/mcp.ts` & `src/cli/index.ts`):**
   - Implement `handleMcp(parsed: ParsedArgs)`:
     - Extract optional `--token` flag.
     - Call `startStdioServer(token)`.
   - Register `mcp` in `src/cli/index.ts`:
     `registerCommand("mcp", { run: handleMcp, requiresAuth: false, help: "lifeos mcp [--token <token>]" })`.

6. **Automated Verification (`scripts/tests/phase-11/plan-01/mcp-handshake.test.ts`):**
   - Test server factory initializes with correct name (`lifeos`) and version (`0.1.0`).
   - Test authentication resolution from token override, environment variable, and stored credentials.
   - Test encrypted token (`v1:...`) decryption and resolution.
   - Test rejection on missing, expired, or invalid session token.
   - Test database teardown trigger on transport close.
   - Test stdout/stderr separation: verify no diagnostic logs write to stdout.

## 6. Acceptance Criteria

1. `@modelcontextprotocol/sdk` is installed and clean TypeScript types compile without errors.
2. `createLifeOSMcpServer` successfully instantiates with advertised capabilities (resources, tools, prompts).
3. Authentication resolves valid session tokens from flags, env, or credentials file, including AES-256-GCM encrypted tokens.
4. Unauthenticated attempts fail closed with clear diagnostic errors on stderr and non-zero exit codes.
5. All diagnostics, connection logs, and errors write strictly to stderr; stdout contains zero log noise.
6. Process lifecycle terminates gracefully and drains database connection pool on `SIGINT`/`SIGTERM` or transport close.
