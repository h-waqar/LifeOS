## 1. Objective

Register structured agent tools with strict Zod argument validation schemas, delegating directly to canonical application services in `src/server/*` with authenticated `userId` ownership enforcement:
1. **Canonical Delegation Architecture (MCP-04):**
   - MCP tools are thin protocol adapters.
   - Zero raw SQL queries in tool handlers.
   - Zero duplicate business logic.
   - All tool executions strictly invoke canonical domain services (`createTask`, `updateTask`, `createProject`, `createGoal`, `createNote`, `search`, etc.).
2. **Caller Identity Isolation Invariant (MCP-04):**
   - The authenticated user's `userId` is obtained strictly from the validated `McpContext`.
   - Tool argument schemas explicitly prohibit caller-supplied `userId`, `user_id`, or `user-id`.
   - Any tool call attempting to inject or specify caller identity fails closed with an error.
3. **Structured Tool Registry (MCP-03):**
   Implement and register the following agent-oriented tools:
   - **Tasks:**
     - `lifeos_create_task`: Create a task with title, optional description, status, priority, energyLevel, scheduledDate, dueDate, estimatedDuration, projectId, milestoneId, tags. Validated with `createTaskSchema`, delegates to `createTask(userId, data)`.
     - `lifeos_update_task`: Update a task by ID. Validated with `id` + `updateTaskSchema`, delegates to `updateTask(userId, id, data)`.
     - `lifeos_delete_task`: Delete a task by ID. Delegates to `deleteTask(userId, id)`.
   - **Projects:**
     - `lifeos_create_project`: Create a project with name, description, area, status, priority, dates, goalId. Validated with `createProjectSchema`, delegates to `createProject(userId, data)`.
     - `lifeos_update_project`: Update a project by ID. Validated with `id` + `updateProjectSchema`, delegates to `updateProject(userId, id, data)`.
   - **Goals:**
     - `lifeos_create_goal`: Create a goal with title, description, horizon, area, metricType, targetValue, targetDate. Validated with `createGoalSchema`, delegates to `createGoal(userId, data)`.
     - `lifeos_update_goal`: Update a goal by ID. Validated with `id` + `updateGoalSchema`, delegates to `updateGoal(userId, id, data)`.
   - **Notes:**
     - `lifeos_create_note`: Create a knowledge note with title, content, noteType, area, tags, links. Validated with `createNoteSchema`, delegates to `createNote(userId, data)`.
   - **Search:**
     - `lifeos_search`: Unified cross-domain hybrid search across notes, tasks, projects, goals, people, and learning items. Validated with `searchQuerySchema`, delegates to `search(userId, params)`.
   - **Habits:**
     - `lifeos_log_habit`: Log a habit completion entry for a date. Validated with `habitId`, `date`, `value`, `notes`, delegates to `logHabitEntry(userId, habitId, input)`.
4. **Safety & Financial Shield Boundary:**
   - Financial mutations (creating transactions, modifying accounts, adjusting balances) are strictly PROHIBITED from tool registration.
   - Any financial data access is restricted to the read-only `lifeos://context/finance/summary` resource (per SAFE-03 and Out of Scope invariants).
5. **Deterministic Tool Responses & Error Mapping:**
   - On success: Returns structured MCP tool content `{ content: [{ type: "text", text: "<deterministic JSON>" }] }`.
   - On error: Formats canonical errors (`ZodError`, `NotFoundError`, `InvariantViolationError`, `AuthError`, `AuthorizationError`) into clean MCP error responses with secret scrubbing.

## 4. Implementation Steps

1. **Tool Wrapper Helper (`src/server/mcp/tools/registry.ts`):**
   - Implement `wrapToolHandler(fn, context)`:
     - Check arguments with `assertNoCallerSpoofing(args)`.
     - Execute handler passing `context.user.id`.
     - Serialize result with `sortKeysDeterministically` and `scrubSecrets`.
     - Catch errors, resolve with `resolveCliError(err)`, and return structured MCP tool response with `isError: true` on failure.

2. **Task Tools (`src/server/mcp/tools/task-tools.ts`):**
   - Register `lifeos_create_task`:
     - Arguments: `z.object({...})` matching `createTaskSchema` fields (excluding `userId` and `id`).
     - Invokes: `createTask(userId, input)`.
   - Register `lifeos_update_task`:
     - Arguments: `id: z.string().min(1)` + `updateTaskSchema` fields.
     - Invokes: `updateTask(userId, id, input)`.
   - Register `lifeos_delete_task`:
     - Arguments: `id: z.string().min(1)`.
     - Invokes: `deleteTask(userId, id)`.

3. **Project & Goal Tools (`src/server/mcp/tools/project-tools.ts`, `goal-tools.ts`):**
   - Register `lifeos_create_project`:
     - Arguments: `createProjectSchema` fields.
     - Invokes: `createProject(userId, input)`.
   - Register `lifeos_update_project`:
     - Arguments: `id: z.string().min(1)` + `updateProjectSchema` fields.
     - Invokes: `updateProject(userId, id, input)`.
   - Register `lifeos_create_goal`:
     - Arguments: `createGoalSchema` fields.
     - Invokes: `createGoal(userId, input)`.
   - Register `lifeos_update_goal`:
     - Arguments: `id: z.string().min(1)` + `updateGoalSchema` fields.
     - Invokes: `updateGoal(userId, id, input)`.

4. **Note, Search & Habit Tools (`note-tools.ts`, `search-tools.ts`, `habit-tools.ts`):**
   - Register `lifeos_create_note`:
     - Arguments: `createNoteSchema` fields.
     - Invokes: `createNote(userId, input)`.
   - Register `lifeos_search`:
     - Arguments: `q: z.string().min(1).max(200)`, `type: z.enum([...]).optional()`, `limit: z.number().int().min(1).max(100).optional()`.
     - Invokes: `search(userId, { q, type, limit })`.
   - Register `lifeos_log_habit`:
     - Arguments: `habitId: z.string().min(1)`, `date: z.string().regex(/^\d{4}-\d{2}-\d{2}$/)`, `value: z.number().optional()`, `notes: z.string().optional()`.
     - Invokes: `logHabitEntry(userId, habitId, input)`.

5. **Tool Registry Assembly (`src/server/mcp/tools/registry.ts`):**
   - Combine all tool registration modules.
   - Assert that no financial transaction/account mutation tools are registered.
   - Register all 10 tools on the `McpServer` instance.

6. **Automated Verification (`scripts/tests/phase-11/plan-03/mcp-tools.test.ts`):**
   - Test tool listing returns all 10 tools with full parameter schemas.
   - Test `lifeos_create_task` creates task via `createTask` with validated properties.
   - Test `lifeos_update_task` updates task status and priority.
   - Test `lifeos_delete_task` deletes task.
   - Test `lifeos_create_project` and `lifeos_update_project`.
   - Test `lifeos_create_goal` and `lifeos_update_goal`.
   - Test `lifeos_create_note`.
   - Test `lifeos_search` returns structured search results across entities.
   - Test `lifeos_log_habit` records habit entry.
   - Test validation errors return `isError: true` with structured Zod issue details.
   - Test caller identity spoofing attempt (`userId` in arguments) is immediately rejected.
   - Verify zero financial mutation tools exist in registry.

## 6. Acceptance Criteria

1. MCP server exposes 10 structured domain tools covering tasks, projects, goals, notes, search, and habits.
2. Every tool validates input arguments against canonical domain Zod schemas before service delegation.
3. Every mutating and read action executes strictly through canonical domain services (`src/server/*`) with authenticated `userId` ownership checks.
4. Supplying `userId`, `user_id`, or `user-id` in tool arguments fails immediately with a security rejection.
5. No financial transaction or account mutation tools exist in the MCP tool registry.
6. Errors are mapped cleanly to MCP tool error payloads with all secrets scrubbed.
