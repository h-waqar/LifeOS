# Plan 15-01: Progressive Web App Manifest, Service Worker Shell Caching & Offline IndexedDB Sync Engine

## Executive Summary
Implements the foundational Progressive Web App (PWA) infrastructure for LifeOS: standard web application manifest, service worker shell caching with strict security boundaries (zero caching of `/api/*`, authentication, or financial responses), versioned IndexedDB offline queue for tasks and notes, multi-user isolation by `userId`, concurrency-safe background synchronization with Web Locks, capped 3-attempt retry policy, and automatic synchronization on network reconnection.

## Objectives
1. **Web App Manifest & Static Assets**:
   - Provide standard `public/manifest.json` and Next.js route `src/app/manifest.ts`.
   - Include application name, short name, start URL (`/`), standalone display, theme/background colors (`#09090b`), and root scope (`/`).
   - Deliver 192x192 and 512x512 icons in both SVG and PNG formats, with maskable icon support.
2. **Service Worker Shell Caching (`public/sw.js` & `src/lib/pwa/service-worker.ts`)**:
   - Cache static application shell, icons, and manifest.
   - Network-only behavior for all `/api/*` endpoints, authentication endpoints, and financial responses.
   - Offline navigation fallback for HTML requests.
   - Safe client-side registration without SSR errors.
3. **IndexedDB Offline Queue Engine (`src/lib/pwa/offline-store.ts`)**:
   - Versioned IndexedDB store (`lifeos_offline_db`) with `offline_queue` object store.
   - Full lifecycle management: `pending -> syncing -> synced` and `pending -> syncing -> failed`.
   - Multi-user isolation enforcing `userId` indexation on all records.
   - Capped 3-attempt retry policy and terminal failure for permanent 400/422 validation errors.
4. **Queue Synchronization Engine (`src/lib/pwa/sync-manager.ts`)**:
   - Enforce multi-user isolation: only sync records matching authenticated `userId`.
   - Concurrency protection: Web Locks API (`navigator.locks`) with in-flight guard to prevent duplicate API submission across multiple tabs.
   - Automatic sync on network reconnect (`online` event listener) and application initialization.
5. **Layout Integration (`src/components/pwa/pwa-register.tsx`, `src/app/layout.tsx`)**:
   - Client component registering service worker and initial sync listeners.
   - Root layout updated with manifest links and mobile web app meta tags.
