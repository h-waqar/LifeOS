# Plan 14-02: AI Action Zero-Trust Integration & Universal Financial Shield

## Executive Summary
Bridges the legacy Phase 8 AI action and HITL execution path onto the canonical Phase 13 zero-trust architecture (`executeAgentOperation`, `AgentSafetyContext`, `assertFinancialShield`, `agent_challenges`, and `agent_audit_log`).

## Objectives
1. **Universal Financial Shield on AI Actions**:
   - Strictly prohibit autonomous/model-originated financial ledger mutations.
   - When an AI tool calls or proposes a financial mutation (`finance_create_transaction`, transfers, balances), it MUST be blocked unconditionally by the Phase 13 financial shield.
   - Even if confirmed by a human through `/api/ai/actions/[id]/confirm`, AI-originated mutations retain `AgentSafetyContext` and are blocked by `assertFinancialShield` / `guardFinancialMutation`.
   - Remove/deprecate direct execution of financial mutations in AI tools.

2. **Full Canonical Zero-Trust Routing for AI Mutations**:
   - `confirmAndExecuteAction` and `interceptToolCall` must establish `AgentSafetyContext`.
   - All AI tool executions delegate through `executeAgentOperation`.
   - Operations receive canonical permission evaluation, capability classification, and mandatory HITL approval gates.
   - Every confirmed AI action writes to `agent_audit_log` with before/after state diff and agent attribution.
   - Ensure tenant isolation: confirming actions across tenants returns 403.
   - Replay protection: consumed/expired actions cannot be executed again.

## Verification
- Tests in `scripts/tests/phase-14/plan-02/ai-action-safety.test.ts`.
- Validates:
  - AI proposed transaction -> BLOCKED by financial shield.
  - Confirmed AI action -> BLOCKED by financial shield if financial.
  - AI task creation -> passes through `executeAgentOperation` with `agent_audit_log`.
  - Cross-tenant action confirmation -> 403 FORBIDDEN.
  - Replayed AI action -> 409 CONFLICT.
  - Expired AI action -> 410 GONE.
