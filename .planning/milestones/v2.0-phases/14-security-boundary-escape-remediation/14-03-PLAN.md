# Plan 14-03: Transactional Audit Coupling & Error Rollback Guarantees

## Executive Summary
Eliminates silent audit loss in `executeAgentOperation` and transactionally couples agent domain mutations with durable audit log persistence in PostgreSQL.

## Objectives
1. **Eliminate Swallowed Audit Errors**:
   - Remove `.catch(() => {})` suppression from `logAgentAudit` calls on executed agent mutations.
   - Any failure to persist the audit record must abort the operation and propagate the error.

2. **Transactional Coupling & Rollback Invariant**:
   - Invariant 1: Every successful agent mutation must have a durable corresponding `agent_audit_log` record.
   - Invariant 2: If the audit record cannot be persisted (e.g. database failure, constraint violation, serialization rejection), the mutation must NOT remain committed and MUST be rolled back.
   - Coordinate transactions between mutation `executor` and `logAgentAudit` using Drizzle transactions.

3. **Handle Serialization Hazards & Pathological Input**:
   - Sanitize invalid JSONB values (e.g. `\u0000` / null bytes) in `scrubSecrets` while preserving audit content.
   - If serialization or database constraints still fail, enforce guaranteed transaction rollback.

## Verification
- Tests in `scripts/tests/phase-14/plan-03/audit-transaction-coupling.test.ts`.
- Validates:
  - Normal case: mutation + audit = COMMIT.
  - Audit failure (mock error): mutation rolled back.
  - JSONB serialization error: mutation rolled back.
  - Constraint violation: mutation rolled back.
  - Zero un-audited state changes.
