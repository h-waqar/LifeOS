# Plan 14-04: Challenge TTL Sweeper Scheduler Registration & Deterministic CLI Hashing

## Executive Summary
Registers the challenge TTL expiration sweeper with the production `SchedulerEngine` and background worker loop, and eliminates CLI payload hash mismatches caused by `--challenge-id` argument normalization (CLI-10).

## Objectives
1. **Challenge TTL Sweeper Registration**:
   - Wrap `sweepExpiredChallenges` as a canonical `PeriodicSweeper` (`challenge_ttl`).
   - Register it with `SchedulerEngine` constructor.
   - Integrate with `SchedulerWorker` and Next.js server lifecycle via `src/instrumentation.ts`.
   - Ensure unconfirmed `PENDING` challenges past TTL transition to `EXPIRED`.
   - Ensure `APPROVED`, `CONSUMED`, and `REJECTED` challenges are never incorrectly modified.
   - Concurrency safety and idempotency via database locking.

2. **Deterministic CLI Argument Hashing (CLI-10 Fix)**:
   - Harmonize argument canonicalization in `src/server/agents/challenges/challenge-service.ts`.
   - Ensure `--challenge-id`, `--challenge`, and `--challengeId` flags are completely excluded from argument hash computation during both challenge creation AND consumption.
   - Exclude global CLI runner options (`token`, `json`, `config`, `help`, `version`) from payload hashing so presentation flags don't break approvals.
   - Normalize alias and casing keys deterministically.

## Verification
- Tests in `scripts/tests/phase-14/plan-04/scheduler-ttl-cli.test.ts`.
- Validates:
  - Sweeper registered in `SchedulerEngine.getSweepers()`.
  - Application boot / scheduler run executes sweeper and transitions expired challenges.
  - Active/approved challenges not modified.
  - CLI command created challenge -> approved -> executed with `--challenge-id` succeeds without hash mismatch.
  - Omitted optional flags or JSON flag do not cause hash mismatch.
