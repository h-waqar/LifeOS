# Plan 14-01: Inbound Webhook Identity Spoofing & GitHub Fail-Closed Remediation

## Executive Summary
Remediates critical inbound webhook identity spoofing and high-severity GitHub webhook fail-open vulnerabilities identified in the Phase 14 battle-test report.

## Objectives
1. **Eliminate Inbound Identity Spoofing**:
   - Remove `userId = token` fallback from `src/app/api/integrations/webhooks/incoming/route.ts`.
   - Never interpret `Authorization: Bearer <arbitrary-string>` or `x-lifeos-webhook-secret` as user ID.
   - Resolve bearer credentials cryptographically against active agent tokens (`resolveAgentByToken`) or registered integration webhook secrets (`integrationConnections`).
   - Reject unauthenticated, malformed, revoked, expired, or cross-tenant webhook credentials with 401/403.
   - Strictly prohibit publishing domain events or triggering automation rules when authentication fails.

2. **Enforce GitHub Webhooks Fail-Closed**:
   - In `src/server/integrations/webhooks/handler.ts`, mandate HMAC-SHA256 signature verification.
   - Reject immediately if signature header is missing, malformed, or if webhook secret is unconfigured.
   - Remove `integrationConnections.limit(1)` fallback entirely.
   - Fail closed if no registered integration unambiguously matches the cryptographic signature.
   - Use timing-safe signature comparison (`crypto.timingSafeEqual`).

## Verification
- Unit and adversarial tests in `scripts/tests/phase-14/plan-01/webhook-security.test.ts`.
- Validates:
  - Victim ID in Authorization header -> REJECTED (401).
  - Victim ID in webhook secret header -> REJECTED (401).
  - Arbitrary token -> REJECTED (401).
  - Valid agent token -> RESOLVED to agent owner.
  - Valid integration connection secret -> RESOLVED to integration owner.
  - Missing signature on GitHub webhook -> REJECTED (401).
  - Unconfigured webhook secret -> REJECTED (401).
  - Invalid HMAC signature -> REJECTED (401).
  - Forged commit/PR events -> BLOCKED.
  - Zero domain events published on failed authentication.
