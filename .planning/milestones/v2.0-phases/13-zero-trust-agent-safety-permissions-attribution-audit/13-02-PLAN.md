## 1. Objective

Implement the five-tier agent capability model and the active zero-trust financial shield that protects canonical domain services from unauthorized or unsafe agent mutations:
1. **Capability Types & Contracts (`src/server/agents/permissions/types.ts`):**
   - Five distinct capabilities: `READ`, `WRITE`, `EXECUTE`, `DESTRUCTIVE`, `SENSITIVE`.
   - `AgentIdentity`: agentTokenId, userId, name, provider, status, capabilities, permissions.
   - `OperationClassification`: operation, capability, domain, isFinancialMutation, isDestructive, isSensitive.
   - `PermissionDecision`: granted, reason, requiresChallenge, classification.
2. **Deterministic Operation Classifier & Evaluator (`src/server/agents/permissions/evaluator.ts`):**
   - Explicit classification of all system operations, MCP tools, and CLI actions.
   - Denial by default for unknown operations.
   - Strict privilege separation: `WRITE` does not imply `DESTRUCTIVE`, `EXECUTE` does not imply `SENSITIVE`.
   - Evaluation rules:
     - Verify tenant ownership (`agent.userId === targetUserId`).
     - Check revocation and expiration status.
     - Enforce required capability tier.
     - Reject client-provided capability or identity claims.
3. **Active Zero-Trust Financial Shield (`src/server/agents/finance-shield.ts`):**
   - Active runtime security boundary located below adapter registries.
   - Explicitly blocks all agent-originated mutations on financial ledgers, transactions, accounts, transfers, and balances (`FinancialShieldViolationError`).
   - Distinguishes agent callers from ordinary first-party user sessions.
   - Supports read-only financial queries (e.g. `finance.summary`) if explicitly granted `READ`.
   - AsyncLocalStorage context propagation (`withAgentSafetyContext`) ensuring nested domain calls inherit the financial shield and cannot be bypassed.
4. **Token Generation & Validation Service (`src/server/agents/token-service.ts`):**
   - Secure token generator (`lifeos_ag_...`) with SHA-256 hashing.
   - Database lookup and resolution of active agent identity.
5. **Verification Test Suite (`scripts/tests/phase-13/plan-02/permission-evaluator.test.ts`):**
   - Test capability tiers, denial by default, privilege escalation rejection, financial mutation blocking across multiple pathways, and read-only allowance.
