## 1. Objective

Implement a cryptographic Human-in-the-Loop (HITL) challenge system and time-to-live (TTL) expiration engine ensuring that no `DESTRUCTIVE` or `SENSITIVE` operation can execute without explicit, single-use, tamper-evident human approval:
1. **Challenge Lifecycle Contract (`src/server/agents/challenges/types.ts`):**
   - States: `PENDING`, `APPROVED`, `REJECTED`, `EXPIRED`, `CONSUMED`.
   - Challenge payload: `id`, `userId`, `agentTokenId`, `operation`, `capability`, `resource`, `resourceId`, `arguments`, `argumentsHash`, `status`, `expiresAt`, timestamps.
2. **Challenge Service (`src/server/agents/challenges/challenge-service.ts`):**
   - `createChallenge`:
     - Cryptographically unpredictable UUID.
     - SHA-256 hash of canonicalized arguments (`argumentsHash`).
     - Default TTL: 10 minutes (`10 * 60 * 1000` ms).
     - Persists to `agent_challenges` with status `PENDING`.
     - Returns challenge metadata and instructions for human review.
   - `approveChallenge(userId, challengeId)`:
     - Enforces human ownership (`userId === challenge.userId`).
     - Verifies status is `PENDING` and not expired (`now < expiresAt`).
     - Atomically transitions status to `APPROVED`.
   - `rejectChallenge(userId, challengeId, reason)`:
     - Enforces human ownership.
     - Atomically transitions status to `REJECTED`.
   - `consumeChallenge(params)`:
     - Synchronous expiration check: if `now >= expiresAt`, updates status to `EXPIRED` and throws `ChallengeExpiredError`.
     - Arguments tamper detection: re-hashes input arguments and asserts `sha256(currentArgs) === challenge.argumentsHash`. If modified, invalidates and throws `ChallengeTamperedError`.
     - Identity binding: asserts matching `userId`, `agentTokenId`, and `operation`. Cross-user or cross-agent usage rejected with `ChallengeForbiddenError`.
     - Status verification: requires `APPROVED`.
     - Atomic transition: uses pessimistic conditional update (`UPDATE ... WHERE id = ? AND status = 'APPROVED'`) to transition to `CONSUMED`. Guarantees exactly-once execution and prevents replay attacks.
3. **TTL Sweeper Engine (`src/server/agents/challenges/ttl-sweeper.ts`):**
   - Background and on-demand sweeper scanning for `PENDING` challenges past `expiresAt`.
   - Atomically transitions stale challenges to `EXPIRED`.
   - Ensures synchronous checks in `consumeChallenge` do not rely solely on the background sweeper.
4. **Verification Test Suite (`scripts/tests/phase-13/plan-03/challenge-lifecycle.test.ts`):**
   - Intercepted destructive operation creates challenge without immediate mutation.
   - Approval allows exactly-once execution.
   - Tampered arguments invalidate challenge.
   - Replay fails closed.
   - Rejection blocks execution.
   - Expiration blocks execution (both synchronous and via sweeper).
   - Concurrency race conditions safely handled.
