## 1. Objective

Integrate the centralized agent safety boundary into external adapter layers (MCP server, CLI commands), implement deep forensic audit logging with secret redaction, and build an exhaustive 20-vector adversarial integration test suite:
1. **Attribution Audit Logger (`src/server/agents/audit/attribution-logger.ts`):**
   - Semantics: `REQUESTED`, `DENIED`, `CHALLENGE_CREATED`, `APPROVED`, `REJECTED`, `EXPIRED`, `EXECUTED`, `FAILED`.
   - Records: auditId, userId, agentTokenId, agentName, provider, sessionId, toolName, capability, operation, redacted arguments, argument hash, challengeId, duration, before/after states, error details.
   - Deep secret scrubbing: redacts tokens, API keys, passwords, bearer tokens, and secrets from all logged representations.
2. **Central Safety Interceptor Boundary (`src/server/agents/safety-boundary.ts`):**
   - Single authoritative entry point for all agent-driven operations:
     `executeAgentOperation<T>(context, request): Promise<AgentOperationResult<T>>`
   - Orchestrates:
     1. Agent Identity Resolution & Status Check
     2. Operation Classification (READ, WRITE, EXECUTE, DESTRUCTIVE, SENSITIVE)
     3. Permission Evaluation (fail-closed, no implicit elevation)
     4. Financial Shield Assertion (block mutations)
     5. HITL Gate: if DESTRUCTIVE/SENSITIVE without approved challenge, generates challenge and interrupts execution safely
     6. Forensic Audit Logging (recording requested, challenge, execution, diff, or denial)
     7. Canonical Domain Delegation
3. **MCP Adapter Integration (`src/server/mcp/tools/*`):**
   - Audit and route every MCP tool through the agent safety boundary:
     - Task tools (`lifeos_create_task`, `lifeos_update_task`, `lifeos_delete_task`)
     - Project tools (`lifeos_create_project`, `lifeos_update_project`)
     - Goal tools (`lifeos_create_goal`, `lifeos_update_goal`)
     - Note tools (`lifeos_create_note`, `lifeos_update_note`)
     - Habit tools (`lifeos_log_habit`)
     - Search & Doc tools (`lifeos_search`, `lifeos_docs_*`, `lifeos_*_skill`)
   - `lifeos_delete_task` and all destructive tools require approved challenge ID:
     - When invoked without challenge: returns challenge metadata with status `CHALLENGE_REQUIRED`.
     - When invoked with approved challenge ID: consumes challenge and completes deletion.
4. **CLI Agent Commands & Dispatcher Integration (`src/cli/commands/agents.ts`):**
   - Add CLI subcommands for managing agent tokens (`lifeos agent token create/list/revoke`), inspecting/approving/rejecting challenges (`lifeos agent challenge list/approve/reject`), and viewing audit logs (`lifeos agent audit`).
   - Register in `src/cli/index.ts`.
   - Route CLI commands executed under agent token context through the safety boundary.
5. **Exhaustive Adversarial Security Test Suite (`scripts/tests/phase-13/plan-04/agent-security.integration.test.ts`):**
   - Implement tests covering all 20 adversarial attack vectors specified in the prompt:
     1. Calling destructive MCP tools without a challenge.
     2. Calling destructive tools with a fake challenge ID.
     3. Reusing an approved challenge (replay attack).
     4. Using a challenge belonging to another agent.
     5. Using a challenge belonging to another user (cross-tenant).
     6. Changing arguments after approval (tampering attack).
     7. Calling after expiration.
     8. Racing approval and expiration.
     9. Racing two executions against one approved challenge (concurrency double-spend).
     10. Supplying a forged user ID.
     11. Supplying forged agent identity.
     12. Supplying elevated capability claims.
     13. Using a revoked token.
     14. Using an expired token.
     15. Calling financial mutation through an alternate adapter.
     16. Calling canonical services through exposed agent paths bypassing MCP.
     17. Attempting to bypass audit logging.
     18. Supplying secrets in arguments and verifying they are not persisted in plaintext.
     19. Attempting cross-tenant resource access.
     20. Calling unknown/unclassified operations.
